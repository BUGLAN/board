# Board 产品需求文档

| 项 | 内容 |
|---|---|
| 版本 | v0.11 |
| 日期 | 2026-11-10 |

## 1. 产品定义

Board 是看板式白板。人在界面上操作，agent 通过命令行（CLI）操作，两边读写的是同一块白板。

服务端部署在线上（例如 `https://board.example.com`）。人用 GitHub 账号登录，agent 用访问令牌连接。

白板按项目组织：一个项目下有多块白板。

Board 只管两件事：卡片在哪个状态、谁在做。agent 怎么干活不归 Board 管。每台干活的机器上可以常驻一个 `board host`：人把卡片派给某台机器，或者机器到了设定的时间自己领卡，`board host` 在本机启动已经装好的 agent（§9.1）。

## 2. 范围

**包含**

- 项目与白板的新建、编辑、删除
- 卡片的新建、编辑、移动、排序、评论、删除
- 卡片附件：图片和常见文件
- 「未整理」条目：放在工作流之前、还没整理成卡片的内容
- 每块白板的工作流（状态和连线）可以自定义
- 标签
- agent 名字的查重与在线状态；agent 领取卡片、发心跳，以及心跳中断后自动释放
- 复制为提示词，以及给 agent 用的 skill（`board-skills`）
- 界面：网页端与桌面端使用同一套界面；手机浏览器可用
- CLI
- 登录：网页端和桌面端用 GitHub 账号登录，只允许一个指定的账号
- agent 访问令牌：在界面上新建、吊销
- 任务下发（§9.1）：机器（`board host`）、手动派发、定时领取

**不包含**

- agent 本身。任何能执行命令行的 agent 都可以接入；`board host` 只启动本机已经装好的 agent。
- 界面里的命令行终端。agent 在自己的环境里运行 CLI。
- 对 GitHub issue、社区的监听
- 与 GitHub 等外部系统的同步（GitHub 只用于登录）
- 多个账号、团队、成员角色，以及注册

## 3. 身份与白板定位

| 操作方式 | 身份 | 操作哪块白板 |
|---|---|---|
| 界面 | 人：登录的 GitHub 账号（§3.1） | 界面上当前打开的白板。每个窗口可以打开不同的白板 |
| CLI | agent。名字由 `--as <名字>` 或环境变量 `BOARD_AS` 给出，两者都没有时命令被拒绝（`NO_IDENTITY`）；会话开始时先 `board check` 占用名字（§3.2）。连接服务端时用访问令牌认证（§3.1、§9） | 由 `--board <项目>/<白板>` 或环境变量 `BOARD` 给出，两者都没有时命令被拒绝（`NO_BOARD`） |

- 白板路径写成「项目标识/白板标识」，例如 `oss/release`。
- 项目下只有一块白板时，可以只写项目标识，例如 `site`。项目下有多块白板时只写项目标识，返回 `BOARD_NOT_FOUND`，原因里列出该项目的白板标识。

### 3.1 登录与访问令牌

**登录**

- 服务端只允许一个指定的 GitHub 账号登录（部署时配置）。所有项目和白板都属于这个账号。
- 没有登录时，网页端和桌面端显示登录页，页面上只有「用 GitHub 登录」。用其他 GitHub 账号登录时被拒绝，登录页提示该账号没有权限。
- 登录后 30 天内有效，使用期间自动续期。在「设置 → 账号」里可以退出登录。
- 所有 API，包括实时推送，都需要登录或访问令牌，否则被拒绝（`NOT_LOGGED_IN`）。
- 服务端以本机模式运行时，只接受本机访问，不需要登录。

**访问令牌**

- agent 连接服务端时用访问令牌认证。令牌属于登录的账号。
- 在「设置 → Agent 接入」新建令牌，填写用途（例如 `macbook`）。令牌原文只在新建时显示一次。
- 令牌列表显示用途、令牌开头几位、创建时间、最近使用时间。令牌可以吊销，吊销后使用它的命令被拒绝（`INVALID_TOKEN`）。
- `--as` / `BOARD_AS` 是 agent 的名字，与令牌无关：同一个令牌可以用不同的名字运行多个 agent。§8 的持有者仍按 agent 名字判断。
- 令牌只能用于 CLI 的命令（§9）和 agent 接口：check、心跳、在线列表（§3.2）；`board host` 的上报、开始与结束派发、上传日志、订阅实时推送，以及创建、取消派发（§9.1）。项目、白板、工作流、标签的管理，机器的设置与移除，以及删除卡片、强制释放，只能在登录后的界面上做。

### 3.2 agent 名字

**格式**：`<运行环境>/<模型>`，需要时加 `-<后缀>`。

- 两段都只能用小写字母、数字、`.`、`-`，并以字母或数字开头；只有一个 `/`，总长不超过 48 个字符。
- 例子：`claude/opus-5.5`、`dsh/deepseek-v4.1-flash`、`claude/opus-5.5-login`。
- 格式不对时 `board check` 报 `USAGE`，原因里给出格式说明。

**名字由 agent 自己生成**：运行环境用 claude、codex 这类名称；模型名转成小写，空格换成 `-`；本机已有同名会话时，加一个和本会话相关的后缀，例如任务名或分支名。

**board host 生成的名字**：`<agent 标识>/<机器名>-<序号>`，例如 `claude/mbp-3`，序号在这台机器上递增。`board host` 以这个名字 check、领取卡片、发心跳，再启动 agent（§9.1）。

**check**：`board check --as <名字>`。

- 名字正被在线 agent 使用时报 `NAME_TAKEN`，`detail` 里带上名字。
- 否则把名字标为在线，心跳时间记为当前时间，然后返回。
- 查重和占用是一个原子操作：同时 check 同一个名字，只有一个成功。

**在线**：名字最近一次心跳在 50 秒以内（每 10 秒一次，连续 5 次没收到算离线）。`board beat --final`（不带 ID）让名字立刻离线。离线后，同一个名字可以被任何会话重新 check，原会话也可以。

**名字表**：服务端记录名字、首次 check 时间、最近心跳时间、令牌 ID。表只增不删。

**严格模式**：带令牌的卡片命令（`POST /api/cmd`）和上传附件（`POST /api/files`）里的名字必须在线，否则报 `NAME_OFFLINE`。读接口不检查名字。

## 4. 项目与白板

**项目**

| 字段 | 说明 |
|---|---|
| 名称 | 必填 |
| 标识 | 必填。小写字母、数字和 `-`，以字母或数字开头，最长 32 个字符；全局唯一；创建后不能修改 |
| 描述 | 选填 |
| 颜色 | 从固定色板里选一种 |
| 标签 | 见 §6 |

**白板**

| 字段 | 说明 |
|---|---|
| 名称 | 必填 |
| 标识 | 必填。格式同项目标识；在所属项目内唯一；创建后不能修改 |
| 描述 | 选填 |

- 一块白板只属于一个项目。
- 新建项目时同时新建它的第一块白板（默认名称「主白板」，标识 `main`）。
- 每块白板相互独立：卡片 ID、工作流、领取、心跳都只在本白板内计算。
- 项目和白板只能在界面上新建、编辑、删除。删除前要二次确认；删除项目会删除它的全部白板。整个工作区至少保留一块白板。
- 白板被删除后，指向它的 CLI 命令返回 `BOARD_NOT_FOUND`。

## 5. 卡片

| 字段 | 说明 |
|---|---|
| ID | 每块白板内自增的整数，从 1 开始；界面上显示为 `#1`。「未整理」条目与卡片共用同一套 ID |
| 标题 | 必填 |
| 描述 | 选填，Markdown。验收标准、相关链接都写在这里 |
| 状态 | 「未整理」或工作流里的一个状态（§7） |
| 标签 | 0 个或多个，取自所属项目的标签 |
| 持有者 | 领取这张卡片的 agent 名字，只有锁定状态里的卡片有 |
| 耗时 | 每一次领取的耗时（第一次心跳到结束），以及累计耗时、做过几次、其中几次异常退出 |
| 完成时间 | 最近一次领取结束的时间（final、心跳中断、释放都算）；评论、编辑、移动不改它；没有结束过的领取时为空 |
| 动态 | 评论和系统记录，按时间排列；人可以在界面上原地修改或删除自己发的评论（修改后显示「已编辑」和修改时间），agent 的评论和系统记录不能修改、不能删除 |
| 附件 | 0 个或多个文件：图片（PNG、JPEG、GIF、WebP）和常见文件（PDF、TXT、Markdown、日志、JSON、CSV、ZIP），单个不超过 10 MB |

- 卡片在状态内有先后顺序，越靠前越优先。
- 附件：
  - 在描述和评论里插入：图片直接显示，点击放大；其他文件显示为下载链接。
  - 人在界面上的描述框、新建弹窗的描述框和评论框里粘贴截图、拖入文件或点「附件」按钮上传；agent 用 `board attach` 上传（§9）。
  - 读取附件需要登录或访问令牌。
  - 删除卡片时附件一起删除；备份包含附件。
- 卡片被新建、编辑、移动、调整顺序、领取、开始或结束心跳、释放，以及加或去标签时，系统自动在动态里追加一条记录，写明谁、在什么时间、做了什么。

## 6. 标签

| 字段 | 说明 |
|---|---|
| 名称 | 必填；在所属项目内唯一，不区分大小写 |
| 颜色 | 从固定色板里选一种 |
| 类型 | agent 可打（默认）：人和 agent 都能给卡片加、去；仅人可打：只有人能在界面上给卡片加、去 |
| 优先 | 开关，默认关。开着时，不带 ID 领取（和定时领取）时带这个标签的卡片先被领取（§8 规则 1）；卡片在状态里的位置不变 |

- 标签属于项目，项目下的所有白板共用。
- 人能给卡片加标签、去标签，任何状态的卡片都可以，包括别人持有的卡片（不受 §8 规则 5 限制）；agent 同样可以，但只能加、去「agent 可打」的标签。
- agent 加、去「仅人可打」的标签（`board label`，或 `board new --label` 新建时带上）被拒绝（`USAGE`），原因里写明这个标签只有人能打，不新建卡片。
- 卡片上的标签显示为块状胶囊；「仅人可打」的标签在名称前带一把小锁，「优先」的标签在名称前带一个闪电，悬停提示「优先：带这个标签的卡片先被领取」。
- 标签的新建、改名、改色、改类型、开关「优先」、删除在界面上做（「管理标签」）。删除标签时，它会从项目内所有卡片上移除。
- 升级前已有的标签都是「agent 可打」，都不是「优先」。
- CLI 引用项目里不存在的标签时，命令被拒绝（`USAGE`），原因里列出可用的标签。

## 7. 工作流

每块白板有自己的工作流：一组有先后顺序的状态，以及状态之间的连线。连线 A → B 表示 agent 可以把卡片从 A 移到 B（§8 规则 12）；人移动卡片不受连线限制。

新建白板时默认是 6 个状态：

| 状态 | 标识 | 规则 | 连线（可以去往） |
|---|---|---|---|
| 待办 | `todo` | 可领取 | 进行中 |
| 进行中 | `doing` | 锁定 | 待审核、需人工校验 |
| 待审核 | `review` | — | 已完成、返工 |
| 已完成 | `done` | 终点 | — |
| 返工 | `rework` | 可领取 | 进行中 |
| 需人工校验 | `check` | — | 待办 |

| 字段 | 说明 |
|---|---|
| 名称 | 必填；在白板内唯一，不区分大小写；最长 12 个字 |
| 标识 | 系统生成，不能修改。默认的 6 个状态见上表，新增的状态依次是 `s1`、`s2`… |
| 颜色 | 从固定色板里选一种 |
| 规则 | 三个开关，见下表 |
| 卡片形态 | 状态块里的卡片怎么显示：卡片、单行、磁贴三选一（§10.3），只影响界面显示。没有设置过时，终点状态用磁贴，其他状态用卡片 |
| 连线 | 从这个状态出发、可以去往的状态，0 个或多个 |

| 规则 | 含义 | 数量 |
|---|---|---|
| 可领取 | `board claim` 从这里领取，领取后卡片沿连线进入锁定状态（§8 规则 1） | 1 个或多个 |
| 锁定 | 只能由 agent 领取进入；卡片被持有期间，只有持有者能编辑和移动 | 0 个或多个 |
| 终点 | 进到这里算完成；只有人能把卡片移入或移出 | 0 个或多个 |

- 状态的顺序决定：工作流条上的排列；不带 ID 领取时先领哪个可领取状态；新建卡片放在哪里。
- **首个可领取状态**：按顺序排在最前面的可领取状态。新建卡片（未指定「未整理」时）、「整理到…」都放进这里。
- 工作流只能在界面上修改：新增、改名、改色、选卡片形态、调整顺序、切换规则、连线、删除。
- 至少要有一个可领取状态：最后一个可领取状态不能关闭「可领取」，也不能删除。
- 可领取状态没有连到任何锁定状态时，不能从这里领取；工作流条上这个状态显示提示。
- 删除状态时，里面的卡片移到首个可领取状态最下面，被持有的卡片同时释放；与它相关的连线一起删除。
- 关闭某个状态的「锁定」时，其中被持有的卡片释放。
- 「未整理」（标识 `inbox`）不属于工作流，没有连线：每块白板固定都有，不显示在白板的主内容区，agent 不能领取，也不能把已有卡片移入或移出；界面或 agent/CLI（`board new --inbox`）都可以新建「未整理」条目。
- CLI 里用标识或名称指定状态，名称不区分大小写。
- 升级前已有的白板：原来的领取起点变为可领取，按原来的顺序给相邻的状态依次连线（第 1 个 → 第 2 个 → …），其余在界面上调整。

## 8. 规则

以下规则都在同一块白板内生效。

1. **领取**：只有可领取状态里的卡片能被领取。领取后卡片沿连线进入锁定状态：这个可领取状态连向的锁定状态里，按顺序排在最前面的一个；没有连到锁定状态时不能从这里领取。不带 ID 领取时，在连到锁定状态的可领取状态里（按工作流顺序，状态内从上到下）挑：有带「优先」标签（§6）的卡片就领排在最前面的那张，没有就领最前面的那张；有排队中派发的卡片跳过。带 ID 领取、手动派发不看「优先」。持有者是领取它的 agent。
2. **互斥**：多个 agent 同时领取同一张卡片，只有一个成功。
3. **一个 agent 在一块白板上同时只持有一张卡片。**
4. **进入锁定状态只能靠领取**：人和 agent 都不能把卡片直接移进锁定状态。例外：持有者可以沿连线把自己持有的卡片从一个锁定状态移到另一个锁定状态，领取保持不变。
5. **持有者独占**：被持有的卡片只有持有者能编辑和移动，其他人和 agent 只能评论、加或去标签。人可以在界面上「强制释放」。
6. **心跳与耗时**：一个 agent 会话只有一路后台心跳。check 之后，`board heartbeat start` 启动的后台循环每 10 秒发一次 `board beat`（不带 ID）：更新名字的心跳时间（名字已离线时被拒绝，`NAME_OFFLINE`），并对这个名字持有、这一次还没 final 的每张卡片记一次心跳，效果等同于 `board beat <ID>`：更新卡片的心跳时间，计入心跳次数。领取后的第一次心跳是这一次的开始，动态里记「开始第 n 次」；final（`board beat <ID> --final`）是结束，两者之差是这一次的耗时，记在动态里；卡片显示累计耗时。final 之后这张卡片不再被后台心跳刷新，再发 `board beat <ID>` 被拒绝。同一张卡片被多次领取时，每一次分别计时、分别记录。评论、编辑不代替心跳。
7. **心跳中断释放**：从领取或最近一次心跳算起，连续 5 次（50 秒）没收到心跳，卡片回到领取它时所在的可领取状态最上面（那个状态已删除或不再可领取时，回到首个可领取状态最上面），持有者清空，动态里记「心跳中断」。进行中的这一次以最后一次心跳为结束，记为异常退出；还没开始心跳、或发了 final 后 50 秒内没有沿连线移走的，动态里写明原因。名字离线后，它持有的卡片收不到心跳，按这条规则在 50 秒内释放。本次耗时有四种结束方式：final 正常结束、持有者移出锁定状态、人强制释放、心跳中断。
8. **离开锁定状态即释放**：持有者把卡片移到不锁定的状态时，持有者清空，进行中的这一次在此时结束。人强制释放后，卡片回到的位置同规则 7，进行中的这一次在此时结束。
9. **终点只归人管**：只有人能把卡片移入或移出终点状态。
10. **删除只能在界面上做。**
11. **「未整理」的整理只归人管**：界面或 agent/CLI（`board new --inbox`）都可以新建「未整理」条目；只有人能把卡片移入或移出「未整理」，同样受规则 4、5 约束。
12. **agent 只能沿连线移动**：agent 把卡片从 A 移到 B 时，工作流里必须有连线 A → B，否则被拒绝，原因里列出 A 能去的状态。人移动卡片不受连线限制。在同一个状态内调整顺序不受影响。

**卡片在状态里的位置**

- 新建：首个可领取状态最下面；CLI 带 `--top` 时放在最上面。界面或 CLI（`--inbox`）新建时可以选择放进「未整理」，放在「未整理」最下面。
- 移动：目标状态最下面；CLI 带 `--top` 时放在最上面。界面上拖拽时放在松手的位置。
- 「整理到<首个可领取状态>」：首个可领取状态最下面。
- 心跳中断释放、强制释放：领取它时所在的可领取状态最上面（规则 7）。

## 9. CLI

所有命令都支持 `--json`，输出 JSON。成功时退出码为 0；被拒绝时退出码为 1，并给出错误码（见 §12）和原因。

**安装**：桌面端安装包自带 `board` 命令行。Windows 安装器把它写进用户 PATH，装完重开终端就能用；macOS 的安装包不带安装脚本，在「设置 → Agent 接入」里执行一条命令，把 `Board.app` 里自带的 `board` 所在目录写进 shell 的 PATH（写进 `~/.zshrc`，重复执行不会重复追加）。不装桌面端时从源码安装：`cargo install --path crates/board-cli`（需要 Rust）。agent 用 skill 自带的 `board`：发版附件 `board-skills.zip` 的 `bin/` 里有各平台的二进制，skill 里的 `scripts/board`（Windows：`scripts\board.cmd`）按平台选用，没有时用 PATH 里的 `board`。

**连接**

CLI 只通过服务端读写白板，规则在服务端执行。服务端地址和访问令牌写在配置文件 `~/.board/config.toml`（Windows 上是 `%USERPROFILE%\.board\config.toml`）里：

| 配置项 | 内容 |
|---|---|
| `url` | 服务端地址，例如 `https://board.example.com`；本机模式的服务端填它的本机地址，例如 `http://127.0.0.1:7420` |
| `token` | 访问令牌，在界面「设置 → Agent 接入」新建 |
| `[host]` | `board host` 的机器名 `name` 和白板与目录 `dirs`（§9.1） |
| `[agents.<标识>]` | `board host` 的 agent 命令模板 `cmd`（§9.1） |

- 配置文件所在目录权限 0700，文件权限 0600。以后固定的配置也写在这个文件里；agent 名字（`BOARD_AS`）和白板（`BOARD`）不写进这个文件。
- 环境变量 `BOARD_CONFIG` 指定另一个配置文件代替 `~/.board/config.toml`（`board host` 启动 agent 时用它传连接，§9.1）。
- 读取顺序：环境变量 `BOARD_URL` / `BOARD_TOKEN` 优先，配置文件其次。两处都没有时报 `NOT_LOGGED_IN`，提示运行 `board login`。
- 令牌无效或已吊销时被拒绝（`INVALID_TOKEN`）；连不上服务端时被拒绝（`UNREACHABLE`）。

**`board login [--url <地址>] [--token <令牌>]`**

- 不带 `--url` 时沿用文件里已有的 `url`，文件里也没有就报 `USAGE`。不带 `--token` 时从标准输入读一行。
- 写入前用 `GET /api/workspace` 校验令牌。校验失败时不写文件，按服务端返回的错误码报错（`INVALID_TOKEN`、`UNREACHABLE` 等）。
- 改写文件时保留其他配置项。
- 写入成功后，如果当前环境里设置了 `BOARD_URL` 或 `BOARD_TOKEN`，输出一行提醒：环境变量会覆盖配置文件，需要从 shell 配置文件里删掉对应的 `export`。
- 输出里不打印令牌原文。

**`board logout`**：从配置文件删掉 `token`，保留 `url`。

**`board doctor [--as <名字>] [--board <白板>]`**：环境自检，没通过的项给出原因和下一步，有失败项时退出码为 1。

- 服务端地址和令牌两项写明值来自哪里：环境变量还是 `~/.board/config.toml`。两处都有时状态为 warn，说明环境变量覆盖了文件；两处都没有时，下一步提示 `board login --url <服务端地址>`。
- 名字（`--as` 或 `BOARD_AS`）和白板（`--board` 或 `BOARD`）没提供时跳过，不判失败；提供了名字时，检查格式和是否在线。

除 `board help`、`board login`、`board logout`、`board doctor` 外，所有命令都需要连接服务端；除这几个和 `board host`、`board dispatch` 外，都需要身份（§3）；此外除 `board boards`、`board check`、不带 ID 的 `board beat`、`board host` 外，都需要白板（§3）。

| 命令 | 作用 |
|---|---|
| `board check --as <名字>` | 占用名字（§3.2）。会话开始时执行一次 |
| `board heartbeat start` | 启动后台心跳（§8 规则 6）：先同步发一次 `board beat`，失败直接报错；成功后后台每 10 秒发一次，立即返回。后台心跳跟随 agent 进程（从 board 往上找第一个不是 shell 的祖先进程），agent 进程不在了就停下，不发 final；心跳被拒绝时停下，连不上服务端时继续重试 |
| `board heartbeat stop` | 先停掉后台心跳、等它退出，再发 `board beat --final`，名字立刻离线；重复执行不报错 |
| `board heartbeat final <ID>` | 等同 `board beat <ID> --final`：结束这张卡片这一次的计时 |
| `board beat [--final]` | agent 级心跳（§8 规则 6），一般由 `board heartbeat` 的后台循环发送；`--final` 让名字立刻离线 |
| `board beat <ID> [--final]` | 一张卡片的心跳；`--final` 结束这一次计时（§8 规则 6） |
| `board boards` | 列出所有白板：路径、项目名、白板名、各状态卡片数 |
| `board flow` | 列出当前白板的工作流：顺序、标识、名称、规则、卡片数，以及每个状态可以去往的状态 |
| `board ls [--column <状态>] [--search <文字>] [--label <标签>]` | 列出卡片：ID、状态、标题、标签、持有者，按工作流顺序和状态内顺序排列。`--search` 在标题和描述里查找；`--label` 只列出带该标签的卡片 |
| `board show <ID>` | 显示卡片的全部字段和动态 |
| `board new "<标题>" [--body "<描述>" \| --body-file <文件>] [--top] [--inbox] [--label <标签>]…` | 在首个可领取状态新建卡片；`--inbox` 记到「未整理」最下面；`--label` 可以写多次，按名称匹配（不区分大小写），同一个只算一次；项目里没有这个标签、或它是「仅人可打」时拒绝（`USAGE`，原因里列出可用的标签 / 写明只有人能打），不新建卡片 |
| `board edit <ID> [--title "<标题>"] [--body "<描述>" \| --body-file <文件>]` | 修改标题或描述 |
| `board move <ID> <状态> [--top]` | 把卡片移到指定状态（标识或名称）；只能沿连线移动（§8 规则 12） |
| `board claim [<ID>]` | 领取。不带 ID 时按 §8 规则 1 选卡片。返回卡片的全部字段和动态 |
| `board next` | 只在 `board host` 启动的会话里用（环境里有 `BOARD_HOST`，名字是这次会话生成的），否则 `USAGE`：结算上一张、领下一张接着做（§9.1「会话接着做」），返回内容和 `board claim` 一样；不再接着做时 `SESSION_DONE` |
| `board comment <ID> "<内容>"`<br>`board comment <ID> --comment-file <文件>` | 追加评论 |
| `board label <ID> +<标签> -<标签> …` | 加标签（`+` 或不带前缀）、去标签（`-`），可以一次写多个；「仅人可打」的标签不能加、去（`USAGE`，§6） |
| `board labels` | 列出白板所属项目的标签、每个标签的类型（agent 可打 / 仅人可打）、是否优先，以及被多少张卡片使用；`--json` 里是 `human_only`、`priority` |
| `board attach <ID> <文件>… [--comment "<说明>" \| --comment-file <文件>]` | 上传附件，连同说明作为一条评论追加到卡片 |
| `board files <ID> [--out <目录>]` | 把卡片的附件下载到本地（默认系统临时目录），列出文件路径 |
| `board host [--name <机器名>] [--dir <项目>/<白板>=<路径>]…` | 在这台机器上常驻接任务（§9.1），前台运行，`Ctrl+C` 退出 |
| `board dispatch <ID> --host <机器名> [--agent <标识>]` | 把卡片派给一台机器上的 agent；不带 `--agent` 用这台机器的默认 agent（§9.1） |
| `board dispatch <ID> --cancel` | 取消还在排队的派发，或停止正在跑的派发（§9.1） |

`board ls --json`、`board show --json` 的卡片里，`labels` 是标签名，`priority_labels` 是其中的优先标签。

`--body-file`、`--comment-file` 从文件读描述、评论（`-` 读标准输入），和直接写的参数只能给一个；文件按 UTF-8 读，去掉 BOM，带 BOM 的 UTF-16 也认，换行统一成 `\n`，不是 UTF-8 时拒绝（`USAGE`）。Windows 上 skill 的入口 `board.cmd` 要经过 cmd.exe，参数里的换行会把命令截断在第一行，多行内容只能这样传。`board --version` 打印版本号。

### 9.1 任务下发（board host）

**机器**：运行 `board host` 的进程代表一台机器。有名字、在线状态、并发上限、启动环境、本机 agent、白板与目录。

- 机器名：小写字母、数字、`.`、`-`，以字母或数字开头，最长 24 个字符；不填时取本机主机名转成小写、非法字符换成 `-`。同名机器正在线时启动失败（`HOST_NAME_TAKEN`）。同一台机器上 `board host` 异常退出后重启，接回原来的名字。
- 白板与目录：`--dir` 把一块白板对应到本机的一个仓库目录，agent 在这个目录里启动。没有对应目录的白板，这台机器不接它的卡片。目录不存在时启动失败（`USAGE`，写明是哪个目录）。
- 启动环境：在哪种 shell 里启动 agent 的命令。启动时找出本机有哪些，上报标识、名称、程序路径（WSL 写发行版名）：

  | 标识 | 名称 | 系统 | 怎么发现 | 怎么启动 agent |
  |---|---|---|---|---|
  | `direct` | 直接启动 | 所有 | 总有 | 直接执行命令模板，不经过 shell |
  | `login` | 登录 shell | macOS、Linux | `$SHELL`，没有时 passwd 里的登录 shell，再没有 `/bin/sh` | `$SHELL -l -i -c 'exec "$0" "$@"' <命令> <参数>…` |
  | `cmd` | cmd | Windows | `%ComSpec%` | `cmd.exe /d /s /c "<命令> <参数>…"`，每个参数加双引号 |
  | `powershell` | Windows PowerShell | Windows | `%SystemRoot%\System32\WindowsPowerShell\v1.0\powershell.exe` | `powershell.exe -NoLogo -NonInteractive -ExecutionPolicy Bypass -Command "& '<命令>' '<参数>' …; exit $LASTEXITCODE"`，参数里的 `'` 写成 `''` |
  | `pwsh` | PowerShell 7 | Windows | `PATH` 里的 `pwsh.exe`，或 `%ProgramFiles%\PowerShell\7\pwsh.exe` | 同上，换成 `pwsh.exe` |
  | `git-bash` | Git Bash | Windows | `%ProgramFiles%\Git\bin\bash.exe`、`%ProgramFiles(x86)%\Git\bin\bash.exe`，再看 `PATH` 里 git 旁边的 | `bash.exe -l -c 'exec "$0" "$@"' <命令> <参数>…` |
  | `wsl:<发行版>` | WSL（<发行版>） | Windows | `wsl.exe -l -q` 列出的每个发行版各算一个 | `wsl.exe -d <发行版> --cd <目录> --exec setsid -w bash -l -i -c 'exec "$0" "$@"' <命令> <参数>…` |

  - 提示词作为独立参数传入，不拼进 shell 命令文本（cmd 除外：加双引号拼进命令行）。启动环境的退出码就是 agent 的退出码。
  - 登录 shell 和 WSL 用交互式（`-i`），这样写在 `~/.zshrc`、`~/.bashrc` 里的 `PATH` 也生效；agent 进程脱离终端（`setsid`）。shell 的启动脚本里设了 `BOARD_URL`、`BOARD_TOKEN` 也不影响：启动 agent 前用 `board host` 的值再设一遍。
  - WSL：目录用 `--cd` 传 Windows 目录，由 `wsl.exe` 换成 `/mnt/…`；环境变量经 `WSLENV` 传入，`BOARD_CONFIG` 换成 WSL 路径，不传 `BOARD_EXE`（WSL 里用 `board-skills` 自带的 Linux 版 `board`）。
- 本机 agent：启动时按配置文件里的 `[agents.*]` 加上内置模板，在每个 agent 支持、本机有的每个启动环境里检查一次：执行 `command -v <命令>`（cmd、PowerShell 用 `where.exe`；WSL 里 `/mnt/` 下的 Windows 程序不算）看找不找得到，找到了再执行 `<命令> --version` 取第一行作为版本号；上报每个 agent 在每个环境里「找到 + 版本号」或「没找到」。内置模板「`PATH` 里没有时再看」的位置只在 `direct`、`login` 里用。找到了、但在它用的启动环境里（用户级 skill 目录，WSL 里看 WSL 用户目录下的；或每块白板目录里的 `.agents/skills`、`.claude/skills`、`.pi/skills`）看不到 `board-skills` 时，启动时在终端提醒一行（写明装到哪里），并在上报里给这个 agent 在这个环境里标上「看不到 `board-skills`」和装到哪里；只在启动时检查一次，装好后重启 `board host` 才会更新。配置文件里同标识的模板覆盖内置模板（支持的启动环境不变）。`{prompt}` 换成提示词；`{patch}` 换成 board host 为这次派发写的 profile 补丁路径（目前只有 dsh 模板用）。接入其他 agent 的方法见 `docs/agents.md`。

  | 标识 | 名称 | 命令模板 | `PATH` 里没有时再看 | 读 skill 的目录 | 支持的启动环境（Windows） |
  |---|---|---|---|---|---|
  | `dsh` | DeepSeek Harness | `dsh --profile headless --patch {patch} --permission-mode danger-full-access {prompt}` | macOS 的 `DeepSeek Harness.app` 里自带的 `dsh` | `~/.agents/skills` | `pwsh` → `powershell` → `cmd` |
  | `claude` | Claude Code | `claude -p {prompt} --dangerously-skip-permissions` | `~/.local/bin/claude`、`~/.claude/local/claude` | `~/.claude/skills` | `pwsh` → `powershell` → `git-bash` → `wsl:*` → `cmd` |
  | `pi` | pi | `pi -p {prompt}` | — | `~/.agents/skills`、`~/.pi/agent/skills` | `git-bash` → `wsl:*` → `pwsh` → `powershell`（不支持 `cmd`；不在 WSL 里时把 `PATH` 里 git 旁边的 Git Bash 放到 pi 的 `PATH` 前面） |
  | `codex` | Codex | `codex exec --dangerously-bypass-approvals-and-sandbox {prompt}` | — | `$CODEX_HOME/skills`（默认 `~/.codex/skills`） | `pwsh` → `powershell` → `git-bash` → `wsl:*` → `cmd` |
  | 配置文件里新加的 | | | | | `pwsh` → `powershell` → `git-bash` → `wsl:*` → `cmd` → `direct` |

  macOS、Linux 上所有 agent 都是 `login` → `direct`。`wsl:*` 按 `wsl.exe -l -q` 的顺序展开。
- 参数也可以写在 `~/.board/config.toml` 的 `[host]`（`name`、`dirs = { "<项目>/<白板>" = "<路径>" }`）和 `[agents.<标识>]`（`cmd = [...]`）里，命令行参数优先。
- 启动后上报机器名、操作系统、board 版本、本机 agent、白板与目录，每 10 秒一次机器心跳，连续 5 次没收到算离线。`board host` 用令牌订阅实时推送，收到派发、设置变化、停止请求后立即处理。
- `Ctrl+C` 退出：先按「人停止」结束本机由它启动的全部 agent，再让机器离线。

**机器设置**（存在服务端，在界面上修改，`board host` 实时拿到，不需要重启；机器第一次连上时按默认值建立）：

| 设置 | 默认值 | 说明 |
|---|---|---|
| 同时跑几个 | 1 | 1–8。正在跑的派发达到上限后，新的派发在服务端排队 |
| 一个会话最多做几张 | 4 | 1–8，超出范围拒绝（`USAGE`）。只对定时领取（含「现在领一轮」）启动的会话生效：agent 做完一张后用 `board next` 接着做，做满就退出，下一批换新会话。设为 1 时一个会话只做一张。手动派发的会话只做指定的那一张；人手动跑 `/board-skills` 的会话不受限制 |
| 暂停接单 | 关 | 打开后不启动新的派发（手动派发照样排队），已经在跑的不受影响 |
| 默认 agent | 本机 agent 里第一个找到的，顺序是 dsh、claude、pi、codex，然后是配置文件里新加的 | 定时领取用它；手动派发时预先选中它 |
| 每个 agent 的启动环境 | 按上表「支持的启动环境」的顺序，取本机有、并且这个 agent 在里面找得到的第一个 | 只能选这个 agent 支持、本机有、在里面找得到命令的环境，否则拒绝（`USAGE`，写明原因）。改了下一次派发就用新的，已经在跑的不受影响。设置的环境本机已经没有（例如卸载了 Git Bash）时按默认值的规则选。agent 在设置的环境里找不到命令，就算这台机器「没找到」这个 agent。旧版 `board host` 不上报启动环境：不显示这一项，按 `direct` 启动 |
| 定时领取 | 关，没有表达式 | 若干条 cron 表达式（标准 5 段「分 时 日 月 周」，支持 `*`、`*/n`、`a-b`、`a,b` 及组合，星期 0 和 7 都是周日，机器本地时区），开关。界面上不手写表达式，用选择组件生成（见 §10.12）；接口收到不合法的表达式拒绝（`USAGE`，写明哪一段不对）。升级前的 `HH:MM` 时间点按等价的 `M H * * *` 迁移，照原时间继续触发 |
| 领取规则 | 没有 | 一个有顺序的列表，每条是「条件 → agent」，最多 20 条；最后可以再设一条兜底「其余卡片 → agent」（默认不设）。条件选一个或多个标签：`in` 带其中任一个、`not in` 一个都不带、`equal` 标签正好是这几个（顺序无关）。标签按名称匹配，不区分大小写；机器可以对应多个项目的白板，哪个项目里有同名标签就在哪个项目里生效，没有同名标签的项目里按「卡片没带这个标签」算。新加或改过的规则里，标签要在这台机器有目录的项目里有、agent 要在这台机器上找得到，否则拒绝（`USAGE`，写明原因）；规则里的 agent 之后找不到了这条规则不生效，标签之后被删了照样保存，界面上都标出来。升级前的「单个标签 → agent」按等价的 `in [标签]` 迁移。只影响定时领取和会话里的 `board next`，手动派发、`board claim` 不受影响 |

**派发**：一次「在某台机器上用某种 agent 做某张卡」，来源是手动或定时。状态：排队 → 在跑 → 结束；结束的结果是已交审、做不下去、异常退出、已停止、已取消、机器掉线、没领到之一。派发、取消、开始、结束都在卡片动态里追加一条，写明机器、agent、来源和结果。派发记录一直保留。

**手动派发**：卡片详情的「派发」或 `board dispatch`。不满足下列条件时拒绝，不产生派发：

| 条件 | 错误码 |
|---|---|
| 卡片不在可领取状态 | `NOT_IN_TODO` |
| 卡片已经有排队或正在跑的派发 | `ALREADY_DISPATCHED` |
| 机器不存在（含已移除） | `NO_SUCH_HOST` |
| 机器上没有这种 agent，或在它设置的启动环境里没找到 | `AGENT_NOT_ON_HOST` |
| 机器没有这块白板的目录 | `BOARD_NOT_ON_HOST` |

派给离线、已满、暂停接单的机器时排队。卡片有排队中的派发时，别的 agent `board claim <ID>` 报 `DISPATCHED`，不带 ID 的 `board claim` 跳过它；人可以照常拖动它，拖出可领取状态时这次派发自动取消。

**定时领取**：到了任一条 cron 表达式的时间（同一分钟有几条到点也只开始一轮），机器在线、没有暂停接单时开始一轮：在这台机器有目录的白板上，按 §8 规则 1 领下一张可领取的卡片（跳过有排队派发的、以及这一轮已经派发过的），用默认 agent 开始（有领取规则时见下文）；有空位就继续领，每有一个会话（agent 进程）结束、还有空位时再开一个新会话；所有白板都没有可领取的卡片时这一轮结束。多块白板时按 `--dir` 的顺序轮流，一块白板领一张再换下一块。一轮还没结束时又到点，不重复开始；到点时机器离线或暂停接单，这次跳过，上线后不补。机器详情里的「现在领一轮」效果与到点相同。

有领取规则时：按顺序找第一条命中的规则，用它的 agent（第一条命中的规则不生效时不领这张）；一条都没命中的卡片，设了兜底时用兜底的 agent，没设时不领。候选卡片之间的先后仍按 §8 规则 1（含优先标签），不因为走的是兜底就排到后面。没有匹配的卡片（也没设兜底）时这一轮结束，即使白板上还有别的可领取卡片。

**执行**（机器在线、没有暂停、有空位时，按派发创建的先后开始）：

1. 生成 agent 名字（§3.2），check 这个名字，再以它领取卡片。领取失败（卡片已被领走、已不在可领取状态）时这次派发结束，结果「没领到」，不启动 agent。
2. 领到后，`board host` 以这个名字发心跳（每 10 秒），直到派发结束。
3. 在这块白板对应的目录里、按这个 agent 的启动环境启动 agent（用的启动环境写进派发记录，卡片动态里写明，例如「派发开始：mbp 上的 pi（Git Bash）以 pi/mbp-3 领取（手动）」）：提示词是 `/board-skills 开始执行 <项目>项目之中的<白板>白板中的#<ID>任务`，后面再带一句 board host 身份提示（`BOARD_AS=<名字>`、`BOARD_HOST=<机器名>`，卡片已由它领取，不要 check、claim、心跳，不要创建 goal；交审或交给人之后执行 `board next --json`，领到卡片就接着做，返回 `SESSION_DONE` 就结束）；环境变量带上 `BOARD_URL`、`BOARD_TOKEN`、`BOARD_AS=<名字>`、`BOARD_HOST=<机器名>`、`BOARD=<项目>/<白板>`，以及 `BOARD_CONFIG`：这次派发自己的配置文件（地址和令牌，0600，派发结束时删除），给不把名字像密钥的环境变量传给命令的 agent 用；`BOARD_EXE`：`board` 自己的路径，`board-skills` 的 `scripts/board` 优先用它，版本和 `board host` 一致。`board-skills` 看到 `BOARD_HOST` 且卡片已由 `BOARD_AS` 持有时，不再 check、不再领取、不启动也不停止心跳，其余步骤不变。
4. agent 的标准输出和标准错误写到 `~/.board/host/logs/<派发 ID>.log`，每 5 秒上传新增的行；服务端每个派发保留最后 500 行。会话里换到下一张后，进程的输出记到当时正在做的那张卡的派发上。

**会话接着做**（`board next`）：同一个 agent 进程做的几张卡算一个会话，每张卡各有一条派发记录。agent 交审或交给人之后执行 `board next`，服务端在一个写事务里：结算上一张的派发 → 挑下一张 → 以同一个名字领取 → 记一条新的派发（同一台机器、同一个 agent、同一个启动环境，来源定时；卡片动态写「派发开始：…以 <名字> 接着做（定时，这个会话的第 N 张）」）。会话占一个空位直到进程退出，取下一张不看「同时跑几个」。

- 返回 `SESSION_DONE`：这个会话已经做满「一个会话最多做几张」；会话是手动派发启动的；有人停止了这个会话；机器暂停接单或已被移除；这块白板上没有可领取的卡片。
- 上一张还由这个名字持有时拒绝（`ALREADY_HOLDING`）。
- 怎么挑下一张（候选：会话所在白板上可领取、没有排队派发、这一轮和这个会话里没派发过的卡片；有领取规则时只含按规则会交给这个会话的 agent 的卡片）：1. 按 §8 规则 1 会领到的那一张带优先标签时，就是它；2. 否则，候选里和这个会话第一张卡共同标签最多的那张（至少一个共同标签；领取规则里用到的标签不算，它只表示谁来做），并列时按规则 1 的顺序；3. 没有带共同标签的卡片时，按规则 1 的顺序取第一张。新会话的第一张仍按定时领取的规则挑。
- 取下一张时结算上一张：卡片在交审状态记「已交审」，在其他状态记「做不下去」。进程退出时只结算它最后一张，规则同下面的结束表；人停止会话里正在跑的派发时，结束整个进程，当前这张按「已停止」处理。

**结束**（「交审状态」「需要人处理的状态」按 `board-skills` 认角色的规则识别：规则、连线、状态名称里的关键词）：

| 情况 | 卡片 | 派发结果 |
|---|---|---|
| agent 退出，卡片已不被这个名字持有，在交审状态 | 不动 | 已交审 |
| agent 退出，卡片已不被这个名字持有，在其他状态 | 不动 | 做不下去 |
| agent 退出（任何退出码），卡片仍由这个名字持有 | 发 final，沿连线移到需要人处理的状态（默认工作流是「需人工校验」），评论「agent 异常退出（退出码 N）」和日志最后 20 行 | 异常退出 |
| 人停止（界面上点「停止」或 `board dispatch <ID> --cancel`）：结束包括启动环境外壳在内的整个进程树（先 SIGTERM，10 秒后 SIGKILL；Windows 结束进程树；WSL 里在 WSL 中结束 agent 的进程组） | 同上一行，评论写「<人> 停止了这次派发」 | 已停止 |
| agent 退出或人停止，但工作流从当前锁定状态连出去的状态里没有需要人处理的状态 | 不动，评论写明没有需要人处理的状态、卡片 50 秒后会回到「<可领取状态>」最上面；这一轮定时领取不会再领它 | 异常退出 / 已停止 |
| 人取消排队中的派发 | 不动 | 已取消 |
| 机器掉线超过 50 秒 | 按心跳超时规则释放（§8 规则 7） | 机器掉线 |
| `board host` 在 50 秒内重启，派发还在跑、本机没有对应进程 | 同「卡片仍由这个名字持有」 | 异常退出 |

- agent 的主进程退出后，同一进程组里剩下的进程（agent 起的子进程）一起结束（Windows 除外）。
- `board host` 没走完退出流程（被 `kill -9`、崩溃）时，它启动的 agent 还在跑：每个 agent 的进程号和启动时间记在 `~/.board/host/run/<机器名>/<派发 ID>.proc`，同名重启、第一次上报成功后，先结束这些还对得上的 agent 进程组（WSL 里在 WSL 中结束），再清理上一次的派发配置文件；这些派发按上一行记「异常退出」。同名的 `board host` 正在线时，第二个只报 `HOST_NAME_TAKEN`，不动前一个的文件。
- `board host` 的标准输出写不进去（管道读端已关、终端已关）时照常运行；退出时照样先结束 agent 再离线。

**移除机器**：取消它所有排队中的派发，停止正在跑的派发，删除机器设置；派发记录保留，界面上显示为「已移除的机器」。之后这台机器的 `board host` 再连上来，按新机器建立设置。

## 10. 界面

### 10.1 整体布局

- **顶栏**：品牌、项目 / 白板切换器、搜索（命令面板入口）、在线的 agent 头像组。
  - 头像组显示所有在线 agent（§3.2），不分白板：check 之后头像出现，离线后消失。
  - 持卡的 agent 头像外圈是心跳波纹，悬停时展开，显示这一次的耗时；提示文字是「<名字> 正在做 <项目>/<白板>#<ID>」，做过不止一次时加上累计耗时。没持卡时不跳波纹，悬停展开和提示文字只写「在线」（「<名字> 在线」）。
  - 侧栏「正在工作」和卡片上的持有者只显示持卡的 agent。
- **左侧操作台**：活动栏 + 侧栏。活动栏从上到下五个 Tab：白板、项目、未整理、机器、设置。再次点击当前 Tab 收起或展开侧栏，每个 Tab 分别记住展开或收起；侧栏宽度可以拖动调整。
- **主内容区**：在右侧，显示当前白板、项目画布或设置页。
- 活动栏图标上不显示数量徽标。
- 手机上，活动栏变为底部 Tab 栏；白板各状态左右滑动切换，顶部有状态切换条，工作流图默认收起成一行入口（「工作流 · N 个状态」），点开再看；白板页头有「筛选」按钮，打开底部抽屉：筛选框、标签（点击筛选）、正在工作、最近动态（和桌面侧栏的白板部分一样，点卡片编号打开详情），可下拉、点遮罩或 `esc` 关闭；筛选生效时页头单独一行写「筛选「…」「<标签>」· N 张」，可一键清除；「项目」「未整理」Tab 占满内容区，显示对应的列表。
- 桌面端：打开线上的 Board（`https://board.buglan.com`）。点「用 GitHub 登录」在系统默认浏览器里登录，登录完成后桌面端自动进入白板。顶栏同时是窗口标题栏，可以拖动窗口；Windows 上没有系统标题栏和菜单栏，最小化、最大化、关闭按钮在顶栏右侧。
- 主题：跟随系统 / 浅色 / 深色。
- 可读性（浅色、深色主题都满足）：要读的文字对比度 ≥ 4.5:1（≥ 18.66px 或 ≥ 14px 粗体的 ≥ 3:1），分隔符、图标、禁用态除外；agent、状态、项目、品牌色写成文字时，浅色主题下加深；品牌色按钮上的文字取白字和深色字里对比度高的那个；有信息的文字不小于 11px；可点的元素至少 24×24px，触屏上按钮和分段切换至少 36px 高；只有图标的按钮和开关都有名字（`aria-label`），开关带开 / 关状态。

### 10.2 项目 / 白板切换器（顶栏）

- 显示「项目名 / 白板名」。点击后列出所有白板，按项目分组，每块白板显示正在工作的 agent 数和可领取状态里的卡片数；可以搜索，回车切换。
- 其他白板上有 agent 正在工作时，切换器上有提示点。
- 底部有「新建白板」「项目总览」入口。

### 10.3 白板 Tab

- 侧栏：
  - 筛选框：按标题、描述、`#ID`、agent 名字、标签名筛选，不匹配的卡片淡出；输入 `label:<标签>` 只按标签筛选。
  - 「标签」：项目的全部标签块状排列，每个标签显示它在当前白板上的卡片数。点击标签即按该标签筛选，再点一次取消；按住标签拖到白板上的卡片上松手，即给这张卡片加上这个标签（卡片已有时只提示；触屏上长按后拖动；Esc 取消）；整块区域就是输入框：点空白处出现光标，输入名称后回车即新建标签。改名、改色、删除标签在命令面板和项目菜单的「管理标签」里。
  - 「正在工作」：当前白板上持有卡片的 agent、卡片和这一次的耗时。
  - 「最近动态」：当前白板最近的记录。
- 主内容区：页头显示白板名（项目只在顶栏出现一次）和「新建卡片」按钮。下面依次是工作流条和状态块。
- 工作流条：把工作流画成有向图，大约两行半高。
  - 第一行是主线：从首个可领取状态出发，沿连线走到终点状态的那条路；其余状态排在第二行，居中对齐到连向它的主线状态下面。
  - 连线是直角折线，箭头表示方向；两行之间的横线自动错开、不重叠。主线末尾是「+ 添加状态」，用虚线连接，输入名称后回车即新增（加在最后，还没有连线）。
  - 每个状态显示卡片数，以及可领取、锁定、终点的标记；可领取状态没有连到锁定状态时显示提示。
  - 鼠标放到状态上时，与它相连的连线高亮，状态右边缘出现一个圆点。
  - 连线：按住圆点拖到另一个状态上松手，即连一条线；已经连过的状态显示为已连接，松手不会重复连。
  - 改连：按住一条连线的箭头，拖到另一个状态上松手，这条连线改为指向那里；拖到空白处松手，即删除这条连线。点击连线选中后，按 `Delete` 或点 × 也能删除。
  - 拖动状态调整顺序。
  - 点击状态打开设置：名称、颜色、卡片形态、三个规则开关、删除（要二次确认，并写明卡片会移到哪里）。
- 状态块：每个状态是一个块，块的高度随卡片数量变化，标题旁显示顺序号、卡片数和规则说明。
  - 拖动块的标题摆放位置：块吸附到 12 栏网格上，并向上贴紧上方的块，块之间不留空隙；拖动块的右边缘调整宽度（按网格吸附）。块变宽后，块里的卡片排成多列。
  - 默认布局：每块占 3 栏，一行 4 块。前 4 个状态并排在最上面，第 5 个起按工作流顺序依次放到第 1、2、3、4 栏下面（第 i 个状态放第 i mod 4 栏）；位置只由顺序决定，不随卡片数变化。保存过布局的白板新增状态时同样按顺序放栏。
  - 布局按白板保存在数据库里，并同步到所有窗口。
- 白板设置：工作流条末尾的「白板设置」，每块白板自己的设置，保存在数据库里，同步到所有窗口和机器：
  - 状态块布局：「保存布局」把现在状态块的位置和宽度存成这块白板的布局（不改现在的布局）；「应用布局」把现在的布局换成存下的；「复原布局」回到默认布局，存下的布局保留，可以再应用。保存之后删掉的状态应用时跳过，新增的状态按默认布局的规则补位。
  - 保存顺序（开关，默认开）：开着时可以在同一状态块里拖动卡片调整顺序，顺序保存在服务端；关掉后在同一块里拖动，卡片留在原位并提示，拖到别的状态不受影响。只管界面上的拖动，CLI 不受影响。
  - 终点状态的卡片只增不减：打开白板时每个终点状态只带最近移入的 50 张（按移入的时间，不看排在哪里），仍按块里的顺序显示，块的标题和工作流条上仍显示总数；块里最后一格是「更早的 M 张」，和这一块的卡片形态（卡片、单行、磁贴）一样大，磁贴里写成「+M」，点击后取回全部卡片并展开，这个窗口里不再收起。没取回全部时拖进这个状态，卡片落在看到的位置（挨着看到的前后两张）。筛选框有内容、选了标签、命令面板里搜索卡片、给这个状态排序时自动取回全部，更早的卡片也能找到。从动态、搜索打开更早的卡片照常显示详情。`board ls`、`board show` 和各状态的卡片数不受影响。
- 状态块里的卡片按所在状态的卡片形态显示：
  - 卡片：显示 ID、标题、评论数、标签；被持有的卡片还显示持有者和这一次的耗时（做过多次时下方显示累计耗时和第几次）；做过的卡片不在进行中时显示累计耗时、次数和「完成于 X 前」（相对时间：刚刚 / N 分钟前 / N 小时前 / N 天前，随时间刷新；悬停显示具体日期时间；没有完成时间时不显示）。
  - 单行：ID 和标题占一行；被持有的卡片右边显示持有者和心跳。终点状态里的单行前面打勾，标题划掉。
  - 磁贴：只显示 ID，横向排列，排满自动换行。同一块里的磁贴一样宽，宽度按这一块里最长的 ID 定；高 24px，手机上 36px。被持有的磁贴右上角是持有者颜色的心跳点，心跳晚了加警告色外框。鼠标放上去显示 ID、标题、标签，被持有的还显示持有者和这一次的耗时；手机上点开看详情。
  - 不带 ID 执行 `board claim` 时会被领走的那张卡片标为「下一张」（磁贴、单行用外框标出）；筛选时三种形态都是不匹配的淡出。
- 拖拽卡片可以调整状态内顺序（白板设置开着「保存顺序」时）或换状态，拖动时显示插入位置，松手后卡片落到插入位置。拖到卡片形态、宽度不同的状态时，卡片一路变成目标状态的尺寸和形态落位。拖到不允许的状态时，该块显示禁止原因；松手后卡片回到原位，并提示原因。
- 通过 CLI 或其他窗口做的修改，已打开的界面在 2 秒内显示出来，不需要刷新页面，被改动的卡片会短暂高亮并标出是谁做的。

### 10.4 项目 Tab

- 侧栏：项目 → 白板的树。每个项目显示白板数和正在工作的 agent 数；每块白板显示正在工作的 agent 数和可领取状态里的卡片数。点击白板即打开它（切到白板 Tab）。
  - 项目行的菜单：新建白板、编辑项目、管理标签、改颜色、删除项目。
  - 白板行的菜单：打开、编辑白板、复制为提示词、复制 `BOARD=<路径>`、删除白板。
  - 画布上的节点有同样的菜单。
- 主内容区：无限画布。
  - 每个项目是一个节点，用连线连到它的各块白板节点。
  - 白板节点显示名称、路径、各状态卡片数、正在工作的 agent，以及「打开」按钮。有 agent 在工作的白板，连线显示为流动状态。
  - 拖动空白处平移；`⌘` / `Ctrl` + 滚轮或双指捏合缩放；有放大、缩小、100%、适应画布、定位到当前白板按钮。默认视图和「适应画布」的缩放不低于 75%，放不下时从左上角开始，拖动查看其余部分。
  - 拖动节点调整位置，位置会保存并在所有窗口同步。
  - 双击白板节点打开该白板；双击空白处新建项目；点项目节点右侧的「+」在该项目下新建白板。
- 新建项目：填名称、标识（根据名称自动生成，可修改）、描述、颜色、第一块白板的名称和标识。
- 新建白板：选所属项目，填名称、标识（自动生成，可修改）、描述。

### 10.5 未整理 Tab

- 侧栏：顶部是「记一条未整理」入口，下面是当前白板的未整理条目，侧栏标题旁显示条目数。条目显示 ID、标题、描述的第一行、标签、创建时间。界面或 agent/CLI（`board new --inbox`）都可以新建条目。
- 条目可以拖到右侧白板的状态块里，也可以点「整理到<首个可领取状态>」。
- 主内容区仍然显示当前白板。

### 10.6 设置 Tab

- 侧栏：设置目录，点击跳到对应部分；「账号」排在第一。
- 主内容区：
  - 账号：当前登录的 GitHub 账号（头像、名字、账号名）与「退出登录」；本机模式下显示不需要登录
  - 外观：主题、卡片密度（舒适 / 紧凑）、动效（完整 / 减弱）
  - 白板规则：当前白板的工作流有向图（和白板页的工作流条同一张图：状态、连线、卡片数、可领取/锁定/终点标记都一样；只读，不能连线、拖动、打开状态设置，窄屏时在框里横向滚动），三个规则开关的说明，以及 §8 的规则摘要
  - Agent 接入：`board-skills` 的用法（§10.9）与安装（可复制 SKILL.md）、`board` 命令行的安装（按系统给出说明：Windows 随桌面端装好、macOS 给一条把 `board` 目录写进 shell PATH 的命令、其他情况从源码装）、连接服务端（`board login`，§9）、错误码；快捷提示词里「做某状态里带某标签的任务」每个可领取状态一行，在行里选标签（当前项目的标签）后复制
  - 访问令牌：单独一节，在侧栏目录里；新建、列表、吊销（§3.1）
  - 新建令牌后只给一条命令：`board login --url <当前服务端地址> --token <令牌>`，不分 shell。桌面端另有「一键写入」：把服务端地址和令牌写进 `~/.board/config.toml`（效果同 `board login`），不改 shell 配置文件和系统环境变量
  - 本机（只在桌面端）：开关「让这台电脑接任务」，打开后桌面端在后台用自带的 `board` 运行 `board host`，关掉窗口也继续运行（macOS 点 Dock 图标、其他系统点托盘图标重新打开窗口），退出桌面端时结束；下次打开桌面端自动运行。同一处可以编辑机器名和白板与目录（写进 `~/.board/config.toml` 的 `[host]`），显示 `board host` 在不在跑和最近的输出。打开「让这台电脑接任务」、修改白板目录时，桌面端先弹系统确认框，列出机器名和每个白板的目录，确认后才生效，取消则配置不变（关掉接任务不用确认）；保存设置要重启 `board host` 时，等旧的退出后才启动新的。桌面端只给线上地址（或 `BOARD_URL` 指定的那个地址）的页面开放本机命令；同一台电脑上只运行一个桌面端，再次打开只把已有窗口带到前面
  - 快捷键
- 窄屏（手机）下标签与控件上下堆叠：分段控件完整可见，代码块、错误码、令牌列表、白板与目录行可换行或横向滚动，页面没有横向滚动；触屏设备上输入框字号不小于 16px，避免 iOS Safari 聚焦输入框时自动放大页面。桌面端宽屏外观不变。

### 10.7 新建（居中弹窗）

- 白板 Tab 的「新建卡片」入口和未整理 Tab 的「记一条未整理」入口都打开同一个居中弹窗。弹窗大小与卡片详情相同。
- 左侧：标题（必填）、描述（Markdown，可以切换编辑 / 预览，可以插入验收标准模板）。
- 右侧：「放到」首个可领取状态或未整理（从未整理入口打开时默认未整理）、标签、等价的 CLI 命令（选未整理时带 `--inbox`）、「连续新建」开关。
- 标题里按 `↵` 创建；`⌘ ↵` / `Ctrl ↵` 在任何位置创建；`⇧ ↵` 跳到描述。标题为空时不能创建，并提示原因。
- 「连续新建」打开时，创建后清空标题和描述、保留标签，继续录入下一条，并列出本次已创建的卡片。
- 关闭弹窗时，未提交的内容保留为草稿，下次打开自动恢复，并可以一键清空。

### 10.8 卡片详情（居中弹窗）

- 点击卡片打开详情。弹窗居中，固定宽 920px、高 640px，窗口不够大时按窗口缩小；手机上从底部弹出，可以下拉关闭。
- 顶部：卡片 ID、所在状态、同状态内「上一张 / 下一张」及位置、「复制为提示词」、关闭。
- 左栏：
  - 标题、创建者和时间、标签（可以加或去）；
  - 被持有的卡片显示持有者、这一次的耗时、累计耗时、领取次数、心跳次数（各次领取收到的心跳之和，含 final）和异常退出次数，并有「强制释放」按钮，标题和描述只读；累计耗时、领取次数、心跳次数、异常退出写成一行；做过的卡片不在进行中时只显示这一行，并加上「完成于 X 前」（悬停显示具体日期时间），没做过的不显示；
  - 「未整理」的条目有「整理到<首个可领取状态>」按钮；
  - 描述（编辑 / 预览），编辑时可以粘贴截图、拖入文件或点「附件」上传；
  - 附件列表：图片缩略图（点击放大）、文件名、大小、上传者，点击文件名下载；
  - 有排队或正在跑的派发时显示派发状态：排队写「排队 → <机器> · <agent>」和原因（等空位 / 等机器上线 / 暂停接单），对应「取消派发」；在跑写机器、agent 名字和已跑时间，可以展开日志，对应「停止」；
  - 底部操作栏：左边「删除」（删除前要二次确认），右边「派发」和「移动到」。「派发」只对可领取状态里、没有派发的卡片可用，打开对话框选机器和 agent（§10.12）。
- 右栏：动态（默认显示到最新一条）和评论框；评论框里可以粘贴截图或点回形针按钮上传附件。评论发出后输入框立即清空，动态底部先显示「发送中」，服务端确认后转成正式评论，失败时原文回到输入框。人发的评论悬停时有「编辑」「删除」按钮：点编辑原地修改（⌘/Ctrl+Enter 保存、Esc 取消，空内容不能保存）；点删除要二次确认，删除后无法恢复。

### 10.9 复制为提示词

- agent 通过 skill 接入：`board-skills` 写明身份与白板的设置方法、处理卡片的步骤（先领取 → 按描述和验收标准干活、用评论记进度 → 交审；做不下去时评论原因，沿连线移到需要人处理的状态，例如「需人工校验」）、整理「未整理」条目的方法、§8 的规则和 §12 的错误码。skill 要求 agent 拿到卡片后第一条和这张卡片有关的命令就是 `board claim <ID>`：领取成功之前不读卡片、不看代码、不调研、不发这张卡片的进展，免得调研期间卡片被别人领走，也让耗时（从领取后的第一次心跳算起）包含全部实际工作。skill 随项目提供（`.agents/skills/board-skills/SKILL.md`，各家 agent 能自动识别；Claude Code 通过 `.claude/skills/board-skills` 链接识别）。
- 复制为提示词只复制一行 skill 调用，卡片的标题、描述、动态由 agent 用 CLI 自己读取：
  - 卡片：`/board-skills 开始执行 <项目>项目之中的<白板>白板中的#<ID>任务`（例如 `/board-skills 开始执行 mini项目之中的main白板中的#2任务`），一句完整的话就说清项目、白板、卡片编号。卡片详情的「复制为提示词」按钮和 `C` 键复制这一行。
  - 白板：`/board-skills <项目>/<白板>`，agent 循环执行不带 ID 的领取，直到 `EMPTY_TODO`。项目树和画布上白板的菜单里有这一项。
- skill 的参数也可以是一句话需求：agent 先用 `board new` 记到首个可领取状态，再按卡片处理。
- 复制后提示已复制的内容。

### 10.11 登录页

- 没有登录时显示：Board 标识、一句说明、「用 GitHub 登录」按钮。
- 点按钮跳到 GitHub 授权，授权后回到 Board 并打开白板。
- 登录失败时在按钮上方显示原因：账号没有权限、登录已过期、取消了授权、无法从 GitHub 取得账号信息。

### 10.12 机器 Tab

- 活动栏图标：两层服务器。
- 侧栏：标题「机器」，右边 `在线数/总数`、「＋」（添加机器）；每台机器一行：状态点、名字、`在跑/上限`（暂停时写「暂停」，离线时写多久前在线），下面列出正在跑的卡片（agent 标记 + `#ID`）。点一行打开这台机器的详情。
- 主区（机位总览）：标题「机器」、一句说明、「添加机器」按钮（没有机器时不显示汇总条，侧栏的「＋」和这个按钮也不显示，只留空状态里一个「添加机器」）；汇总条：在线台数 `x/总数`、在用的并发位 `x/总位数`（不算暂停和离线的机器）、排队张数、占用比例条；每台机器一张卡片，两列排：
  - 头部：系统图标、名字、系统和最近心跳（离线时写多久前在线）、状态胶囊（满载 / 在跑 / 空闲 / 暂停接单 / 离线）；
  - 并发位：上限是几就画几格。占用的格子显示 agent 标记、`#ID`、标题、已用分钟、最近心跳、来源（手动 / 定时）；空格子写「空位」，暂停时写「暂停」，离线时画斜纹写「离线」；
  - 有排队时列出排队的卡片；
  - 底部：设置里会用到的 agent（默认 agent、领取规则和兜底里的 agent），不把检测到的全部列出；胶囊带上启动环境（例如「pi · Git Bash」，默认的标「默认」；在用的启动环境里看不到 `board-skills` 的加警告色外框和警告标记，鼠标放上去写明装到哪里）、定时领取的摘要（和机器详情里的胶囊一样，例如「每天 23:00、工作日 09:00」；没开或没设表达式时不显示）。
- 机器详情：与卡片详情同一种居中弹窗。顶栏：系统图标、状态胶囊、上一台 / 下一台（`↑↓` / `K J`）、关闭（`esc`）。左栏从上到下：名字和系统、board 版本、最近心跳；正在跑 `x/上限`（每个派发一行：agent 标记、`#ID`、标题、agent 名字、启动环境、已用时间、最近心跳、来源，「日志」展开最后 500 行，「停止」）；排队（「等空位」或「等机器上线」、来源、排了多久，「取消派发」）；派发规则（同时跑几个 − / ＋、一个会话最多做几张 − / ＋、定时领取的开关和定时列表（胶囊写说明，例如「每天 03:00」「工作日 09:00」「每周一、三、五 09:00」「每月 1 号 09:00」「每 30 分钟」「每 2 小时」，说不出来的旧表达式写原样，悬停看表达式；不手写 cron：下面一行选「每天 / 工作日 / 每周（点选周一到周日）/ 每月（几号）」加「时 : 分」（分钟按 5 分钟一档），或「每隔几分钟（5、10、15、20、30）/ 每隔几小时（1、2、3、4、6、8、12）」，点「加一条」生成表达式；已有的同一条不能再加，每周一天都没选时不能加）、「现在领一轮」、领取规则：每条规则可上移、下移、删除，下面一行加规则，最后一行「其余卡片 →」选兜底 agent 或「不领」；规则或兜底的 agent 找不到时这一行划掉并写「这台机器上找不到 <agent>，这条规则不生效」；每条规则是「条件下拉（带其中任一个 / 一个都不带 / 标签正好是）、标签（和卡片详情的标签一行一样：标签胶囊和颜色，× 去掉；点标签按钮打开同一个标签选择器，勾一个应用一个。机器只对应一个项目时就是那个项目的选择器，能新建、管理标签；对应几个项目时只列这几个项目里的标签，不能新建）→ agent 下拉」；标签在项目里没有时划掉并写明；有规则、没设兜底时下面写「有 N 张可领取的卡片没有匹配任何规则」（这台机器有目录的白板上的合计，N = 0 时不显示））；本机 agent（每个 agent 一行：图标、名称、启动环境下拉——列出这个 agent 支持、本机有的环境，每项带版本号，找不到的置灰写「没找到」——、「默认」标记，点一下设为默认；没找到的 agent 下拉禁用；在用的启动环境里看不到 `board-skills` 时，这一行下面用警告色写「<agent> 在<启动环境>里看不到 board-skills：派给它的卡片会做不成，先装到 <位置>（见 docs/agents.md）」，下拉里看不到的环境也标上；旧版 `board host` 不显示下拉，写版本号，也不显示这条提醒）；启动环境（发现的启动环境，每行名称和程序路径，名称列同宽、路径左端对齐，WSL 写发行版；旧版 `board host` 不显示）；白板与目录（路径太长时中间省略，保留开头和最后一级目录，悬停显示全路径）；「启动环境」「白板与目录」和右栏「最近」可以点标题收起 / 展开（标题带箭头），前两个默认收起，展开状态记在本机；底部操作栏左边「移除机器」、右边「暂停接单 / 恢复接单」，贴在左栏底部，不用滚到底就能看到。设置都是当帧生效：开关滑动、数字滚动、新的时间点和规则滑入，保存成功这一行闪一下；保存失败时值回到原处，这一行回弹并闪警告色，再提示原因；减弱动效时不播放这些动画。右栏「最近」：这台机器最近 50 个结束的派发（agent、`#ID`、标题、结果、启动环境、用时、结束时间），顶部写今天交审几个、异常退出几个。
- 添加机器：同样的居中弹窗，写两种方法：装了桌面端的电脑在「设置 → 本机」打开「让这台电脑接任务」；只有命令行的机器先 `board login`，再 `board host --name … --dir …`。
- 派发对话框（卡片详情的「派发」）：列出所有机器，每台显示在线 / 离线、`在跑/上限`、是否暂停接单；离线、已满、暂停的机器可以选，写明「会排队」；没有这块白板目录的机器不能选，写明「没有这块白板的目录」。选机器后列出它的本机 agent（胶囊带上启动环境，例如「pi · Git Bash」），没找到的不能选，默认选中这台机器的默认 agent。选中看不到 `board-skills` 的 agent 时，胶囊带警告标记，下面显示和机器详情里一样的提醒，仍然可以派发。点「派发」后关闭对话框，卡片上出现派发状态。
- 白板上的卡片：有排队中的派发时写「排队 → <机器> · <agent>（原因）」；在跑时显示持有者和耗时（与领取相同）。

## 11. 实时同步

- 多个窗口、CLI 读写的是同一份数据。任一处的修改，其他已打开的界面在 2 秒内显示出来。
- 实时推送只发给已登录的界面和带令牌的 `board host`（§3.1、§9.1）。
- agent 上线（check）、下线（`board beat --final` 或心跳中断）和卡片状态变化时推送；只更新心跳时间的 `board beat` 不推送。
- 机器上线、离线、设置变化，以及派发的排队、开始、停止请求、结束时推送；推送里带上机器和派发的版本，`board host` 看到它变了就重新取自己的任务。只更新心跳时间的机器心跳不推送，机器页、机器详情打开时立即刷新一次最近心跳，之后每 10 秒一次。
- 项目画布上节点位置、工作流和状态块布局的修改也同步到所有窗口。

## 12. 错误码

| 错误码 | 出现时机 |
|---|---|
| `NO_IDENTITY` | CLI 没有提供 agent 名字。提示：先 `board check --as <名字>`，之后每条命令都带 `--as <名字>` |
| `NO_BOARD` | CLI 没有指定白板 |
| `BOARD_NOT_FOUND` | 指定的项目或白板不存在；或项目下有多块白板却只写了项目标识 |
| `NOT_FOUND` | 卡片不存在 |
| `EMPTY_TITLE` | 新建或编辑时标题为空 |
| `EMPTY_TODO` | 不带 ID 领取时，连到锁定状态的可领取状态里都没有卡片 |
| `NOT_IN_TODO` | 带 ID 领取的卡片不在可领取状态，且不是自己持有的卡片 |
| `ALREADY_HOLDING` | 该 agent 在这块白板上已经持有另一张卡片 |
| `NOT_HOLDER` | 编辑或移动被持有卡片的不是持有者 |
| `FORBIDDEN_COLUMN` | 把卡片直接移进锁定状态；agent 把卡片移入、移出终点状态或「未整理」；agent 不沿连线移动卡片；从没有连到锁定状态的可领取状态领取 |
| `USAGE` | 命令格式或参数不正确：未知的命令、未知的状态、项目里不存在的标签、agent 加或去「仅人可打」的标签、缺少必需的参数、评论内容为空 |
| `NOT_LOGGED_IN` | 没有登录：界面没有登录会话；CLI 的环境变量和配置文件里都没有服务端地址或令牌（提示运行 `board login`）；用访问令牌调用只能在界面上做的管理接口（项目、白板、工作流、标签、机器） |
| `INVALID_TOKEN` | 访问令牌不存在或已吊销 |
| `UNREACHABLE` | CLI 连不上服务端 |
| `NAME_TAKEN` | `board check` 的名字正被在线 agent 使用（HTTP 409） |
| `NAME_OFFLINE` | 名字没有 check，或心跳中断超过 50 秒：带令牌的卡片命令、上传附件、agent 级心跳被拒绝（HTTP 409）。原因：「名字不在线：没有 check，或心跳中断超过 50 秒，先 board check --as <名字>」 |
| `NOT_AUTHOR` | 修改或删除不是自己发的评论：agent 修改、删除任何评论，或人修改、删除 agent 的评论（HTTP 403） |
| `HOST_NAME_TAKEN` | `board host` 的机器名正被另一个在线的 `board host` 使用（HTTP 409） |
| `ALREADY_DISPATCHED` | 派发的卡片已经有排队或正在跑的派发（HTTP 409） |
| `NO_SUCH_HOST` | 派发、修改、移除的机器不存在，含已移除的机器（HTTP 404） |
| `AGENT_NOT_ON_HOST` | 派发的 agent 不在这台机器上，或标为没找到（HTTP 409） |
| `BOARD_NOT_ON_HOST` | 派发的卡片所在白板在这台机器上没有目录（HTTP 409） |
| `DISPATCHED` | 卡片有排队中的派发，别的 agent 带 ID 领取它（HTTP 409） |
| `SESSION_DONE` | `board next`：这个会话不再接着做（做满了、手动派发、有人停止、暂停接单或已移除、没有可领取的卡片）（HTTP 409） |
| `INTERNAL` | 服务端内部错误（HTTP 500），例如数据库或文件读写失败 |

## 13. 验收标准

1–11 在同一块白板上执行，CLI 已登录（`board login`），名字已 check 并在发心跳，命令带上名字和白板（`--as`、`--board`，或 `BOARD_AS`、`BOARD`）；服务端和本机两种连接方式（§9）结果相同。

1. 「待办」从上到下是 #1、#2。α 执行 `board claim`，得到 #1；#1 进入「进行中」，持有者是 α。
2. 「待办」里只有 #1。α 和 β 同时执行 `board claim 1`：一个成功，另一个得到 `NOT_IN_TODO`。
3. α 持有 #1，再执行 `board claim`，得到 `ALREADY_HOLDING`。
4. α 持有 #1。β 执行 `board edit 1 --title x`，得到 `NOT_HOLDER`；β 执行 `board comment 1 "…"`，成功。
5. α 在 10:00 领取 #1，10:00:02 开始心跳并每 10 秒一次，10:20:05 发 final：动态里记「第 1 次耗时 20 分 3 秒」，卡片累计耗时 20 分 3 秒。
6. α 在 10:00 领取 #1，心跳到 10:10 后中断。10:10:50 时 #1 回到「待办」最上面，持有者为空，动态里记「心跳中断」「判定异常退出，第 1 次耗时约 10 分」。β 随后领取 #1；α 再执行 `board move 1 review`，得到 `NOT_HOLDER`。
7. α 持有 #1，执行 `board move 1 done`，得到 `FORBIDDEN_COLUMN`；执行 `board move 1 review` 成功，持有者清空。人把 #1 拖到「已完成」，成功。
8. 人把「待办」里的卡片拖进「进行中」：卡片回到原位，并显示原因。agent 执行 `board move 2 doing`，得到 `FORBIDDEN_COLUMN`。
9. 人对 α 持有的 #1 点「强制释放」：#1 回到「待办」最上面，持有者为空；α 之后执行 `board claim`，不会得到 `ALREADY_HOLDING`。
10. 执行 `board new "x"` 后，已打开的界面在 2 秒内出现卡片 x，不需要刷新。
11. 任一命令加 `--json`，都输出合法 JSON；被拒绝时退出码为 1，JSON 里带错误码。

项目与白板：

12. 没有 `--board` 也没有 `BOARD` 时执行 `board ls`，得到 `NO_BOARD`。
13. 项目 `oss` 下有白板 `main` 和 `release`：`--board oss` 得到 `BOARD_NOT_FOUND`，原因里列出 `main`、`release`；`--board oss/nope` 得到 `BOARD_NOT_FOUND`。项目 `site` 下只有白板 `launch`：`--board site` 等同于 `--board site/launch`。
14. 在新建的白板上执行 `board new "x"`，得到 #1。
15. α 在 `oss/main` 持有一张卡片，在 `oss/release` 执行 `board claim`，成功。
16. 在 `oss/main` 执行 `board new "x"`，正在看 `oss/release` 的界面不出现卡片 x。
17. 人在界面上删除白板 `oss/release` 后，agent 以 `BOARD=oss/release` 执行任一命令，得到 `BOARD_NOT_FOUND`。
18. `board boards` 列出所有白板的路径。

未整理：

19. agent 执行 `board new "想法" --inbox --json` 成功，返回 `column=inbox`、`holder=null`，条目位于「未整理」最下面；`board ls --column inbox` 能看到它。人在界面上也能新建放进「未整理」的条目 #5。「待办」为空时 agent 执行 `board claim`，得到 `EMPTY_TODO`；执行 `board claim 5`，得到 `NOT_IN_TODO`。
20. 人对 #5 点「整理到待办」，#5 出现在「待办」最下面。
21. 人把「未整理」里的条目拖到「进行中」：条目回到原位，并显示原因。

标签：

22. α 持有 #1。β 执行 `board label 1 +bug`，成功，#1 的动态里有一条加标签的记录，持有者仍是 α。
23. 执行 `board label 1 +不存在的标签`，得到 `USAGE`。
24. `board ls --label bug` 只列出带 bug 标签的卡片。
25. 人在界面上删除标签 bug 后，项目内所有卡片上都没有 bug 标签。

工作流（默认工作流，§7）：

26. 人在 `oss/main` 新增状态「设计中」（标识 `s1`），拖到「待办」之后，并从「待办」连线到「设计中」。agent 执行 `board move 2 设计中` 成功；执行 `board move 3 review`，得到 `FORBIDDEN_COLUMN`，原因里列出「待办」能去的状态；人把 #3 拖到「待审核」，成功。`board flow` 按顺序列出 待办、设计中、进行中、待审核、已完成、返工、需人工校验，每个状态后面列出它能去的状态。
27. 「待办」为空，「返工」里有 #4。α 执行 `board claim`，领到 #4，#4 进入「进行中」。「待办」「返工」都有卡片时，`board claim` 先领「待办」的；人把「返工」拖到「待办」之前后，先领「返工」的。
28. 人新增状态「测试中」，打开「锁定」，并从「进行中」连线到「测试中」。α 持有 #1（在「进行中」），执行 `board move 1 测试中` 成功，持有者仍是 α；人把另一张卡片拖进「测试中」，被拒绝并显示原因。
29. 人删除状态「设计中」：里面的卡片出现在「待办」最下面，「待办 → 设计中」的连线一起消失。
30. 人在一个窗口里拖动状态块、改工作流或连线，另一个打开同一块白板的窗口在 2 秒内显示同样的结果。
31. α 持有 #1（在「进行中」），执行 `board move 1 todo`，得到 `FORBIDDEN_COLUMN`，原因里列出「待审核」「需人工校验」；执行 `board move 1 需人工校验` 成功，持有者清空。人把 #1 从「需人工校验」拖到「待审核」，成功。
32. α 领取「返工」里的 #4 后心跳中断：#4 回到「返工」最上面，不回「待办」。人对 α 持有的「返工」卡片点「强制释放」，结果相同。
33. 人在工作流条上拖动连线「返工 → 进行中」的箭头到空白处松手，连线删除，「返工」显示提示；α 执行 `board claim 4`，得到 `FORBIDDEN_COLUMN`；不带 ID 执行 `board claim` 时跳过「返工」。
34. agent 执行 `board move 2 inbox`，得到 `FORBIDDEN_COLUMN`；人把卡片拖进「未整理」，成功。

复制为提示词：

35. 在卡片 #3 的详情里点「复制为提示词」，剪贴板里是 `/board-skills 开始执行 <项目>项目之中的<白板>白板中的#3任务`。把这一句发给装了 `board-skills` 的 agent，agent 从话里认出项目和白板、领取 #3、完成后移到「待审核」，期间不需要人补充其他信息。

登录与访问令牌：

36. 没有登录时打开网页端或桌面端，显示登录页。不带登录会话和令牌请求任一 API（包括 `/api/stream`），返回 `NOT_LOGGED_IN`。
37. 用指定的 GitHub 账号登录，进入白板。用其他 GitHub 账号登录，停留在登录页，并提示该账号没有权限。
38. 在「设置 → 账号」退出登录后，界面回到登录页；退出前的会话再请求 API，返回 `NOT_LOGGED_IN`。
39. 在「设置 → Agent 接入」新建令牌，原文只显示这一次，下面只给出一条 `board login --url <当前服务端地址> --token <令牌>`。执行它之后，agent check 名字并执行 `board claim`，成功，持有者是这个名字；已打开的界面在 2 秒内显示。
40. 环境变量和配置文件里都没有服务端地址，或有地址没有令牌，得到 `NOT_LOGGED_IN`；令牌写错或已吊销，得到 `INVALID_TOKEN`；服务端连不上，得到 `UNREACHABLE`。退出码都是 1。
41. 用访问令牌新建项目、删除白板、修改工作流，得到 `NOT_LOGGED_IN`。
42. 同一份数据上，服务端方式和本机方式执行同一条命令，`--json` 输出相同。

卡片形态：

43. 新建白板：「已完成」的卡片显示为磁贴，其他状态显示为卡片。人新增状态「已发布」，显示为卡片；打开「终点」后显示为磁贴。人在「待审核」的设置里把卡片形态选为「单行」，另一个打开同一块白板的窗口在 2 秒内同样显示为单行；再把「待审核」设为终点，仍是单行。

配置文件与登录：

44. `board login --url <地址> --token <令牌>` 写出权限为 0600 的 `~/.board/config.toml`；之后不设任何环境变量，`board ls` 可用。
45. 令牌错误时 `board login` 报 `INVALID_TOKEN`，配置文件不变。
46. 环境变量和配置文件都有值时，CLI 用环境变量；`board doctor` 标出来源，状态为 warn。
47. `board logout` 后 `board ls` 报 `NOT_LOGGED_IN`，文件里保留 `url`。
48. 设置页新建令牌后只给出一条 `board login` 命令；桌面端「一键写入」写的是 `~/.board/config.toml`。

agent 名字与心跳：

49. 两个进程同时 check 同一个名字，只有一个成功，另一个得到 `NAME_TAKEN`。
50. 用没 check 过的名字执行 `board new`，得到 `NAME_OFFLINE`。
51. check 后不发心跳，50 秒后名字离线，同一个名字可以再次 check 成功。
52. 格式不对的名字 check 时报 `USAGE`，例如 `claude`、`Claude/opus`、`a/b/c`、超过 48 个字符的名字。
53. 后台循环只发 `board beat`（不带 ID）时，持有的卡片不会被释放；卡片动态里有「开始第 n 次」，心跳次数在增长。
54. 停掉后台循环后，50 秒内名字离线，它在所有白板上持有的卡片回到领取起点最上面，动态里有「心跳中断」。
55. `board beat <ID> --final` 之后，后台心跳不再刷新这张卡片；50 秒内没移走就释放；之后的 `board beat <ID>` 被拒绝。
56. 本次耗时与卡片上的累计耗时计算方式不变（规则 6、7）。
57. `board heartbeat stop` 之后名字立刻离线。
58. 同一台 Mac 上开两个 dsh 会话，各自 check 并启动心跳；关掉其中一个，50 秒内它的名字离线，另一个不受影响。
59. 右上角头像在 check 后出现、离线后消失，提示文字区分「正在做 …」和「在线」（没持卡）；只发存活心跳时，界面不会每 10 秒刷新一次。

任务下发（§9.1）：

60. `board host --name mbp --dir oss/main=<目录>` 启动后，界面「机器」页出现 mbp：在线、同时跑 1、本机 agent 里 Claude Code 带版本号；PATH 里没有的 agent 显示为没找到。再用同名启动第二个 `board host`，报 `HOST_NAME_TAKEN`。
61. 在 #3（待办）的详情里点「派发」→ mbp → Claude Code，2 秒内 mbp 领取 #3，持有者是 `claude/mbp-1`；`~/.board/host/logs/` 下出现这次派发的日志，界面上「日志」能看到内容。
62. agent 按 skill 做完并移到「待审核」后退出：派发结果「已交审」，mbp 的并发位空出，卡片动态里有派发开始和结束两条记录。
63. mbp 同时跑 1 个时再派发 #4：#4 显示「排队 → mbp · Claude Code（等空位）」，别的 agent `board claim 4` 报 `DISPATCHED`；#3 结束后 #4 自动开始。
64. mbp 离线时派发 #5：显示「等机器上线」；mbp 上线后 #5 开始。
65. 正在跑 #3 时在界面上点「停止」：10 秒内 agent 进程结束，#3 移到「需人工校验」，评论写明是谁停止的，派发结果「已停止」。
66. agent 进程被 `kill -9`：#3 移到「需人工校验」，评论里有退出码和日志最后 20 行，派发结果「异常退出」；mbp 开着定时领取时，下一张领的不是 #3。
67. 关掉 mbp 的网络超过 50 秒：#3 按心跳超时规则回到原状态最上面，派发结果「机器掉线」。
68. 设置定时领取的 cron 表达式为下一分钟（例如 `M H * * *`）、同时跑 2：到点后 mbp 连续领两张可领取的卡片；一张结束后马上领下一张；待办领完后不再领。点「现在领一轮」效果相同。
69. 暂停接单后手动派发：派发排队，原因写「暂停接单」；恢复后开始。
70. `board dispatch 6 --host mbp --agent pi`（pi 没找到）报 `AGENT_NOT_ON_HOST`；`board dispatch 6 --host nope` 报 `NO_SUCH_HOST`；对没有目录的白板派发报 `BOARD_NOT_ON_HOST`。
71. 移除 mbp：排队的派发取消、正在跑的停止；mbp 的 `board host` 重新连上后作为新机器出现，设置是默认值。
72. 桌面端打开「让这台电脑接任务」后关闭窗口，机器仍在线；退出桌面端后机器离线。

启动环境（§9.1）：

73. Windows 机器装了 Git for Windows、PowerShell 7 和 WSL 发行版 Ubuntu：`board host` 启动后，机器详情「启动环境」列出 cmd、Windows PowerShell、PowerShell 7、Git Bash、WSL（Ubuntu）、直接启动。
74. 同一台机器上，pi 的启动环境下拉里没有 cmd，默认是 Git Bash；派一张卡给 pi，派发记录写「Git Bash」，结果「已交审」。
75. 把 pi 的启动环境改成 WSL（Ubuntu）（WSL 里装了 pi 和 `board-skills`），不重启 `board host`，派一张卡：agent 在 WSL 里、仓库对应的 `/mnt/…` 目录里启动，结果「已交审」；再派一张，点「停止」：10 秒内 WSL 里的 agent 进程结束，卡片移到「需人工校验」。
76. WSL 里没装 pi 时，pi 的启动环境下拉里 WSL（Ubuntu）置灰并写「没找到」；把设置改成它被拒绝（`USAGE`）。
77. macOS 上默认启动环境是登录 shell：只在 `~/.zshrc` 里加进 `PATH` 的 agent 命令，`board host` 能找到并启动。
78. 机位卡片和派发对话框里的 agent 胶囊显示「pi · Git Bash」这样的启动环境。
79. 「管理标签」里把一个标签设为优先、取消优先，刷新后保持；升级前已有的标签都不是优先。优先标签的胶囊带闪电，深色、浅色主题下都看得清。
80. 待办从上到下是 A、B、C，只有 C 带优先标签：`board claim`（不带 ID）领到 C，再领一次领到 A。「待办」里没有带优先标签的卡片、「返工」里有：领到「返工」里那张。同一个状态里两张带优先标签的：先领上面那张。
81. 带优先标签的卡片有排队中的派发时照样被跳过；`board claim <ID>`、手动派发的行为不变；定时领取一轮里带优先标签的卡片先被派发。
82. `board labels --json`、`board ls --json`、`board show --json` 里能看出标签是否优先；取消优先、或把优先标签从卡片上去掉后，领取顺序恢复成原来的。
83. 机器详情里能改「一个会话最多做几张」（1–8，默认 4），`board host` 不重启就生效；超出范围被拒绝。
84. N = 4、待办里有 6 张同标签的卡片、同时跑 1 个：现在领一轮后，第一个进程做 4 张后退出，第二个进程做剩下 2 张；每张卡各有一条派发记录、各一个提交。
85. 会话第一张带 `UI` 标签，待办从上到下是 X（无共同标签）、Y（带 `UI`）：`board next` 领到 Y；候选里都没有共同标签时按规则 1 的顺序领第一张；出现带优先标签的卡片时领到它。
86. N = 1、手动派发的会话里 `board next` 返回 `SESSION_DONE`；不是 `board host` 启动的会话执行 `board next` 报 `USAGE`；上一张还没交审就执行报 `ALREADY_HOLDING`；机器暂停接单后，在跑的会话做完当前这张，`board next` 返回 `SESSION_DONE`。
87. 取下一张后，上一张的派发结果是「已交审」或「做不下去」；会话做第 2 张时进程异常退出或被人停止：第 1 张的结果不变，第 2 张按「异常退出」/「已停止」处理，不再领下一张。
88. 同时跑 2 个、N = 4：两个会话各自取下一张，不会领到同一张卡，在跑的进程不超过 2 个；agent 没执行 `board next` 直接退出时按现有规则结算，这一轮接着开新会话。
89. 机器详情里能加、删、改领取规则和调顺序，`board host` 不重启就生效；没有规则时定时领取的行为和改动前一样。
90. 规则 `claude → claude`，待办里有带 `claude`、带 `deepseek`、不带标签的卡片各一张：现在领一轮只派发带 `claude` 的那张，用 claude；另外两张留在待办，这一轮结束。规则 `claude → claude`、`deepseek → dsh`：两种卡片分别由对应的 agent 做。规则 `claude → claude`、兜底 dsh：不带标签的和带 `deepseek` 的由 dsh 做。
91. 规则 `claude → claude`、没设兜底，待办里有 2 张不带 `claude` 的卡片：机器详情显示「有 2 张可领取的卡片没有匹配任何规则」；给其中一张加上 `claude` 后变成 1 张；设了兜底后不再显示。
92. 一张卡片同时带两条规则的标签：用排在前面的那条规则的 agent；标签名大小写不同也能匹配；项目里没有同名标签时不报错，只是匹配不到。规则里选这台机器上没有的 agent 被拒绝（`USAGE`）；agent 之后找不到时，这条规则不生效，界面上有提示。
93. 会话里 `board next` 只领按规则属于这个会话的 agent 的卡片；会话第一张带 `claude`、`UI`，待办里 X（只带 `claude`）在上、Y（带 `claude`、`UI`）在下：领到 Y，只有 X 时领到 X。手动派发带任何标签的卡片照常可以，agent 由派发时选的决定。
94. `board new "x" --label 功能 --label UI` 新建的卡片带这两个标签，界面上 2 秒内出现并显示标签；`--label ui` 能匹配到 `UI`；`--label 不存在的标签` 和 `--label <仅人可打的标签>` 报 `USAGE`，白板上没有多出卡片；`--label` 能和 `--inbox`、`--top` 一起用；`--json` 输出里有 `labels`。新建弹窗选了标签后，「等价的 CLI」里出现对应的 `--label`。
95. 「待审核」卡片显示「累计 … · N 次 · 完成于 X 分钟前」，相对时间随时间推移更新，进行中的卡片不显示；评论、编辑描述、移动状态不改完成时间；卡片详情里也能看到，悬停有具体时间；旧数据没有结束时间时不显示这一项。
96. 机器磁贴底部不再出现「只接手动」，只显示机器详情里设置会用到的 agent；机器详情所有设置项修改当帧生效并有过渡动画，保存失败回滚有可见反馈，减弱动效下不播放；启动环境的名称列和路径左端对齐，长路径悬停可看全；「启动环境」「白板与目录」可收起，默认收起，重开保持。
97. 机器详情里用选择组件加定时（不手写），生成的表达式和说明一致（例如选「每周」一、三、五 09:00 生成 `0 9 * * 1,3,5`，胶囊写「每周一、三、五 09:00」）；接口只保存合法的 cron 表达式，`61 * * * *`、`* * *` 被拒绝并提示哪一段不对；`*/5 * * * *` 每 5 分钟开始一轮，`0 9 * * 1-5` 工作日 9 点开始一轮；同一分钟两条都到点只开始一轮；升级前的 `HH:MM` 升级后按原时间继续触发，界面上能看到迁移后的表达式；修改后 `board host` 不重启就生效；机器磁贴的定时摘要和机器详情一致。
98. 规则 `in [claude, UI] → claude`：带 claude 或 UI 的卡片都由 claude 做；`not in [claude] → dsh`：不带 claude 的由 dsh 做，带 claude 的跳过；`equal [claude, UI] → claude`：只有正好带 claude 和 UI 的匹配，只带 claude 的不匹配；多条规则按顺序第一条命中生效；没有兜底时「有 N 张可领取的卡片没有匹配任何规则」按新条件计算；旧的单标签规则升级后等价于 `in [标签]`；规则里选不存在的标签或 agent 被拒绝（`USAGE`），界面标出失效规则；手动派发、`board claim` 不受影响。
99. 白板设置里「保存布局」后拖动状态块，再「应用布局」：状态块回到保存时的位置和宽度；「复原布局」回到默认布局，之后还能「应用布局」；刷新页面、换一台机器打开同一块白板，结果相同；另一块白板的布局不变；保存后删掉一个状态、加一个状态，「应用布局」不报错，新状态按默认规则放栏。
100. 白板设置里关掉「保存顺序」：在「待办」里把第一张拖到第三张下面，松手后回到原位并提示；拖到别的状态照常；刷新后开关仍是关的，另一块白板仍是开的；打开后同一块里拖动排序，刷新后保持新顺序。升级前的白板「保存顺序」都是开的。

## 14. 使用场景（不属于产品功能）

我们用 Board 自动维护开源项目时，会在 Board 之外运行下面这些程序。它们都只通过 CLI 访问白板，用 `board login` 写的配置连接服务端，开始时 `board check` 名字并启动心跳，每条命令带上名字和要操作的白板。

| 程序 | 怎么用 Board |
|---|---|
| issue 监听 | 发现新 issue 后，先用 `board ls --search gh#140` 查有没有卡片；没有就执行 `board new "<标题>" --body "gh#140 …"` |
| 社区监听 | 同上，用帖子链接查重 |
| 定期清理 | 发现需要清理的代码，执行 `board new` |
| 需求拆解 | 把需求拆成卡片，只 `board new`，不修改已有的卡片。一张卡 = 一次复盘 = 集成分支上的一个提交：同类别的小改动（界面、文案、图片）合成一张卡，描述里每项改动一个小节、带自己的验收标准；模块重构，改数据表、服务端接口、CLI 命令、skill 规则，以及其他改动各一张卡。不按前端、后端拆，不按步骤拆，有先后依赖的部分放在同一张卡里 |
| 执行 agent | 会话开始：`board check` 名字，启动后台心跳。循环执行：`board claim` 领卡片 → 在本会话的 worktree 里按描述干活，期间用 `board comment` 记进度 → 改代码的卡片：rebase 到集成分支，在 rebase 之后的代码上跑仓库规定的全部检查，压成一个最后一行是 `卡片：<项目>/<白板>#<ID>` 的提交，直接推到集成分支，推送被拒就重新 rebase、重新检查再推 → 评论改了什么、`提交：<sha>`、`检查：<结果>`，对这张卡片发 final，沿连线移到交审状态（默认工作流里是「待审核」）；做不下去就不推集成分支，把未完成的改动推到 `wip/<白板>/<ID>` 分支，用 `board comment` 写明原因和分支名，发 final，再沿连线把卡片移到需要人处理的状态（默认工作流里是「需人工校验」）。会话结束：停掉心跳，名字离线，删掉自己的 worktree |

代码仓库的 AGENTS.md / CLAUDE.md 写明集成分支（没写就用远端的默认分支）和推送前要跑的检查。不建卡片分支，不设专门的合并节点；每个会话在本机一个 worktree 里一张接一张地做卡片。agent 只按工作流的规则、连线和状态名称里的关键词认出首个可领取状态、交审状态和需要人处理的状态，不依赖具体的状态名。

人在界面上调整「待办」的顺序来决定先做什么。「待审核」里的卡片代码已经在集成分支上，人看卡片动态里的提交号、检查记录和提交本身复盘：没问题拖到「已完成」；有问题拖到「返工」并评论哪几项不对，领到它的 agent 在集成分支上再提交一次修复，不改写已经推上去的提交。「需人工校验」里是 agent 做不下去、等人处理的卡片。发版由人决定。没想清楚的事先记在「未整理」，整理好再放进「待办」。
