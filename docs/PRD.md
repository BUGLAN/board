# Board 产品需求文档

| 项 | 内容 |
|---|---|
| 版本 | v0.5 |
| 日期 | 2026-11-07 |

## 1. 产品定义

Board 是看板式白板。人在界面上操作，agent 通过命令行（CLI）操作，两边读写的是同一块白板。

服务端部署在线上（`https://board.buglan.com`）。人用 GitHub 账号登录，agent 用访问令牌连接。

白板按项目组织：一个项目下有多块白板。

Board 只管两件事：卡片在哪个状态、谁在做。agent 怎么干活、什么时候来领卡片，不归 Board 管。

## 2. 范围

**包含**

- 项目与白板的新建、编辑、删除
- 卡片的新建、编辑、移动、排序、评论、删除
- 「未整理」条目：放在工作流之前、还没整理成卡片的内容
- 每块白板的工作流（状态）可以自定义
- 标签
- agent 领取卡片，以及领取超时后自动释放
- 复制为提示词，以及给 agent 用的 skill（`board-skills`）
- 界面：网页端与桌面端使用同一套界面；手机浏览器可用
- CLI
- 登录：网页端和桌面端用 GitHub 账号登录，只允许一个指定的账号
- agent 访问令牌：在界面上新建、吊销

**不包含**

- agent 本身。任何能执行命令行的 agent 都可以接入。
- 界面里的命令行终端。agent 在自己的环境里运行 CLI。
- 定时任务，以及对 GitHub issue、社区的监听
- 与 GitHub 等外部系统的同步（GitHub 只用于登录）
- 多个账号、团队、成员角色，以及注册

## 3. 身份与白板定位

| 操作方式 | 身份 | 操作哪块白板 |
|---|---|---|
| 界面 | 人：登录的 GitHub 账号（§3.1） | 界面上当前打开的白板。每个窗口可以打开不同的白板 |
| CLI | agent。名字由 `--as <名字>` 或环境变量 `BOARD_AS` 给出，两者都没有时命令被拒绝（`NO_IDENTITY`）。连接服务端时用访问令牌认证（§3.1、§9） | 由 `--board <项目>/<白板>` 或环境变量 `BOARD` 给出，两者都没有时命令被拒绝（`NO_BOARD`） |

- 白板路径写成「项目标识/白板标识」，例如 `oss/release`。
- 项目下只有一块白板时，可以只写项目标识，例如 `site`。项目下有多块白板时只写项目标识，返回 `BOARD_NOT_FOUND`，原因里列出该项目的白板标识。

### 3.1 登录与访问令牌

**登录**

- 服务端只允许一个指定的 GitHub 账号登录（部署时配置）。所有项目和白板都属于这个账号。
- 没有登录时，网页端和桌面端显示登录页，页面上只有「用 GitHub 登录」。用其他 GitHub 账号登录时被拒绝，登录页提示该账号没有权限。
- 登录后 30 天内有效，使用期间自动续期。在「设置 → 账号」里可以退出登录。
- 所有 API，包括实时推送，都需要登录或访问令牌，否则被拒绝（`NOT_LOGGED_IN`）。
- 服务端以本机模式运行时，只接受本机访问，不需要登录。

**访问令牌**

- agent 连接服务端时用访问令牌认证。令牌属于登录的账号。
- 在「设置 → Agent 接入」新建令牌，填写用途（例如 `macbook`）。令牌原文只在新建时显示一次。
- 令牌列表显示用途、令牌开头几位、创建时间、最近使用时间。令牌可以吊销，吊销后使用它的命令被拒绝（`INVALID_TOKEN`）。
- `--as` / `BOARD_AS` 只是 agent 的名字，与令牌无关：同一个令牌可以用不同的名字运行多个 agent。§8 的持有者仍按 agent 名字判断。
- 令牌只能用于 CLI 的命令（§9）。项目、白板、工作流、标签的管理，以及删除卡片、强制释放，只能在登录后的界面上做。

## 4. 项目与白板

**项目**

| 字段 | 说明 |
|---|---|
| 名称 | 必填 |
| 标识 | 必填。小写字母、数字和 `-`，以字母或数字开头，最长 32 个字符；全局唯一；创建后不能修改 |
| 描述 | 选填 |
| 颜色 | 从固定色板里选一种 |
| 标签 | 见 §6 |

**白板**

| 字段 | 说明 |
|---|---|
| 名称 | 必填 |
| 标识 | 必填。格式同项目标识；在所属项目内唯一；创建后不能修改 |
| 描述 | 选填 |

- 一块白板只属于一个项目。
- 新建项目时同时新建它的第一块白板（默认名称「主白板」，标识 `main`）。
- 每块白板相互独立：卡片 ID、工作流、领取、超时都只在本白板内计算。
- 项目和白板只能在界面上新建、编辑、删除。删除前要二次确认；删除项目会删除它的全部白板。整个工作区至少保留一块白板。
- 白板被删除后，指向它的 CLI 命令返回 `BOARD_NOT_FOUND`。

## 5. 卡片

| 字段 | 说明 |
|---|---|
| ID | 每块白板内自增的整数，从 1 开始；界面上显示为 `#1`。「未整理」条目与卡片共用同一套 ID |
| 标题 | 必填 |
| 描述 | 选填，Markdown。验收标准、相关链接都写在这里 |
| 状态 | 「未整理」或工作流里的一个状态（§7） |
| 标签 | 0 个或多个，取自所属项目的标签 |
| 持有者 | 领取这张卡片的 agent 名字，只有锁定状态里的卡片有 |
| 领取到期时间 | 只有被持有的卡片有 |
| 动态 | 评论和系统记录，按时间排列，只能追加 |

- 卡片在状态内有先后顺序，越靠前越优先。
- 卡片被新建、编辑、移动、调整顺序、领取、续期、释放，以及加或去标签时，系统自动在动态里追加一条记录，写明谁、在什么时间、做了什么。

## 6. 标签

| 字段 | 说明 |
|---|---|
| 名称 | 必填；在所属项目内唯一，不区分大小写 |
| 颜色 | 从固定色板里选一种 |

- 标签属于项目，项目下的所有白板共用。
- 人和 agent 都能给卡片加标签、去标签，任何状态的卡片都可以，包括别人持有的卡片（不受 §8 规则 5 限制）。加或去标签不会续期。
- 卡片上的标签显示为块状胶囊（色点 + 名称）。
- 标签的新建、改名、改色、删除在界面上做。删除标签时，它会从项目内所有卡片上移除。
- CLI 引用项目里不存在的标签时，命令被拒绝（`USAGE`），原因里列出可用的标签。

## 7. 工作流

每块白板有自己的工作流：一组有先后顺序的状态。新建白板时默认是 4 个状态：

| 状态 | 标识 | 规则 |
|---|---|---|
| 待办 | `todo` | 领取起点 |
| 进行中 | `doing` | 锁定 |
| 待审核 | `review` | — |
| 已完成 | `done` | 终点 |

| 字段 | 说明 |
|---|---|
| 名称 | 必填；在白板内唯一，不区分大小写；最长 12 个字 |
| 标识 | 系统生成，不能修改。默认的 4 个状态是 `todo`、`doing`、`review`、`done`，新增的状态依次是 `s1`、`s2`… |
| 颜色 | 从固定色板里选一种 |
| 规则 | 三个开关，见下表 |

| 规则 | 含义 | 数量 |
|---|---|---|
| 领取起点 | `board claim` 从这里领取；新建卡片默认放在这里；超时释放、强制释放后卡片回到这里 | 每块白板恰好一个 |
| 锁定 | 只能由 agent 领取进入；卡片被持有期间，只有持有者能编辑和移动 | 0 个或多个 |
| 终点 | 进到这里算完成；只有人能把卡片移入或移出 | 0 个或多个 |

- 工作流只能在界面上修改：新增、改名、改色、调整顺序、切换规则、删除。
- 把另一个状态设为领取起点时，原来的领取起点自动取消。领取起点不能删除。
- 删除状态时，里面的卡片移到领取起点最下面；被持有的卡片同时释放。
- 关闭某个状态的「锁定」时，其中被持有的卡片释放。
- 「未整理」（标识 `inbox`）不属于工作流：每块白板固定都有，不显示在白板的主内容区，agent 不能领取。
- CLI 里用标识或名称指定状态，名称不区分大小写。

## 8. 规则

以下规则都在同一块白板内生效。

1. **领取**：只有领取起点里的卡片能被领取。领取后卡片进入工作流里领取起点之后的第一个锁定状态（之后没有锁定状态时，进入第一个锁定状态）；工作流里没有锁定状态时不能领取。持有者是领取它的 agent，领取到期时间是 30 分钟后。
2. **互斥**：多个 agent 同时领取同一张卡片，只有一个成功。
3. **一个 agent 在一块白板上同时只持有一张卡片。**
4. **进入锁定状态只能靠领取**：人和 agent 都不能把卡片直接移进锁定状态。例外：持有者可以把自己持有的卡片从一个锁定状态移到另一个锁定状态，领取保持不变。
5. **持有者独占**：被持有的卡片只有持有者能编辑和移动，其他人和 agent 只能评论、加或去标签。人可以在界面上「强制释放」。
6. **续期**：持有者对自己的卡片评论、编辑、移动，或再次执行 `board claim <ID>`，领取到期时间都重新算为 30 分钟后。
7. **超时释放**：到了领取到期时间仍未续期，卡片回到领取起点最上面，持有者清空，动态里记一条「领取超时，自动释放」。
8. **离开锁定状态即释放**：持有者把卡片移到不锁定的状态时，持有者和领取到期时间一起清空。人强制释放后，卡片回到领取起点最上面。
9. **终点只归人管**：只有人能把卡片移入或移出终点状态。
10. **删除只能在界面上做。**
11. **「未整理」只在界面上新建。** 人和 agent 都能把卡片移入或移出「未整理」，同样受规则 4、5、9 约束。

**卡片在状态里的位置**

- 新建：领取起点最下面；CLI 带 `--top` 时放在最上面。界面上新建时可以选择放进「未整理」，放在「未整理」最下面。
- 移动：目标状态最下面；CLI 带 `--top` 时放在最上面。界面上拖拽时放在松手的位置。
- 「整理到<领取起点>」：领取起点最下面。
- 超时释放、强制释放：领取起点最上面。

## 9. CLI

所有命令都支持 `--json`，输出 JSON。成功时退出码为 0；被拒绝时退出码为 1，并给出错误码（见 §12）和原因。

**连接方式**

| 方式 | 设置 | 读写哪里 |
|---|---|---|
| 服务端 | `BOARD_URL=<服务端地址>`（例如 `https://board.buglan.com`）和 `BOARD_TOKEN=<访问令牌>` | 通过服务端读写，规则在服务端执行 |
| 本机 | 不设置 `BOARD_URL` | 直接读写本机的数据库（`~/.board/board.db`，`BOARD_DB` 可以指定别的位置） |

- 两种方式的命令、输出、规则和错误码相同。
- 设置了 `BOARD_URL` 但没有 `BOARD_TOKEN` 时，命令被拒绝（`NOT_LOGGED_IN`）；令牌无效或已吊销时被拒绝（`INVALID_TOKEN`）；连不上 `BOARD_URL` 时被拒绝（`UNREACHABLE`）。

除 `board help` 外，所有命令都需要身份（§3）；除 `board help`、`board boards` 外，所有命令都需要白板（§3）。

| 命令 | 作用 |
|---|---|
| `board boards` | 列出所有白板：路径、项目名、白板名、各状态卡片数 |
| `board flow` | 列出当前白板的工作流：顺序、标识、名称、规则、卡片数 |
| `board ls [--column <状态>] [--search <文字>] [--label <标签>]` | 列出卡片：ID、状态、标题、标签、持有者，按工作流顺序和状态内顺序排列。`--search` 在标题和描述里查找；`--label` 只列出带该标签的卡片 |
| `board show <ID>` | 显示卡片的全部字段和动态 |
| `board new "<标题>" [--body "<描述>"] [--top]` | 在领取起点新建卡片 |
| `board edit <ID> [--title "<标题>"] [--body "<描述>"]` | 修改标题或描述 |
| `board move <ID> <状态> [--top]` | 把卡片移到指定状态（标识或名称） |
| `board claim [<ID>]` | 领取。不带 ID 时领取领取起点最上面的卡片。返回卡片的全部字段和动态 |
| `board comment <ID> "<内容>"` | 追加评论 |
| `board label <ID> +<标签> -<标签> …` | 加标签（`+` 或不带前缀）、去标签（`-`），可以一次写多个 |
| `board labels` | 列出白板所属项目的标签，以及每个标签被多少张卡片使用 |

## 10. 界面

### 10.1 整体布局

- **顶栏**：品牌、项目 / 白板切换器、搜索（命令面板入口）、当前白板上正在工作的 agent（头像外圈显示剩余领取时间）。
- **左侧操作台**：活动栏 + 侧栏。活动栏从上到下四个 Tab：白板、项目、未整理、设置。再次点击当前 Tab 收起或展开侧栏，每个 Tab 分别记住展开或收起；侧栏宽度可以拖动调整。
- **主内容区**：在右侧，显示当前白板、项目画布或设置页。
- 活动栏图标上不显示数量徽标。
- 手机上，活动栏变为底部 Tab 栏；白板各状态左右滑动切换，顶部有状态切换条；「项目」「未整理」Tab 占满内容区，显示对应的列表。
- 桌面端：打开线上的 Board（`https://board.buglan.com`），登录方式与网页端相同；顶栏同时是窗口标题栏，可以拖动窗口。
- 主题：跟随系统 / 浅色 / 深色。

### 10.2 项目 / 白板切换器（顶栏）

- 显示「项目名 / 白板名」。点击后列出所有白板，按项目分组，每块白板显示正在工作的 agent 数和领取起点里的卡片数；可以搜索，回车切换。
- 其他白板上有 agent 正在工作时，切换器上有提示点。
- 底部有「新建白板」「项目总览」入口。

### 10.3 白板 Tab

- 侧栏：
  - 筛选框：按标题、描述、`#ID`、agent 名字、标签名筛选，不匹配的卡片淡出；输入 `label:<标签>` 只按标签筛选。
  - 「标签」：项目的全部标签块状排列，每个标签显示它在当前白板上的卡片数。点击标签即按该标签筛选，再点一次取消；整块区域就是输入框：点空白处出现光标，输入名称后回车即新建标签。改名、改色、删除标签在命令面板和项目菜单的「管理标签」里。
  - 「正在工作」：当前白板上持有卡片的 agent、卡片和剩余领取时间。
  - 「最近动态」：当前白板最近的记录。
- 主内容区：页头显示「项目名 › 白板名」和「新建卡片」按钮。下面依次是工作流条和状态块。
- 工作流条：按顺序列出工作流的状态，每个状态显示卡片数，以及领取起点、锁定、终点的标记。
  - 拖动状态调整顺序；末尾的「+ 添加状态」输入名称后回车即新增（加在最后）。
  - 点击状态打开设置：名称、颜色、三个规则开关、删除（要二次确认，并写明卡片会移到哪里）。
- 状态块：每个状态是一个块，块的高度随卡片数量变化，标题旁显示顺序号、卡片数和规则说明。
  - 拖动块的标题摆放位置：块吸附到 12 栏网格上，并向上贴紧上方的块，块之间不留空隙；拖动块的右边缘调整宽度（按网格吸附）。块变宽后，块里的卡片排成多列。
  - 默认布局：各状态并排，每块占 3 栏。新增的状态放在当前最矮的那一栏下面。
  - 布局按白板保存在数据库里，并同步到所有窗口；工作流条末尾有「复原布局」，回到默认布局。
- 卡片显示 ID、标题、评论数、标签；被持有的卡片还显示持有者和剩余的领取时间。领取起点的第一张卡片标为「下一张」。终点状态里的卡片只占一行，标题划掉。
- 拖拽卡片可以调整状态内顺序或换状态，拖动时显示插入位置。拖到不允许的状态时，该块显示禁止原因；松手后卡片回到原位，并提示原因。
- 通过 CLI 或其他窗口做的修改，已打开的界面在 2 秒内显示出来，不需要刷新页面，被改动的卡片会短暂高亮并标出是谁做的。

### 10.4 项目 Tab

- 侧栏：项目 → 白板的树。每个项目显示白板数和正在工作的 agent 数；每块白板显示正在工作的 agent 数和领取起点里的卡片数。点击白板即打开它（切到白板 Tab）。
  - 项目行的菜单：新建白板、编辑项目、管理标签、改颜色、删除项目。
  - 白板行的菜单：打开、编辑白板、复制为提示词、复制 `BOARD=<路径>`、删除白板。
  - 画布上的节点有同样的菜单。
- 主内容区：无限画布。
  - 每个项目是一个节点，用连线连到它的各块白板节点。
  - 白板节点显示名称、路径、各状态卡片数、正在工作的 agent，以及「打开」按钮。有 agent 在工作的白板，连线显示为流动状态。
  - 拖动空白处平移；`⌘` / `Ctrl` + 滚轮或双指捏合缩放；有放大、缩小、100%、适应画布、定位到当前白板按钮。
  - 拖动节点调整位置，位置会保存并在所有窗口同步。
  - 双击白板节点打开该白板；双击空白处新建项目；点项目节点右侧的「+」在该项目下新建白板。
- 新建项目：填名称、标识（根据名称自动生成，可修改）、描述、颜色、第一块白板的名称和标识。
- 新建白板：选所属项目，填名称、标识（自动生成，可修改）、描述。

### 10.5 未整理 Tab

- 侧栏：顶部是「记一条未整理」入口，下面是当前白板的未整理条目，侧栏标题旁显示条目数。条目显示 ID、标题、描述的第一行、标签、创建时间。
- 条目可以拖到右侧白板的状态块里，也可以点「整理到<领取起点>」。
- 主内容区仍然显示当前白板。

### 10.6 设置 Tab

- 侧栏：设置目录，点击跳到对应部分。
- 主内容区：
  - 外观：主题、卡片密度（舒适 / 紧凑）、动效（完整 / 减弱）
  - 白板规则：工作流与三个规则开关的说明，以及 §8 的规则摘要
  - Agent 接入：`board-skills` 的用法（§10.9）与安装（可复制 SKILL.md）、`board` 命令行的安装、连接服务端的设置（`BOARD_URL`、`BOARD_TOKEN`）、访问令牌（新建、列表、吊销，§3.1）、错误码
  - 账号：当前登录的 GitHub 账号（头像、名字、账号名）与「退出登录」；本机模式下显示不需要登录
  - 快捷键

### 10.7 新建（居中弹窗）

- 白板 Tab 的「新建卡片」入口和未整理 Tab 的「记一条未整理」入口都打开同一个居中弹窗。弹窗大小与卡片详情相同。
- 左侧：标题（必填）、描述（Markdown，可以切换编辑 / 预览，可以插入验收标准模板）。
- 右侧：「放到」领取起点或未整理（从未整理入口打开时默认未整理）、标签、等价的 CLI 命令、「连续新建」开关。
- 标题里按 `↵` 创建；`⌘ ↵` / `Ctrl ↵` 在任何位置创建；`⇧ ↵` 跳到描述。标题为空时不能创建，并提示原因。
- 「连续新建」打开时，创建后清空标题和描述、保留标签，继续录入下一条，并列出本次已创建的卡片。
- 关闭弹窗时，未提交的内容保留为草稿，下次打开自动恢复，并可以一键清空。

### 10.8 卡片详情（居中弹窗）

- 点击卡片打开详情。弹窗居中，固定宽 920px、高 640px，窗口不够大时按窗口缩小；手机上从底部弹出，可以下拉关闭。
- 顶部：卡片 ID、所在状态、同状态内「上一张 / 下一张」及位置、「复制为提示词」、关闭。
- 左栏：
  - 标题、创建者和时间、标签（可以加或去）；
  - 被持有的卡片显示持有者和剩余领取时间，并有「强制释放」按钮，标题和描述只读；
  - 「未整理」的条目有「整理到<领取起点>」按钮；
  - 描述（编辑 / 预览）；
  - 「删除」按钮，删除前要二次确认。
- 右栏：动态（默认显示到最新一条）和评论框。

### 10.9 复制为提示词

- agent 通过 skill 接入：`board-skills` 写明身份与白板的设置方法、处理卡片的步骤（领取 → 按描述和验收标准干活、用评论记进度 → 交审；做不下去时评论原因并放回领取起点）、整理「未整理」条目的方法、§8 的规则和 §12 的错误码。skill 随项目提供（`skills/board-skills/SKILL.md`）。
- 复制为提示词只复制一行 skill 调用，卡片的标题、描述、动态由 agent 用 CLI 自己读取：
  - 卡片：`/board-skills <项目>/<白板>#<ID>`。卡片详情的「复制为提示词」按钮和 `C` 键复制这一行。
  - 白板：`/board-skills <项目>/<白板>`，agent 循环领取领取起点最上面的卡片，直到 `EMPTY_TODO`。项目树和画布上白板的菜单里有这一项。
- skill 的参数也可以是一句话需求：agent 先用 `board new` 记到领取起点，再按卡片处理。
- 复制后提示已复制的内容。

### 10.11 登录页

- 没有登录时显示：Board 标识、一句说明、「用 GitHub 登录」按钮。
- 点按钮跳到 GitHub 授权，授权后回到 Board 并打开白板。
- 登录失败时在按钮上方显示原因：账号没有权限、登录已过期、取消了授权、无法从 GitHub 取得账号信息。
- 使用中登录失效（过期、在别处退出）时，界面回到登录页。

## 11. 实时同步

- 多个窗口、CLI 读写的是同一份数据。任一处的修改，其他已打开的界面在 2 秒内显示出来。
- 实时推送只发给已登录的界面（§3.1）。
- 项目画布上节点位置、工作流和状态块布局的修改也同步到所有窗口。

## 12. 错误码

| 错误码 | 出现时机 |
|---|---|
| `NO_IDENTITY` | CLI 没有提供 agent 名字 |
| `NO_BOARD` | CLI 没有指定白板 |
| `BOARD_NOT_FOUND` | 指定的项目或白板不存在；或项目下有多块白板却只写了项目标识 |
| `NOT_FOUND` | 卡片不存在 |
| `EMPTY_TITLE` | 新建或编辑时标题为空 |
| `EMPTY_TODO` | 不带 ID 领取时领取起点为空 |
| `NOT_IN_TODO` | 带 ID 领取的卡片不在领取起点，且不是自己持有的卡片 |
| `ALREADY_HOLDING` | 该 agent 在这块白板上已经持有另一张卡片 |
| `NOT_HOLDER` | 编辑或移动被持有卡片的不是持有者 |
| `FORBIDDEN_COLUMN` | 把卡片直接移进锁定状态；agent 把卡片移入、移出终点状态；工作流里没有锁定状态时领取 |
| `USAGE` | 命令格式或参数不正确：未知的命令、未知的状态、项目里不存在的标签、缺少必需的参数、评论内容为空 |
| `NOT_LOGGED_IN` | 没有登录：界面没有登录会话；CLI 设置了 `BOARD_URL` 却没有 `BOARD_TOKEN`；用访问令牌做只能在界面上做的操作 |
| `INVALID_TOKEN` | 访问令牌不存在或已吊销 |
| `UNREACHABLE` | CLI 连不上 `BOARD_URL` 指定的服务端 |

## 13. 验收标准

1–11 在同一块白板上执行，CLI 已设置 `BOARD_AS` 和 `BOARD`；服务端和本机两种连接方式（§9）结果相同。

1. 「待办」从上到下是 #1、#2。α 执行 `board claim`，得到 #1；#1 进入「进行中」，持有者是 α。
2. 「待办」里只有 #1。α 和 β 同时执行 `board claim 1`：一个成功，另一个得到 `NOT_IN_TODO`。
3. α 持有 #1，再执行 `board claim`，得到 `ALREADY_HOLDING`。
4. α 持有 #1。β 执行 `board edit 1 --title x`，得到 `NOT_HOLDER`；β 执行 `board comment 1 "…"`，成功。
5. α 在 10:00 领取 #1，10:20 评论一次，领取到期时间变为 10:50。
6. α 在 10:00 领取 #1 后没有任何操作。10:30 时 #1 回到「待办」最上面，持有者为空，动态里有「领取超时，自动释放」。β 随后领取 #1；α 再执行 `board move 1 review`，得到 `NOT_HOLDER`。
7. α 持有 #1，执行 `board move 1 done`，得到 `FORBIDDEN_COLUMN`；执行 `board move 1 review` 成功，持有者清空。人把 #1 拖到「已完成」，成功。
8. 人把「待办」里的卡片拖进「进行中」：卡片回到原位，并显示原因。agent 执行 `board move 2 doing`，得到 `FORBIDDEN_COLUMN`。
9. 人对 α 持有的 #1 点「强制释放」：#1 回到「待办」最上面，持有者为空；α 之后执行 `board claim`，不会得到 `ALREADY_HOLDING`。
10. 执行 `board new "x"` 后，已打开的界面在 2 秒内出现卡片 x，不需要刷新。
11. 任一命令加 `--json`，都输出合法 JSON；被拒绝时退出码为 1，JSON 里带错误码。

项目与白板：

12. 没有 `--board` 也没有 `BOARD` 时执行 `board ls`，得到 `NO_BOARD`。
13. 项目 `oss` 下有白板 `main` 和 `release`：`--board oss` 得到 `BOARD_NOT_FOUND`，原因里列出 `main`、`release`；`--board oss/nope` 得到 `BOARD_NOT_FOUND`。项目 `site` 下只有白板 `launch`：`--board site` 等同于 `--board site/launch`。
14. 在新建的白板上执行 `board new "x"`，得到 #1。
15. α 在 `oss/main` 持有一张卡片，在 `oss/release` 执行 `board claim`，成功。
16. 在 `oss/main` 执行 `board new "x"`，正在看 `oss/release` 的界面不出现卡片 x。
17. 人在界面上删除白板 `oss/release` 后，agent 以 `BOARD=oss/release` 执行任一命令，得到 `BOARD_NOT_FOUND`。
18. `board boards` 列出所有白板的路径。

未整理：

19. 人在界面上新建一条放进「未整理」的条目 #5。「待办」为空时 agent 执行 `board claim`，得到 `EMPTY_TODO`；执行 `board claim 5`，得到 `NOT_IN_TODO`。
20. 人对 #5 点「整理到待办」，#5 出现在「待办」最下面。
21. 人把「未整理」里的条目拖到「进行中」：条目回到原位，并显示原因。

标签：

22. α 持有 #1。β 执行 `board label 1 +bug`，成功，#1 的动态里有一条加标签的记录，领取到期时间不变。
23. 执行 `board label 1 +不存在的标签`，得到 `USAGE`。
24. `board ls --label bug` 只列出带 bug 标签的卡片。
25. 人在界面上删除标签 bug 后，项目内所有卡片上都没有 bug 标签。

工作流：

26. 人在 `oss/main` 新增状态「设计中」（标识 `s1`）并拖到「待办」之后。agent 执行 `board move 2 设计中` 和 `board move 3 s1` 都成功；`board flow` 按顺序列出 待办、设计中、进行中、待审核、已完成。
27. 人把「待审核」设为领取起点：「待办」的领取起点标记消失；agent 执行 `board claim`，领到「待审核」最上面的卡片，卡片进入「待审核」之后的第一个锁定状态；没有时进入「进行中」。
28. 人新增状态「测试中」并打开「锁定」。α 持有 #1（在「进行中」），执行 `board move 1 测试中` 成功，持有者仍是 α；人把另一张卡片拖进「测试中」，被拒绝并显示原因。
29. 人删除状态「设计中」：里面的卡片出现在领取起点最下面。
30. 人在一个窗口里拖动状态块或改工作流，另一个打开同一块白板的窗口在 2 秒内显示同样的布局。

复制为提示词：

31. 在卡片 #3 的详情里点「复制为提示词」，剪贴板里是 `/board-skills <当前白板路径>#3`。把这一行发给装了 `board-skills` 的 agent，agent 领取 #3、完成后移到「待审核」，期间不需要人补充其他信息。

登录与访问令牌：

32. 没有登录时打开网页端或桌面端，显示登录页。不带登录会话和令牌请求任一 API（包括 `/api/stream`），返回 `NOT_LOGGED_IN`。
33. 用指定的 GitHub 账号登录，进入白板。用其他 GitHub 账号登录，停留在登录页，并提示该账号没有权限。
34. 在「设置 → 账号」退出登录后，界面回到登录页；退出前的会话再请求 API，返回 `NOT_LOGGED_IN`。
35. 在「设置 → Agent 接入」新建令牌，原文只显示这一次。agent 设置 `BOARD_URL` 和 `BOARD_TOKEN` 后执行 `board claim`，成功，持有者是 `BOARD_AS` 的名字；已打开的界面在 2 秒内显示。
36. 设置了 `BOARD_URL` 没有 `BOARD_TOKEN`，得到 `NOT_LOGGED_IN`；令牌写错或已吊销，得到 `INVALID_TOKEN`；`BOARD_URL` 连不上，得到 `UNREACHABLE`。退出码都是 1。
37. 用访问令牌新建项目、删除白板、修改工作流，得到 `NOT_LOGGED_IN`。
38. 同一份数据上，服务端方式和本机方式执行同一条命令，`--json` 输出相同。

## 14. 使用场景（不属于产品功能）

我们用 Board 自动维护开源项目时，会在 Board 之外运行下面这些程序。它们都只通过 CLI 访问白板，用 `BOARD_URL` 和 `BOARD_TOKEN` 连接服务端，并通过 `BOARD` 指定要操作的白板。

| 程序 | 怎么用 Board |
|---|---|
| issue 监听 | 发现新 issue 后，先用 `board ls --search gh#140` 查有没有卡片；没有就执行 `board new "<标题>" --body "gh#140 …"` |
| 社区监听 | 同上，用帖子链接查重 |
| 定期清理 | 发现需要清理的代码，执行 `board new` |
| 执行 agent | 循环执行：`board claim` 领卡片 → 按描述干活，期间用 `board comment` 记进度（同时续期）→ 做完执行 `board move <ID> review`；做不下去就先用 `board comment` 写明原因，再执行 `board move <ID> todo`（白板的工作流不是默认的四个状态时，先用 `board flow` 查看） |

人在界面上调整「待办」的顺序来决定先做什么，在「待审核」里检查结果，确认后拖到「已完成」。没想清楚的事先记在「未整理」，整理好再放进「待办」。
