# Board 产品需求文档

| 项 | 内容 |
|---|---|
| 版本 | v0.16 |
| 日期 | 2026-11-12 |

## 1. 产品定义

Board 是看板式白板。人在界面上操作，agent 通过命令行（CLI）操作，两边读写的是同一块白板。

服务端部署在线上（例如 `https://board.example.com`）。人用 GitHub 账号登录，agent 用访问令牌连接。

白板按项目组织：一个项目下有多块白板。

Board 只管两件事：卡片在哪个状态、谁在做。agent 怎么干活不归 Board 管。每台干活的机器上可以常驻一个 `board host`：人把卡片派给某台机器，或者机器到了设定的时间自己领卡，`board host` 在本机启动已经装好的 agent（§9.1）。

## 2. 范围

**包含**

- 项目与白板的新建、编辑、删除
- 卡片的新建、编辑、移动、排序、评论、删除
- 卡片附件：图片和常见文件
- 「未整理」条目：放在工作流之前、还没整理成卡片的内容
- 每块白板的工作流（状态和连线）可以自定义
- 标签
- agent 名字的查重与在线状态；agent 领取卡片、发心跳，以及心跳中断后自动释放
- 复制为提示词，以及给 agent 用的 skill（`board-skills`）
- 界面：网页端与桌面端使用同一套界面；手机浏览器可用
- CLI
- 登录：网页端和桌面端用 GitHub 账号登录，只允许一个指定的账号
- agent 访问令牌：在界面上新建、吊销
- 任务下发（§9.1）：机器（`board host`）、手动派发、定时领取

**不包含**

- agent 本身。任何能执行命令行的 agent 都可以接入；`board host` 只启动本机已经装好的 agent。
- 界面里的命令行终端。agent 在自己的环境里运行 CLI。
- 对 GitHub issue、社区的监听
- 与 GitHub 等外部系统的同步（GitHub 只用于登录）
- 多个账号、团队、成员角色，以及注册

## 3. 身份与白板定位

| 操作方式 | 身份 | 操作哪块白板 |
|---|---|---|
| 界面 | 人：登录的 GitHub 账号（§3.1） | 界面上当前打开的白板。每个窗口可以打开不同的白板 |
| CLI | agent。名字由 `--as <名字>` 或环境变量 `BOARD_AS` 给出，两者都没有时命令被拒绝（`NO_IDENTITY`）；会话开始时先 `board check` 占用名字（§3.2）。连接服务端时用访问令牌认证（§3.1、§9） | 由 `--board <项目>/<白板>` 或环境变量 `BOARD` 给出，两者都没有时命令被拒绝（`NO_BOARD`） |

- 白板路径写成「项目标识/白板标识」，例如 `oss/release`。
- 项目下只有一块白板时，可以只写项目标识，例如 `site`。项目下有多块白板时只写项目标识，返回 `BOARD_NOT_FOUND`，原因里列出该项目的白板标识。

### 3.1 登录与访问令牌

**登录**

- 服务端只允许一个指定的 GitHub 账号登录（部署时配置）。所有项目和白板都属于这个账号。
- 没有登录时，网页端和桌面端显示登录页，页面上只有「用 GitHub 登录」。用其他 GitHub 账号登录时被拒绝，登录页提示该账号没有权限。
- 登录后 30 天内有效，使用期间自动续期。在「设置 → 账号」里可以退出登录。
- 所有 API，包括实时推送，都需要登录或访问令牌，否则被拒绝（`NOT_LOGGED_IN`）。
- 服务端以本机模式运行时，只接受本机访问，不需要登录。

**访问令牌**

- agent 连接服务端时用访问令牌认证。令牌属于登录的账号。
- 在「设置 → Agent 接入」新建令牌，填写用途（例如 `macbook`）。令牌原文只在新建时显示一次。
- 令牌列表显示用途、令牌开头几位、创建时间、最近使用时间。令牌可以吊销，吊销后使用它的命令被拒绝（`INVALID_TOKEN`）。
- `--as` / `BOARD_AS` 是 agent 的名字，与令牌无关：同一个令牌可以用不同的名字运行多个 agent。§8 的持有者仍按 agent 名字判断。
- 令牌只能用于 CLI 的命令（§9）和 agent 接口：check、心跳、在线列表（§3.2）；`board host` 的上报、开始与结束派发、上传日志、订阅实时推送，以及创建、取消派发（§9.1）。项目、白板、工作流、标签的管理，机器的设置与移除，以及删除卡片、强制释放，只能在登录后的界面上做。

### 3.2 agent 名字

**格式**：`<运行环境>/<模型>`，需要时加 `-<后缀>`。

- 两段都只能用小写字母、数字、`.`、`-`，并以字母或数字开头；只有一个 `/`，总长不超过 48 个字符。
- 例子：`claude/opus-5.5`、`dsh/deepseek-v4.1-flash`、`claude/opus-5.5-login`。
- 格式不对时 `board check` 报 `USAGE`，原因里给出格式说明。

**名字由 agent 自己生成**：运行环境用 claude、codex 这类名称；模型名转成小写，空格换成 `-`；本机已有同名会话时，加一个和本会话相关的后缀，例如任务名或分支名。

**board host 生成的名字**：`<agent 标识>-<机器名>/<模型名>`，例如 `dsh-win/deepseek-v4.1-flash`。模型名来自这台机器上这个 agent 实际配的模型（`~/.board/config.toml` 的 `[agents.<标识>] model`，内置模板有默认值，见 §9.1；没有时用 agent 标识）。不带序号的这个名字空闲时直接用；同一台机器同一 agent、模型有多个并发派发时模型名后面加 `-<序号>`（例如 `dsh-win/deepseek-v4.1-flash-2`、`dsh-win/deepseek-v4.1-flash-3`），只有在线的名字算占用，上一个会话离线后名字可以复用。`board host` 以这个名字 check、领取卡片、发心跳，再启动 agent（§9.1）。

**check**：`board check --as <名字>`。

- 名字正被在线 agent 使用时报 `NAME_TAKEN`，`detail` 里带上名字。
- 否则把名字标为在线，心跳时间记为当前时间，然后返回。
- 查重和占用是一个原子操作：同时 check 同一个名字，只有一个成功。
- 会话标识：`board` 在 check 时向服务端要一个随机的会话标识，服务端记下名字现在属于这个会话，只在这次返回里给出。`board` 把「名字、会话标识、check 它的 agent 进程（从 board 往上找第一个不是 shell 的祖先进程）」记在本机的状态文件里（`<临时目录>/board-heartbeat/<名字>.json`），之后的 agent 级心跳和 `board beat --final` 都带上这个标识。旧版 `board` check 时不要标识，名字没有标识。
- `board host` 开始派发时生成的名字记为属于这台 host。

**会话标识的规则**（防止同名会话互相干扰）：

- 名字在线、有会话标识时，agent 级心跳和 `--final` 带的标识和记录的一致才接受；不一致或没带时拒绝（`NAME_TAKEN`，原因写「这个名字现在属于另一个会话」），名字的状态不变。
- 属于 `board host` 的名字只有 `board host` 能发 agent 级心跳、让它离线：派发会话里的 agent 自己执行 `board heartbeat stop`，名字不离线，派发不受影响。反过来的方向也不放开：`board host` 级的心跳和 `--final` 只对这个规则生成的名字有效，不能用来给 `NameOwner::Session`（新版 CLI check 的）或别的机器派发的名字发心跳、让它离线（`NAME_TAKEN`，原因写「board host 只能给自己派发生成的名字发心跳、让它离线」）。
- 没有标识的名字（旧版 `board` check 的）规则和以前一样。卡片级心跳（`board beat <ID>`）不看标识。
- 本机保护：`board heartbeat start`、`board heartbeat stop`、不带 ID 的 `board beat` 只在 check 这个名字的 agent 进程里生效。名字是本机另一个还在运行的 agent 进程 check 的时候拒绝（`NAME_TAKEN`，写明是哪个进程），不停它的后台心跳、不顶掉它、不发 final；那个进程已经不在了才接管。`--force` 只放开本机这一层，服务端的校验照旧。
- 其他带名字的命令：调用它的 agent 进程不是 check 这个名字的那个、而那个进程还在运行时，照常执行，但在输出里加一行提醒（`--json` 里加 `warning` 字段），说明可能用了别人的名字。

**在线**：名字最近一次心跳在 50 秒以内（每 10 秒一次，连续 5 次没收到算离线）。`board beat --final`（不带 ID）让名字立刻离线。离线后，同一个名字可以被任何会话重新 check，原会话也可以。

**名字表**：服务端记录名字、首次 check 时间、最近心跳时间、令牌 ID、现在属于哪个会话（会话标识或 `board host`）。表只增不删。

**严格模式**：带令牌的卡片命令（`POST /api/cmd`）和上传附件（`POST /api/files`）里的名字必须在线，否则报 `NAME_OFFLINE`。读接口不检查名字。

## 4. 项目与白板

**项目**

| 字段 | 说明 |
|---|---|
| 名称 | 必填 |
| 标识 | 必填。小写字母、数字和 `-`，以字母或数字开头，最长 32 个字符；全局唯一；创建后不能修改 |
| 描述 | 选填 |
| 颜色 | 从固定色板里选一种 |
| 标签 | 见 §6 |

**白板**

| 字段 | 说明 |
|---|---|
| 名称 | 必填 |
| 标识 | 必填。格式同项目标识；在所属项目内唯一；创建后不能修改 |
| 描述 | 选填，一句话 |
| 说明 | 选填。Markdown，不限行数，可以粘贴图片；显示在大盘的总览里（§10.13） |
| 环境检查 | 选填。一行命令（例如 `cargo --version && node --version`），可以给 Windows 单独写一行；机器先在这块白板的目录里跑通它，才接这块白板的卡（§9.1「环境检查」）。不写时不检查 |
| 仓库地址 | 选填。这块白板对应的 git 远端地址，例如 `git@github.com:o/r.git`、`https://github.com/o/r.git`。设了之后描述和评论里的「提交：<sha>」和 `gh#123` 变成指向仓库网页的链接（GitHub、GitLab、Gitea 的常见写法；推不出网页地址时不加链接，代码块里的不处理），给新机器克隆仓库时也优先用它（§9.1「白板与目录」）。别的机器上报过这块白板目录的 `origin` 时，编辑框里把它作为建议 |
| 集成分支 | 选填。agent 推送的目标分支。留空时按原来的规则：读仓库的 AGENTS.md / CLAUDE.md，没写就用远端的默认分支 |

- 仓库地址、集成分支只有人能在界面上的「编辑白板」和白板设置里改；用访问令牌改被拒绝（`NOT_LOGGED_IN`）。

- 一块白板只属于一个项目。
- 新建项目时同时新建它的第一块白板（默认名称「主白板」，标识 `main`）。
- 每块白板相互独立：卡片 ID、工作流、领取、心跳都只在本白板内计算。
- 项目和白板只能在界面上新建、编辑、删除。删除前要二次确认；删除项目会删除它的全部白板。整个工作区至少保留一块白板。
- 白板被删除后，指向它的 CLI 命令返回 `BOARD_NOT_FOUND`。

## 5. 卡片

| 字段 | 说明 |
|---|---|
| ID | 每块白板内自增的整数，从 1 开始；界面上显示为 `#1`。「未整理」条目与卡片共用同一套 ID |
| 标题 | 必填 |
| 描述 | 选填，Markdown。验收标准、相关链接都写在这里 |
| 状态 | 「未整理」或工作流里的一个状态（§7） |
| 标签 | 0 个或多个，取自所属项目的标签 |
| 持有者 | 领取这张卡片的 agent 名字，只有锁定状态里的卡片有 |
| 耗时 | 每一次领取的耗时（第一次心跳到结束），以及累计耗时、做过几次、其中几次异常退出 |
| 完成时间 | 最近一次领取结束的时间（final、心跳中断、释放都算）；评论、编辑、移动不改它；没有结束过的领取时为空 |
| 动态 | 评论和系统记录，按时间排列；人可以在界面上原地修改或删除自己发的评论（修改后显示「已编辑」和修改时间），agent 的评论和系统记录不能修改、不能删除 |
| 附件 | 0 个或多个文件：图片（PNG、JPEG、GIF、WebP）和常见文件（PDF、TXT、Markdown、日志、JSON、CSV、ZIP），单个不超过 10 MB |

- 卡片在状态内有先后顺序，越靠前越优先。
- 附件：
  - 在描述和评论里插入：图片直接显示，点击放大；其他文件显示为下载链接。
  - 人在界面上的描述框、新建弹窗的描述框和评论框里粘贴截图、拖入文件或点「附件」按钮上传；agent 用 `board attach` 上传（§9）。
  - 读取附件需要登录或访问令牌。
  - 删除卡片时附件跟着卡片进回收站；永久删除（在回收站里删掉，或删除超过 30 天被自动清理）时附件一起删除；备份包含附件。
- 卡片被新建、编辑、移动、调整顺序、领取、开始或结束心跳、释放，以及加或去标签、删除、从回收站恢复时，系统自动在动态里追加一条记录，写明谁、在什么时间、做了什么。
- 删除的卡片先进回收站（§8 规则 10）：从白板、`board ls`、搜索、大盘里消失，编号不再复用；动态、评论、附件都还在，30 天内可以恢复。永久删除时附件一起删除；备份包含回收站里的卡片和附件。

## 6. 标签

| 字段 | 说明 |
|---|---|
| 名称 | 必填；在所属项目内唯一，不区分大小写 |
| 颜色 | 从固定色板里选一种 |
| 类型 | agent 可打（默认）：人和 agent 都能给卡片加、去；仅人可打：只有人能在界面上给卡片加、去 |
| 优先 | 开关，默认关。开着时，不带 ID 领取（和定时领取）时带这个标签的卡片先被领取（§8 规则 1）；卡片在状态里的位置不变 |

- 标签属于项目，项目下的所有白板共用。
- 人能给卡片加标签、去标签，任何状态的卡片都可以，包括别人持有的卡片（不受 §8 规则 5 限制）；agent 同样可以，但只能加、去「agent 可打」的标签。
- agent 加、去「仅人可打」的标签（`board label`，或 `board new --label` 新建时带上）被拒绝（`USAGE`），原因里写明这个标签只有人能打，不新建卡片。
- 卡片上的标签显示为块状胶囊；「仅人可打」的标签在名称前带一把小锁，「优先」的标签在名称前带一个闪电，悬停提示「优先：带这个标签的卡片先被领取」。
- 标签的新建、改名、改色、改类型、开关「优先」、删除在界面上做（「管理标签」）。删除标签时，它会从项目内所有卡片上移除。
- 升级前已有的标签都是「agent 可打」，都不是「优先」。
- CLI 引用项目里不存在的标签时，命令被拒绝（`USAGE`），原因里列出可用的标签。

## 7. 工作流

每块白板有自己的工作流：一组有先后顺序的状态，以及状态之间的连线。连线 A → B 表示 agent 可以把卡片从 A 移到 B（§8 规则 12）；人移动卡片不受连线限制。

新建白板时默认是 6 个状态：

| 状态 | 标识 | 规则 | 连线（可以去往） |
|---|---|---|---|
| 待办 | `todo` | 可领取 | 进行中 |
| 进行中 | `doing` | 锁定 | 待审核、需人工校验 |
| 待审核 | `review` | — | 已完成、返工 |
| 已完成 | `done` | 终点 | — |
| 返工 | `rework` | 可领取 | 进行中 |
| 需人工校验 | `check` | — | 待办 |

| 字段 | 说明 |
|---|---|
| 名称 | 必填；在白板内唯一，不区分大小写；最长 12 个字 |
| 标识 | 系统生成，不能修改。默认的 6 个状态见上表，新增的状态依次是 `s1`、`s2`… |
| 颜色 | 从固定色板里选一种 |
| 规则 | 四个开关，见下表 |
| 卡片形态 | 状态块里的卡片怎么显示：卡片、单行、磁贴三选一（§10.3），只影响界面显示。没有设置过时，终点状态用磁贴，其他状态用卡片 |
| 连线 | 从这个状态出发、可以去往的状态，0 个或多个 |

| 规则 | 含义 | 数量 |
|---|---|---|
| 可领取 | `board claim` 从这里领取，领取后卡片沿连线进入锁定状态（§8 规则 1） | 1 个或多个 |
| 锁定 | 只能由 agent 领取进入；卡片被持有期间，只有持有者能编辑和移动 | 0 个或多个 |
| 终点 | 进到这里算完成；只有人能把卡片移入或移出 | 0 个或多个 |
| 错误节点 | agent 异常退出、做不下去时沿连线移到这里（§9.1 派发结束、`board-skills`）；agent 能沿连线移入，只有人能移出。不可领取，配了定时领取也不会被下一轮重新领走 | 0 个或多个 |

- 状态的顺序决定：工作流条上的排列；不带 ID 领取时先领哪个可领取状态；新建卡片放在哪里。
- **首个可领取状态**：按顺序排在最前面的可领取状态。新建卡片（未指定「未整理」时）、「整理到…」都放进这里。
- 工作流只能在界面上修改：新增、改名、改色、选卡片形态、调整顺序、切换规则、连线、删除。
- 至少要有一个可领取状态：最后一个可领取状态不能关闭「可领取」，也不能删除。
- 可领取状态没有连到任何锁定状态时，不能从这里领取；工作流条上这个状态显示提示。
- 删除状态时，里面的卡片移到首个可领取状态最下面，被持有的卡片同时释放；与它相关的连线一起删除。
- 关闭某个状态的「锁定」时，其中被持有的卡片释放。
- 「错误节点」和可领取、锁定、终点互斥：打开「错误节点」时这三个开关一起关掉（最后一个可领取状态不能打开），打开这三个之一时「错误节点」关掉。错误节点只看这个开关，不看状态名称；默认工作流没有错误节点，按需新增一个状态并打开它，再从锁定状态连过去。
- 「未整理」（标识 `inbox`）不属于工作流，没有连线：每块白板固定都有，不显示在白板的主内容区，agent 不能领取，也不能把已有卡片移入或移出；界面或 agent/CLI（`board new --inbox`）都可以新建「未整理」条目。
- CLI 里用标识或名称指定状态，名称不区分大小写。
- 升级前已有的白板：原来的领取起点变为可领取，按原来的顺序给相邻的状态依次连线（第 1 个 → 第 2 个 → …），其余在界面上调整。

## 8. 规则

以下规则都在同一块白板内生效。

1. **领取**：只有可领取状态里的卡片能被领取。领取后卡片沿连线进入锁定状态：这个可领取状态连向的锁定状态里，按顺序排在最前面的一个；没有连到锁定状态时不能从这里领取。不带 ID 领取时，在连到锁定状态的可领取状态里（按工作流顺序，状态内从上到下）挑：有带「优先」标签（§6）的卡片就领排在最前面的那张，没有就领最前面的那张；有排队中派发的卡片跳过。带 ID 领取、手动派发不看「优先」。持有者是领取它的 agent。
2. **互斥**：多个 agent 同时领取同一张卡片，只有一个成功。
3. **一个 agent 在一块白板上同时只持有一张卡片。**
4. **进入锁定状态只能靠领取**：人和 agent 都不能把卡片直接移进锁定状态。例外：持有者可以沿连线把自己持有的卡片从一个锁定状态移到另一个锁定状态，领取保持不变；派发排队时卡片进入领取时会进的锁定状态，没有持有者（§9.1「占用」）。
5. **持有者独占**：被持有的卡片只有持有者能编辑和移动，其他人和 agent 只能评论、加或去标签。人可以在界面上「强制释放」。
6. **心跳与耗时**：一个 agent 会话只有一路后台心跳。check 之后，`board heartbeat start` 启动的后台循环每 10 秒发一次 `board beat`（不带 ID）：更新名字的心跳时间（名字已离线时被拒绝，`NAME_OFFLINE`；带的会话标识对不上时被拒绝，`NAME_TAKEN`，见 §3.2），并对这个名字持有、这一次还没 final 的每张卡片记一次心跳，效果等同于 `board beat <ID>`：更新卡片的心跳时间，计入心跳次数。领取后的第一次心跳是这一次的开始，动态里记「开始第 n 次」；final（`board beat <ID> --final`）是结束，两者之差是这一次的耗时，记在动态里；卡片显示累计耗时。final 之后这张卡片不再被后台心跳刷新，再发 `board beat <ID>` 被拒绝。同一张卡片被多次领取时，每一次分别计时、分别记录。评论、编辑不代替心跳。
7. **心跳中断释放**：从领取或最近一次心跳算起，连续 5 次（50 秒）没收到心跳，卡片回到领取它时所在的可领取状态最上面（那个状态已删除或不再可领取时，回到首个可领取状态最上面），持有者清空，动态里记「心跳中断」。进行中的这一次以最后一次心跳为结束，记为异常退出；还没开始心跳、或发了 final 后 50 秒内没有沿连线移走的，动态里写明原因。名字离线后，它持有的卡片收不到心跳，按这条规则在 50 秒内释放。本次耗时有四种结束方式：final 正常结束、持有者移出锁定状态、人强制释放、心跳中断。
8. **离开锁定状态即释放**：持有者把卡片移到不锁定的状态时，持有者清空，进行中的这一次在此时结束。人强制释放后，卡片回到的位置同规则 7，进行中的这一次在此时结束。
9. **终点只归人管**：只有人能把卡片移入或移出终点状态。错误节点只有人能移出（agent 可以沿连线移入）。
10. **删除的卡片先进回收站，30 天内可以恢复；只有人能删除、恢复、永久删除。**
    - 删除：白板、卡片详情、未整理页里的删除和批量删除都移进回收站。卡片不再出现在白板、`board ls`、搜索、大盘里，`board show` / 编辑 / 移动 / 评论得到 `NOT_FOUND`（经服务端的卡片命令得到 `IN_TRASH`，原因写明它在回收站里）；卡片编号不复用。删除前已有的处理照旧：还在持有中的领取先释放（进行中的这一次在此时结束），排队中的派发取消、正在跑的请求停止。动态里记一条「<人> 删除」。
    - 回收站按白板划分：列出这块白板删掉的卡片，每张记下编号、标题、删除的时间、谁删的、删除前在哪个状态、在那个状态里排第几位。
    - 恢复：卡片回到原来状态里原来的位置；原来在锁定状态（被删时还在做）的，回到当初领取它的可领取状态；原来的状态已经删了的，回到首个可领取状态。恢复后不保留领取（没有人持有），动态里记一条「从回收站恢复」。
    - 永久删除：卡片、动态、评论、附件一起删掉，不能恢复。
    - 回收站里超过 30 天的卡片自动永久删除（附件一起删）；每块白板的回收站最多留 1000 张，超出的按删除时间先清掉最早的。
    - 合并「未整理」条目时被并掉的那几条不进回收站：它们的内容已经并进留下的那一条（规则 11）。
    - 删除白板、删除项目的行为不变：白板、项目连同里面的卡片（含回收站里的）一起删除。
11. **「未整理」的整理只归人管**：界面或 agent/CLI（`board new --inbox`）都可以新建「未整理」条目；只有人能把卡片移入或移出「未整理」，同样受规则 4、5 约束。合并条目也只能由人在界面上做，而且只能合并「未整理」里的条目：选中的几条并成其中一条（保留它的编号），其余几条的标题和描述按顺序接在它的描述后面（每条一节，写明合并自哪一条，合并前可以改），标签取并集，附件和评论归到留下的这条，其余几条删除。
12. **agent 只能沿连线移动**：agent 把卡片从 A 移到 B 时，工作流里必须有连线 A → B，否则被拒绝，原因里列出 A 能去的状态。人移动卡片不受连线限制。在同一个状态内调整顺序不受影响。

**卡片在状态里的位置**

- 新建：首个可领取状态最下面；CLI 带 `--top` 时放在最上面。界面或 CLI（`--inbox`）新建时可以选择放进「未整理」，放在「未整理」最下面。
- 移动：目标状态最下面；CLI 带 `--top` 时放在最上面。界面上拖拽时放在松手的位置。
- 「整理到<首个可领取状态>」：首个可领取状态最下面。
- 合并「未整理」条目：留下的那条位置不变。
- 心跳中断释放、强制释放：领取它时所在的可领取状态最上面（规则 7）。
- 从回收站恢复：原来状态里原来的位置（删除之后那一列的第几位还在，就放回第几位）；原来在锁定状态、或者原来的状态已经删了的，见规则 10。

## 9. CLI

所有命令都支持 `--json`，输出 JSON。成功时退出码为 0；被拒绝时退出码为 1，并给出错误码（见 §12）和原因。

**安装**：桌面端安装包自带 `board` 命令行。Windows 安装器把它写进用户 PATH，装完重开终端就能用；macOS 的安装包不带安装脚本，在「设置 → Agent 接入」里执行一条命令，把 `Board.app` 里自带的 `board` 所在目录写进 shell 的 PATH（写进 `~/.zshrc`，重复执行不会重复追加）。不装桌面端时（例如只有命令行的服务器）用服务端提供的安装脚本：`curl -fsSL <服务端>/install.sh | sh`（Windows：`irm <服务端>/install.ps1 | iex`），见下面「安装与升级」；也可以从源码安装：`cargo install --path crates/board-cli`（需要 Rust）。agent 用 skill 自带的 `board`：发版附件 `board-skills.zip` 的 `bin/` 里有各平台的二进制，skill 里的 `scripts/board`（Windows：`scripts\board.cmd`）按平台选用，没有时用 PATH 里的 `board`。

**安装与升级**

- 发版附件里有单独的 `board` 包：每个平台一个压缩包（`board-darwin-arm64.tar.gz`、`board-darwin-x64.tar.gz`、`board-linux-x64.tar.gz`、`board-linux-arm64.tar.gz`、`board-windows-x64.zip`，里面只有 `board` / `board.exe`），和 SHA-256 校验文件 `board-sha256.txt`。
- 安装脚本：服务端在 `/install.sh`（macOS、Linux）和 `/install.ps1`（Windows）提供，不需要登录；脚本里写着服务端自己的版本号、对外地址和发版附件的地址（服务端的环境变量 `BOARD_DOWNLOAD` 可以换成镜像）。脚本按平台下载压缩包和校验文件，校验对不上就中止、不替换已有的 `board`；装到 `~/.local/bin`（Windows：`%LOCALAPPDATA%\Board\bin`，环境变量 `BOARD_INSTALL_DIR` 可改），这个目录不在 PATH 里时写进 shell 配置（Windows 写用户 PATH），只追加一次。带 `--token`（PowerShell：`-Token`）时接着 `board login`；带 `--name`、`--dir` 时，加 `--service` 装成系统服务（`board host --install`，开机自动接任务），不加时给出前台运行的命令。「添加机器」弹窗生成的就是这样一行（§10.12）。
- **`board update [--latest]`**：把单独安装的 `board` 原地升级到服务端的版本（`GET /api/health`，只要服务端地址、不要令牌）；`--latest` 升级到最新发版。下载、校验和安装脚本一样，校验对不上不替换；解压出的新 `board` 先核对 `--version`，再替换正在运行的这个文件（Windows 上把旧的改名成 `board.old.exe`，下次升级时删掉）。已经是这个版本时什么都不做。桌面端自带的 `board`（在 `.app` 里，或和 `board-desktop` 在同一个目录）跟着桌面端升级：拒绝执行，提示用桌面端的「检查更新」。本机有用这个文件运行的 `board host` 时提示重启它；远程「升级」（§9.1）由 `board host` 自己执行 `board update`，成功后自己重启。

**`board skills <ls | push <目录>… | sync | rm <名称>>`**：skills 共用库（§10.12「共用配置」），访问令牌就能执行，不用 `--as`、`--board`。

- `ls`：列出库里的 skill（名称、版本、更新时间、来源），以及这台机器上每个 agent skill 目录（`~/.agents/skills`、`~/.claude/skills`、`$CODEX_HOME/skills` 里上一级目录存在的）里的状态：已同步、版本落后、本机有同名没覆盖、没装。
- `push <目录>…`：把本机的 skill 目录传进库里：目录名（转成小写）就是 skill 名，里面要有 `SKILL.md`，跳过以 `.` 开头的文件和目录，合计不超过 5 MB（超过时拒绝并说明，服务端也拦）；同名的换成新版本，来源记这台机器的机器名，上传者记令牌名称。`board-skills` 不能传。
- `sync`：按库更新本机；本机有 `board host` 在跑时不做，提示由它来做。
- `rm <名称>`：从库里删掉，各台机器上由同步装的那份随后删掉；`board-skills` 不能删。

**连接**

CLI 只通过服务端读写白板，规则在服务端执行。服务端地址和访问令牌写在配置文件 `~/.board/config.toml`（Windows 上是 `%USERPROFILE%\.board\config.toml`）里：

| 配置项 | 内容 |
|---|---|
| `url` | 服务端地址，例如 `https://board.example.com`；本机模式的服务端填它的本机地址，例如 `http://127.0.0.1:7420` |
| `token` | 访问令牌，在界面「设置 → Agent 接入」新建 |
| `[host]` | `board host` 的机器名 `name`、白板与目录 `dirs`、本机日志保留天数 `log_days`（§9.1） |
| `[agents.<标识>]` | `board host` 的 agent 命令模板 `cmd`（§9.1） |

- 配置文件所在目录权限 0700，文件权限 0600。以后固定的配置也写在这个文件里；agent 名字（`BOARD_AS`）和白板（`BOARD`）不写进这个文件。
- 环境变量 `BOARD_CONFIG` 指定另一个配置文件代替 `~/.board/config.toml`（`board host` 启动 agent 时用它传连接，§9.1）。
- 读取顺序：环境变量 `BOARD_URL` / `BOARD_TOKEN` 优先，配置文件其次。两处都没有时报 `NOT_LOGGED_IN`，提示运行 `board login`。
- 令牌无效或已吊销时被拒绝（`INVALID_TOKEN`）；连不上服务端时被拒绝（`UNREACHABLE`）。

**`board login [--url <地址>] [--token <令牌>]`**

- 不带 `--url` 时沿用文件里已有的 `url`，文件里也没有就报 `USAGE`。不带 `--token` 时从标准输入读一行。
- 写入前用 `GET /api/workspace` 校验令牌。校验失败时不写文件，按服务端返回的错误码报错（`INVALID_TOKEN`、`UNREACHABLE` 等）。
- 改写文件时保留其他配置项。
- 写入成功后，如果当前环境里设置了 `BOARD_URL` 或 `BOARD_TOKEN`，输出一行提醒：环境变量会覆盖配置文件，需要从 shell 配置文件里删掉对应的 `export`。
- 输出里不打印令牌原文。

**`board logout`**：从配置文件删掉 `token`，保留 `url`。

**`board doctor [--as <名字>] [--board <白板>]`**：环境自检，没通过的项给出原因和下一步，有失败项时退出码为 1。

- 服务端地址和令牌两项写明值来自哪里：环境变量还是 `~/.board/config.toml`。两处都有时状态为 warn，说明环境变量覆盖了文件；两处都没有时，下一步提示 `board login --url <服务端地址>`。
- 名字（`--as` 或 `BOARD_AS`）和白板（`--board` 或 `BOARD`）没提供时跳过，不判失败；提供了名字时，检查格式和是否在线。

除 `board help`、`board login`、`board logout`、`board doctor`、`board update` 外，所有命令都需要连接服务端；除这几个和 `board host`、`board dispatch`、`board skills` 外，都需要身份（§3）；此外除 `board boards`、`board check`、不带 ID 的 `board beat`、`board host` 外，都需要白板（§3）。

| 命令 | 作用 |
|---|---|
| `board check --as <名字>` | 占用名字（§3.2）。会话开始时执行一次 |
| `board heartbeat start` | 启动后台心跳（§8 规则 6）：先同步发一次 `board beat`，失败直接报错；成功后后台每 10 秒发一次，立即返回。后台心跳跟随 agent 进程（从 board 往上找第一个不是 shell 的祖先进程），agent 进程不在了就停下，不发 final；心跳被拒绝时停下，连不上服务端时继续重试 |
| `board heartbeat stop [--force]` | 先停掉后台心跳、等它退出，再发 `board beat --final`，名字立刻离线；重复执行不报错。名字是本机另一个还在运行的 agent 进程 check 的时候，`start`、`stop` 都拒绝（`NAME_TAKEN`），不动它的后台心跳；`--force` 只放开本机这一层（§3.2） |
| `board heartbeat final <ID>` | 等同 `board beat <ID> --final`：结束这张卡片这一次的计时 |
| `board beat [--final] [--force]` | agent 级心跳（§8 规则 6），一般由 `board heartbeat` 的后台循环发送；`--final` 让名字立刻离线。带着 check 时拿到的会话标识，规则同 §3.2 |
| `board beat <ID> [--final]` | 一张卡片的心跳；`--final` 结束这一次计时（§8 规则 6） |
| `board boards` | 列出所有白板：路径、项目名、白板名、各状态卡片数 |
| `board flow` | 列出当前白板的工作流：顺序、标识、名称、规则、卡片数，以及每个状态可以去往的状态；末尾一行是白板设置的仓库地址和集成分支（`--json` 里是 `repo`、`branch`，没设时为空字符串） |
| `board ls [--column <状态>] [--search <文字>] [--label <标签>]` | 列出卡片：ID、状态、标题、标签、持有者，按工作流顺序和状态内顺序排列。`--search` 在标题和描述里查找；`--label` 只列出带该标签的卡片。只查一块白板 |
| `board search "<文字>" [--limit <条数>]` | 跨所有白板（含「未整理」）搜卡片，不需要 `--board`：文字按标题、描述、评论搜（不区分大小写，空格分开的多个词先要求全部出现，没有结果时改为任一词出现），也认 `#ID`（所有白板里编号是它的卡片）、`项目/白板#ID`（直接定位那张卡）、`label:<标签>`（带这个标签的卡片，标签名不区分大小写）。输出白板路径、ID、状态、标题、标签；结果按相关度（编号、标签、标题、描述、评论依次靠前）、再按更新时间排序，最多 50 条（`--limit` 可以更少）。`--json` 里每条还带 `column`、`status`、`matched`、`updated_at` |
| `board show <ID>` | 显示卡片的全部字段和动态；第一段多一行「网址」（见 §10.1 的网址规则） |
| `board new "<标题>" [--body "<描述>" \| --body-file <文件>] [--image <图片>]… [--file <文件>]… [--top] [--inbox] [--label <标签>]…` | 在首个可领取状态新建卡片；建好后多输出一行「网址」；`--inbox` 记到「未整理」最下面；`--label` 可以写多次，按名称匹配（不区分大小写），同一个只算一次；项目里没有这个标签、或它是「仅人可打」时拒绝（`USAGE`，原因里列出可用的标签 / 写明只有人能打），不新建卡片；`--image`、`--file` 可以写多次：建卡前先在本地检查每个文件（不存在、类型不支持、内容和扩展名对不上、超过 10 MB 都拒绝，`USAGE`，不上传、不建卡；`--image` 只收图片），再上传成还没归属的附件，按参数顺序把 Markdown 引用（图片 `![名](/api/files/<id>)`、文件 `[名](/api/files/<id>)`）接在描述后面，建卡时服务端按引用把附件归到这张卡片 |
| `board edit <ID> [--title "<标题>"] [--body "<描述>" \| --body-file <文件>]` | 修改标题或描述 |
| `board move <ID> <状态> [--top]` | 把卡片移到指定状态（标识或名称）；只能沿连线移动（§8 规则 12） |
| `board claim [<ID>]` | 领取。不带 ID 时按 §8 规则 1 选卡片。返回卡片的全部字段和动态 |
| `board next` | 只在 `board host` 启动的会话里用（环境里有 `BOARD_HOST`，名字是这次会话生成的），否则 `USAGE`：结算上一张、领这个会话排着的下一张接着做（§9.1「会话接着做」），返回内容和 `board claim` 一样；不再接着做时 `SESSION_DONE` |
| `board hold <ID> [--wait <秒>]` | 推集成分支前确认领取仍有效：卡片由这个名字持有、在锁定状态时成功；否则 `NOT_HOLDER`，写明卡片现在在哪个状态、谁持有。连不上服务端时每 30 秒重试，最多等 `--wait` 秒（默认 300），还连不上就 `UNREACHABLE` |
| `board comment <ID> "<内容>"`<br>`board comment <ID> --comment-file <文件>` | 追加评论 |
| `board label <ID> +<标签> -<标签> …` | 加标签（`+` 或不带前缀）、去标签（`-`），可以一次写多个；「仅人可打」的标签不能加、去（`USAGE`，§6） |
| `board labels` | 列出白板所属项目的标签、每个标签的类型（agent 可打 / 仅人可打）、是否优先，以及被多少张卡片使用；`--json` 里是 `human_only`、`priority` |
| `board attach <ID> <文件>… [--comment "<说明>" \| --comment-file <文件>]` | 上传附件，连同说明作为一条评论追加到卡片 |
| `board files <ID> [--out <目录>]` | 把卡片的附件下载到本地（默认系统临时目录），列出文件路径 |
| `board host [--name <机器名>] [--dir <项目>/<白板>=<路径>]…` | 在这台机器上常驻接任务（§9.1），前台运行，`Ctrl+C` 退出 |
| `board dispatch <ID> --host <机器名> [--agent <标识>]` | 把卡片派给一台机器上的 agent；不带 `--agent` 用这台机器的默认 agent（§9.1） |
| `board dispatch <ID> --cancel` | 取消还在排队的派发，或停止正在跑的派发（§9.1） |

`board ls --json`、`board show --json` 的卡片里，`labels` 是标签名，`priority_labels` 是其中的优先标签；`board show --json`、`board new --json`（以及返回卡片的 `board claim`、`board next` 等）还有 `url`，是这张卡片的完整网址（服务端地址 + `/<项目>/<白板>/<ID>`，见 §10.1）。

`--body-file`、`--comment-file` 从文件读描述、评论（`-` 读标准输入），和直接写的参数只能给一个；文件按 UTF-8 读，去掉 BOM，带 BOM 的 UTF-16 也认，换行统一成 `\n`，不是 UTF-8 时拒绝（`USAGE`）。Windows 上 skill 的入口 `board.cmd` 要经过 cmd.exe，参数里的换行会把命令截断在第一行，多行内容只能这样传。`board --version` 打印版本号。

### 9.1 任务下发（board host）

**机器**：运行 `board host` 的进程代表一台机器。有名字、在线状态、并发上限、启动环境、本机 agent、白板与目录。

**让机器重启后自动接任务**：

- 命令行：`board host --install [--name <机器名>] [--dir <项目>/<白板>=<路径>]…` 按这些参数装成开机自启的服务（不给时跟着配置文件 `[host]` 走），装好后立即启动，打印怎么看状态、日志在哪、怎么卸载；`board host --uninstall` 停掉并删掉服务。macOS 写 launchd 用户代理 `~/Library/LaunchAgents/dev.board.host.plist`；Linux 写 systemd 用户服务 `~/.config/systemd/user/board-host.service`（没开 linger 时提示执行 `loginctl enable-linger <用户>`，才能在没人登录时也运行）；Windows 建一个这个用户登录时运行的计划任务「Board host」（经隐藏窗口的 PowerShell 启动，不限运行时长）。服务带上安装时的 `PATH` 和 `HOME`；只用配置文件里的服务端地址和令牌（没有时拒绝安装，提示先 `board login`）。`--dir` 里的相对路径按当前目录换成绝对路径。桌面端自带的 `board` 拒绝安装，提示用桌面端的「开机时自动启动」。
- 服务运行的是守护进程 `board host --service …`：它带着同样的参数启动 `board host`（环境变量 `BOARD_HOST_SUPERVISED=1`），输出写进 `~/.board/host/host.log`（超过 5 MB 轮转成 `host.log.1`、`host.log.2`，守护进程自己的话带日期时间）；`board host` 异常退出（退出码非 0、被 `kill -9`）10 秒后重启，退出码 75（远程「重启」、命令行升级后）马上重启，正常退出时守护进程也退出。守护进程收到停止信号（停止服务、卸载）时先让 `board host` 收尾（结束 agent、离线），最多等 30 秒。守护进程自己崩溃时由 launchd（只在非 0 退出时拉起、间隔 10 秒）、systemd（`Restart=on-failure`、`RestartSec=10`）、计划任务（失败后 1 分钟重试）重新拉起。
- 桌面端：「设置 → 本机」的「开机时自动启动」（§10.6）。

- 机器名：小写字母、数字、`.`、`-`，以字母或数字开头，最长 24 个字符；不填时取本机主机名转成小写、非法字符换成 `-`。同名机器正在线时启动失败（`HOST_NAME_TAKEN`）。同一台机器上 `board host` 异常退出后重启，接回原来的名字。桌面端运行的 `board host`（`BOARD_HOST_STDIN=1`）在标准输入读到一行 `reload` 时重新读配置文件，机器名、白板与目录变了（命令行没给 `--name` / `--dir`）不重启就换上：机器名先在服务端原地改名，改名失败、目录不存在时打印一行，接着用原来的。
- 白板与目录：一块白板对应本机的一个仓库目录，agent 在这个目录里启动。没有对应目录的白板，这台机器不接它的卡片。设置存在服务端：机器第一次连上、服务端还没有时，用它配置文件里上报的建立；之后以服务端为准。在任一登录设备上都能改（加一块白板、改路径、删除），改动通过实时推送送到那台 `board host`，它写进自己的 `~/.board/config.toml` `[host] dirs` 并马上换上，不用重启，离线重启后照样生效。`--dir` 启动的白板由启动参数固定，界面上只读，要改得去那台机器改启动参数。`board host` 每次心跳检查每个目录：存在且是 git 仓库（同时上报 `origin` 和当前分支）、不存在、存在但不是 git 仓库；界面上逐行显示，异常的用警告色。目录不存在时可以在界面上填仓库地址，让那台机器用本机 git 凭据执行 `git clone <地址> <路径>`，进度和失败原因回到这一行；一块白板失败不影响其他白板。远端改目录不需要目标机器确认（打开「让这台电脑接任务」时已经确认过免审批运行的风险）；本机桌面端改目录仍然先确认。
- 环境检查：白板设置里可以写一行检查命令（所有系统一行；Windows 可以单独写一行，没写时用所有系统那行），最长 500 个字符，只能一行。`board host` 在这块白板的目录里执行它（macOS、Linux 在登录 shell 里 `$SHELL -l -i -c`，和启动 agent 时读到同样的 `PATH`；Windows 在 cmd 里 `cmd /d /s /c`），退出码为 0 算通过，最长 2 分钟（超时结束它、算没通过），上报结果、退出码和输出（标准输出和标准错误）的最后 20 行。登录 shell 自己的启动、退出提示（没有终端时 bash 的 `bash: cannot set terminal process group…`、`bash: no job control…`、退出时的 `logout`，以及发行版 `/etc/bash.bashrc` 打的 sudo 提示）不是命令的输出，上报前去掉；`zsh:1: command not found: cargo` 这类真正的错误照常保留，作为失败原因。执行时机：`board host` 启动时、重新读配置时、每天一次、白板的检查命令或这块白板的目录改了之后、目录不存在之后又有了（克隆完）；目录不存在时直接算没通过。结果只认命令对得上的：命令改了、还没跑完时算「还没检查」；旧版 `board host` 不检查，一直是「还没检查」。检查没通过（含还没检查）的机器不接这块白板的卡：定时领取跳过这块白板；手动派发被拒（`BOARD_NOT_READY`，写明输出的最后一行），界面上派发对话框里这台机器不能选并写明原因；已经在跑、已经排队的派发不受影响。没写检查命令的白板和原来一样。
- 启动环境：在哪种 shell 里启动 agent 的命令。启动时找出本机有哪些，上报标识、名称、程序路径（WSL 写发行版名）：

  | 标识 | 名称 | 系统 | 怎么发现 | 怎么启动 agent |
  |---|---|---|---|---|
  | `direct` | 直接启动 | 所有 | 总有 | 直接执行命令模板，不经过 shell |
  | `login` | 登录 shell | macOS、Linux | `$SHELL`，没有时 passwd 里的登录 shell，再没有 `/bin/sh` | `$SHELL -l -i -c 'exec "$0" "$@"' <命令> <参数>…` |
  | `cmd` | cmd | Windows | `%ComSpec%` | `cmd.exe /d /s /c "<命令> <参数>…"`，每个参数加双引号；命令名是普通名字（字母、数字、`.`、`-`、`_`）时不加引号，含路径、空格等字符时才加（加了引号的 `.cmd` 拿到的 `%~dp0` 是当前目录，脚本里拼的相对路径会找错——DeepSeek Harness 的 `dsh.cmd` 就是这样，退出码 9009） |
  | `powershell` | Windows PowerShell | Windows | `%SystemRoot%\System32\WindowsPowerShell\v1.0\powershell.exe` | `powershell.exe -NoLogo -NonInteractive -ExecutionPolicy Bypass -Command "& '<命令>' '<参数>' …; exit $LASTEXITCODE"`，参数里的 `'` 写成 `''` |
  | `pwsh` | PowerShell 7 | Windows | `PATH` 里的 `pwsh.exe`，或 `%ProgramFiles%\PowerShell\7\pwsh.exe` | 同上，换成 `pwsh.exe` |
  | `git-bash` | Git Bash | Windows | `%ProgramFiles%\Git\bin\bash.exe`、`%ProgramFiles(x86)%\Git\bin\bash.exe`，再看 `PATH` 里 `git` 所在的那套 Git 安装：从 `git.exe` 的目录往上三层找 `bin\bash.exe`（`<Git>\bin`、`<Git>\cmd`、`<Git>\mingw64\bin` 三种布局都认），没有时用 `usr\bin\bash.exe` | `bash.exe -l -c 'exec "$0" "$@"' <命令> <参数>…` |
  | `wsl:<发行版>` | WSL（<发行版>） | Windows | `wsl.exe -l -q` 列出的每个发行版各算一个 | `wsl.exe -d <发行版> --cd <目录> --exec setsid -w bash -l -i -c 'exec "$0" "$@"' <命令> <参数>…` |

  - 提示词作为独立参数传入，不拼进 shell 命令文本（cmd 除外：加双引号拼进命令行）。启动环境的退出码就是 agent 的退出码。
  - 登录 shell 和 WSL 用交互式（`-i`），这样写在 `~/.zshrc`、`~/.bashrc` 里的 `PATH` 也生效；agent 进程脱离终端（`setsid`）。shell 的启动脚本里设了 `BOARD_URL`、`BOARD_TOKEN` 也不影响：启动 agent 前用 `board host` 的值再设一遍。
  - WSL：目录用 `--cd` 传 Windows 目录，由 `wsl.exe` 换成 `/mnt/…`；环境变量经 `WSLENV` 传入，`BOARD_CONFIG` 换成 WSL 路径，不传 `BOARD_EXE`（WSL 里用 `board-skills` 自带的 Linux 版 `board`）。
- 本机 agent：启动时按内置模板、服务端下发的共用模板（§10.12「共用配置」的「agent 模板」，随任务下发）和配置文件里的 `[agents.*]`（后面的覆盖前面同标识的：本机配置文件优先；覆盖了共用模板的在上报里标出来，机器详情这个 agent 标「本机配置覆盖」），在每个 agent 支持、本机有的每个启动环境里检查一次：执行 `command -v <命令>`（cmd、PowerShell 用 `where.exe`；WSL 里 `/mnt/` 下的 Windows 程序不算）看找不找得到，找到了再执行 `<命令> --version` 取第一行作为版本号；上报每个 agent 在每个环境里「找到 + 版本号」或「没找到」。内置模板「`PATH` 里没有时再看」的位置只在 `direct`、`login` 里用。找到了、但在它用的启动环境里（用户级 skill 目录，WSL 里看 WSL 用户目录下的；或每块白板目录里的 `.agents/skills`、`.claude/skills`、`.pi/skills`）看不到 `board-skills` 时，启动时在终端提醒一行（写明装到哪里），并在上报里给这个 agent 在这个环境里标上「看不到 `board-skills`」和装到哪里；在启动、重新读配置、远程「重新检查」时检查（见下面「远程管理」），装好后在界面上点「重新检查」就会更新。共用模板、配置文件里同标识的模板覆盖内置模板（写了哪项换哪项；支持的启动环境不变，共用模板写了 Windows 启动环境时用它的）。共用模板变了，`board host` 取到任务时重新检查本机 agent 并马上上报，不用重启。`{prompt}` 换成提示词；`{patch}` 换成 board host 为这次派发写的 profile 补丁路径（目前只有 dsh 模板用）。接入其他 agent 的方法见 `docs/agents.md`。

  | 标识 | 名称 | 命令模板 | `PATH` 里没有时再看 | 读 skill 的目录 | 支持的启动环境（Windows） |
  |---|---|---|---|---|---|
  | `dsh` | DeepSeek Harness | `dsh --profile headless --json --patch {patch} --permission-mode danger-full-access {prompt}` | macOS 的 `DeepSeek Harness.app` 里自带的 `dsh` | `~/.agents/skills` | `pwsh` → `powershell` → `cmd` |
  | `claude` | Claude Code | `claude -p {prompt} --dangerously-skip-permissions --output-format stream-json --verbose` | `~/.local/bin/claude`、`~/.claude/local/claude` | `~/.claude/skills` | `pwsh` → `powershell` → `git-bash` → `wsl:*` → `cmd` |
  | `pi` | pi | `pi --mode json {prompt}` | — | `~/.agents/skills`、`~/.pi/agent/skills` | `git-bash` → `wsl:*` → `pwsh` → `powershell`（不支持 `cmd`；不在 WSL 里时把 `PATH` 里 git 所在那套 Git 的 Git Bash 放到 pi 的 `PATH` 前面） |
  | `codex` | Codex | `codex exec --json --dangerously-bypass-approvals-and-sandbox {prompt}` | — | `$CODEX_HOME/skills`（默认 `~/.codex/skills`） | `pwsh` → `powershell` → `git-bash` → `wsl:*` → `cmd` |
  | 配置文件里新加的 | | | | | `pwsh` → `powershell` → `git-bash` → `wsl:*` → `cmd` → `direct` |

  macOS、Linux 上所有 agent 都是 `login` → `direct`。`wsl:*` 按 `wsl.exe -l -q` 的顺序展开。
- 参数也可以写在 `~/.board/config.toml` 的 `[host]`（`name`、`dirs = { "<项目>/<白板>" = "<路径>" }`、`log_days`）和 `[agents.<标识>]`（`cmd = [...]`）里，命令行参数优先。
- 启动后上报机器名、操作系统、board 版本、本机 agent、白板与目录，每 10 秒一次机器心跳，连续 5 次没收到算离线。`board host` 用令牌订阅实时推送，收到派发、设置变化、停止请求后立即处理。
- 和服务端断开超过 30 秒时，`board host` 在本机输出里提醒一次（还有几个 agent 在跑、超过 50 秒会被判掉线、卡片会被放回），恢复连接时再写一行。恢复后发现派发已经被服务端结束（机器掉线），结束那个 agent；它退出后，agent 的 worktree（`board-skills` 约定的 `<仓库目录名>.wt/<名字>`）和白板目录里有没提交的文件、不在任何远端分支上的提交时，在本机输出里写明路径，方便人捞回来。
- `Ctrl+C` 退出：先按「人停止」结束本机由它启动的全部 agent，再让机器离线。

**远程管理**（只能在登录后的界面上做，用令牌调用时 `NOT_LOGGED_IN`；请求存在服务端，随任务下发给那台 `board host`，同一时间一台机器只有一个请求，新的换掉旧的；每次操作和结果都记进这台机器的操作记录：谁、什么时间、做了什么，机器详情「最近」里显示，移除机器时一起删）：

| 操作 | 什么时候能用 | 做什么 |
|---|---|---|
| 重新检查 | 在线 | `board host` 重新查找启动环境、本机 agent（找不找得到、版本号）、`board-skills`，环境检查也重跑，立即上报；正在跑的派发不受影响。做完记下时间（机器详情「本机 agent」写「<时间> 重新检查过」） |
| 升级到 <服务端版本> | 在线，并且这台机器的 board 版本比服务端旧 | 先暂停接单（本来就暂停的保持），等正在跑的派发结束再升级，界面上写「等 N 个派发结束后升级」；「立即升级」时正在跑的按「人停止」结束。命令行运行的 `board host` 执行 `board update`（还没有这个命令的旧版本记为失败：要到那台机器上手动升级一次），成功后用新版本原地重启自己；桌面端运行的退出码 76 交给桌面端：检查、下载、验签、安装桌面端更新（和设置里手动更新同一套），然后重启桌面端，重启后照常接任务。新版本上线后恢复接单，记「升级到 <版本>」；失败时恢复接单，写明原因 |
| 重启 board host | 在线；二次确认 | 正在跑的派发按「人停止」结束；`board host` 让机器离线后用同样的参数重新启动（macOS、Linux 原地换进程；Windows 上桌面端运行的退出码 75 交给桌面端重新启动，命令行运行的启动一个新进程），重新读配置、重新检查后上线 |
| 排空 | 总是 | 暂停接单，等正在跑的派发结束；都结束后机器详情写「已排空，可以关机或维护」。恢复接单时排空结束 |
| 取消 | 有还没处理的请求时 | 清掉请求；为升级暂停的接单恢复 |

- 等重启、升级时这台机器不开始新的派发（排队的留着）。
- 旧版 `board host` 不认这些请求：请求一直留着，界面上显示是谁、多久前请求的，可以取消。
- 令牌：服务端记着每台机器最近一次上报用的访问令牌。机器详情显示它的名称、开头几位、最近一次使用时间，还有哪些别的在线机器也在用它。「移除机器」的确认框里有「同时吊销它用的令牌」：只有别的在线机器都不用这个令牌时才能勾；勾了之后这个令牌立即作废，用它的命令得到 `INVALID_TOKEN`，那台机器的 `board host` 随之退出。

**机器设置**（存在服务端，在界面上修改，`board host` 实时拿到，不需要重启；机器第一次连上时按默认值建立）：

| 设置 | 默认值 | 说明 |
|---|---|---|
| 同时跑几个 | 1 | 1–8。正在跑的派发达到上限后，新的派发在服务端排队 |
| 单次最长运行 | 3 小时 | 30 分钟到 12 小时，或者不限（0）。界面从预设档位里选（不限、30、60、90、120、180、240、300、360、480、600、660、720 分钟，档位不连续）；接口接受 0–720 的整数分钟，超出范围拒绝（`USAGE`）。从 agent 进程启动算起；到时间后 `board host` 按「人停止」的流程结束整个进程树，派发结果「超时」（见下面「结束」）。界面上改，`board host` 下一次上报（每 10 秒）就拿到最新值，不用重启；改了之后正在跑的派发也按新值算，改小到已经超过的时间时下一次检查就停 |
| 没输出多久算卡住 | 20 分钟 | 5 到 120 分钟，或者不限（0）。界面从预设档位里选（不限、5、10、15、20、30、45、60、75、90、105、120 分钟，档位不连续）；接口接受 0–120 的整数分钟，超出范围拒绝（`USAGE`）。只对已经输出过内容的派发生效：agent 的标准输出和标准错误写进日志文件，日志在这么久里一行都没变长就按「人停止」的流程结束它，派发结果「超时」。一行都还没输出过的派发不算（内置的 Claude Code 模板带 `--output-format stream-json --verbose`，运行中逐步有输出；只有在配置里改写命令、又没带事件流参数时，`-p` 才要到结束才有输出）。同样不用重启 |
| 一个会话最多做几张 | 4 | 1–8，超出范围拒绝（`USAGE`）。只对定时领取（含「现在领一轮」）启动的会话生效：开会话时一次排好这个会话要做的卡片，最多这么多张；agent 做完一张用 `board next` 接着做排着的下一张，排着的做完就退出（§9.1「定时领取」「会话接着做」）。一轮里先把一个会话排满再开下一个会话；设为 1 时一个会话只做一张，有几个空位就同时开几个会话。改了只影响之后新开的会话。手动派发的会话只做指定的那一张；人手动跑 `/board-skills` 的会话不受限制 |
| 暂停接单 | 关 | 打开后不启动新的派发（手动派发照样排队），已经在跑的不受影响 |
| 默认 agent | 本机 agent 里第一个找到的，顺序是 dsh、claude、pi、codex，然后是配置文件里新加的 | 手动派发时预先选中它 |
| 每个 agent 的启动环境 | 按上表「支持的启动环境」的顺序，取本机有、并且这个 agent 在里面找得到的第一个 | 只能选这个 agent 支持、本机有、在里面找得到命令的环境，否则拒绝（`USAGE`，写明原因）。改了下一次派发就用新的，已经在跑的不受影响。设置的环境本机已经没有（例如卸载了 Git Bash）时按默认值的规则选。agent 在设置的环境里找不到命令，就算这台机器「没找到」这个 agent。旧版 `board host` 不上报启动环境：不显示这一项，按 `direct` 启动 |
| 每个 agent 的模型、思考强度 | agent 自己的默认（不传参数） | 机器详情「本机 agent」每个 agent 下面一行：「模型」是可以手填的下拉（列这个 agent 常用的几个），「强度」只列这个 agent 支持的档位，各自乐观保存。模板决定怎么传：Claude Code `--model`、`--effort`（low、medium、high、xhigh、max），pi `--model`、`--thinking`（off、minimal、low、medium、high、xhigh、max），Codex `-m`、`-c model_reasoning_effort=`（minimal、low、medium、high），dsh 不能选（不显示）；配置文件里的 agent 写了 `model_args`、`effort_args`（、`efforts`）才显示。参数插在 `{prompt}` 前面，没选时命令和原来完全一样。模型名：字母或数字开头，字母、数字和 `. _ : / @ + -`，最长 64 个字符；不支持的档位、不对的模型名拒绝（`USAGE`）。改了下一次派发就用新值，已经在跑的不受影响，不用重启 `board host`。旧版 `board host` 不上报能选什么：这两项置灰，写「这台机器的 board 要升级到 <服务端版本> 才能设置」，接口拒绝（`USAGE`） |
| 白板与目录 | 首次连接时配置文件 `[host] dirs` 里的值 | 服务端保存后是主版本；改了发实时推送，`board host` 写回本机配置并直接换上。每行带目录检查结果（正常 / 不存在 / 不是 git 仓库）。`--dir` 启动的行只读。目录不存在时可以请求那台机器克隆仓库 |
| 定时领取 | 关，没有表达式 | 若干条 cron 表达式（标准 5 段「分 时 日 月 周」，支持 `*`、`*/n`、`a-b`、`a,b` 及组合，星期 0 和 7 都是周日，机器本地时区），开关。界面上不手写表达式，用选择组件生成（见 §10.12）；接口收到不合法的表达式拒绝（`USAGE`，写明哪一段不对）。升级前的 `HH:MM` 时间点按等价的 `M H * * *` 迁移，照原时间继续触发 |
| 领取规则 | 没有 | 一个有顺序的列表，每条是「条件 → agent」，最多 20 条；最后可以再设一条兜底「其余卡片 → agent」（默认不设）。每条规则是一个条件加一组标签：`in` 带其中任一个、`all` 全都带（多出的标签不管）、`not in` 一个都不带、`equal` 标签正好是这几个（顺序无关）、`only` 标签都在这几个里面、没有别的（至少带一个）；还有一个不带标签的条件「没有标签」，匹配一个标签都没有的卡片。一条规则只有一个条件，规则之间按顺序第一条命中的生效（相当于「或」）；不提供一条规则里写多个条件、或条件之间写「或」的写法。标签按名称匹配，不区分大小写；机器可以对应多个项目的白板，哪个项目里有同名标签就在哪个项目里生效，没有同名标签的项目里按「卡片没带这个标签」算。新加或改过的规则里，标签要在这台机器有目录的项目里有、agent 要在这台机器上找得到，否则拒绝（`USAGE`，写明原因）；规则里的 agent 之后找不到了这条规则不生效，标签之后被删了照样保存，界面上都标出来。升级前的「单个标签 → agent」按等价的 `in [标签]` 迁移。定时领取和会话里的 `board next` 都按它挑卡片和 agent，一条规则都没有时不会自动领取（兜底单独设了也一样）；手动派发、`board claim` 不受影响 |

**派发**：一次「在某台机器上用某种 agent 做某张卡」，来源是手动或定时。开始时把用的启动环境，以及机器设置里选的模型、思考强度（旧版 `board host` 不记）写进派发记录，`board host` 按记录启动；卡片动态的「派发开始」写明模型和强度（例如「派发开始：mbp 上的 Claude Code（登录 shell）以 claude-mbp/sonnet 领取（手动，模型 sonnet，强度 high）」），机器详情的「正在跑」「最近」和卡片详情的派发说明也显示它们；`board next` 接着做的那几张沿用同一个模型和强度。设置了模型时，派发的 agent 名字第二段用它。状态：排队 → 在跑 → 结束；结束的结果是已交审、做不下去、异常退出、超时、已停止、已取消、机器掉线、没领到之一。派发、取消、开始、结束都在卡片动态里追加一条，写明机器、agent、来源和结果。派发记录一直保留。

**手动派发**：卡片详情的「派发」或 `board dispatch`。不满足下列条件时拒绝，不产生派发：

| 条件 | 错误码 |
|---|---|
| 卡片不在可领取状态 | `NOT_IN_TODO` |
| 卡片已经有排队或正在跑的派发 | `ALREADY_DISPATCHED` |
| 机器不存在（含已移除） | `NO_SUCH_HOST` |
| 机器上没有这种 agent，或在它设置的启动环境里没找到 | `AGENT_NOT_ON_HOST` |
| 机器没有这块白板的目录 | `BOARD_NOT_ON_HOST` |
| 机器上这块白板的环境检查没通过，或还没检查 | `BOARD_NOT_READY` |

派给离线、已满、暂停接单的机器时排队。

**占用**：派发排队时（手动派发、定时领取的会话里排着的都算），卡片就沿连线进入领取时会进的锁定状态（默认工作流是「进行中」），排在那一块被持有的卡片后面，没有持有者，显示排队（§10「白板上的卡片」）：它已经交给了这台机器，不再是谁都能领的卡片。开始时在那里原地领取，不再移动；之后被领取进来的卡片排在排队的卡片前面。

- 别的 agent `board claim <ID>` 报 `DISPATCHED`，不带 ID 的 `board claim` 不会领到它，agent 也不能移动它（`DISPATCHED`）。
- 人可以照常拖动它：在这一块里调整顺序不影响派发；拖出这一块（拖回可领取状态也一样，拖到哪就放在哪）时这次派发自动取消。
- 派发没开始就结束（人取消、没领到、会话结束时还排着、移除机器）时，卡片回到原来的可领取状态最上面（和释放一样，§8 规则 7）；几张一起回去时仍按原来的先后。
- 删除后从回收站恢复：回到原来的可领取状态（§8 规则 10，和被删时还在做的卡片一样）。
- 锁定状态被删除时，排队的卡片和别的卡片一样移到首个可领取状态，派发继续排队，开始时照常从那里领取。

**定时领取**：到了任一条 cron 表达式的时间（同一分钟有几条到点也只开始一轮），机器在线、没有暂停接单、并且至少有一条领取规则时开始一轮。一轮里有空位就开一个会话（一个 agent 进程），开会话时把它要做的卡片一次排好：

1. 第一张：在这台机器有目录、环境检查通过（或不检查）的白板上，按 §8 规则 1 的顺序取第一张按领取规则会交给这台机器的 agent 的可领取卡片。它定下这个会话的白板和 agent。
2. 后面几张：从同一块白板上、按领取规则交给同一个 agent 的可领取卡片里再取，连第一张一共最多「一个会话最多做几张」张，不够就少几张。先后顺序：先是带优先标签的（按 §8 规则 1 的顺序），再是其余卡片：和第一张共同标签多的在前（领取规则里用到的标签不算，它只表示谁来做），一样多时按 §8 规则 1 的顺序。
3. 第一张马上开始（下面「执行」）；后面几张各记一条排队的派发，属于这个会话，卡片和别的排队一样进入锁定状态（上面「占用」），动态写「派发到 <机器> · <agent>（定时），会话第 N/M 张，在「<锁定状态>」排队等 <名字> 接着做」。会话里排着的派发不占空位，不按「执行」的先后开始，只由这个会话的 `board next` 一张一张开始（下面「会话接着做」）。

第 1、2 步都跳过已有排队或正在跑的派发的卡片（包括别的会话排着的），以及这一轮里这台机器已经派发过的卡片（会话结束时还没轮到、被取消的排队不算）。开完一个会话还有空位，就照样开下一个；每有一个会话结束、还有空位时再开一个；所有白板上都没有符合规则的卡片、这台机器也没有会话还排着卡片时这一轮结束（会话中途结束时排着的会被取消，这一轮要能由新开的会话重新排）。所以卡片少时先把一个会话排满，而不是同时开几个会话各做一张：同时跑 4 个、一个会话最多做 4 张时，4 张卡开 1 个会话；6 张开 2 个（4 + 2）；16 张开 4 个；20 张先开 4 个，剩下 4 张等有会话结束、空出位置再开。多块白板时按 `--dir` 的顺序轮流，一块白板开一个会话再换下一块。一轮还没结束时又到点，不重复开始；到点时机器离线或暂停接单，这次跳过，上线后不补。机器详情里的「现在领一轮」效果与到点相同，没有领取规则时也不能开始。

一条领取规则都没有（兜底不算）时不会自动领取：到点不开始这一轮，正在跑的一轮领卡时直接结束，已经在跑的会话再用 `board next` 也返回 `SESSION_DONE`；手动派发、`board claim` 不受影响。有规则时：按顺序找第一条命中的规则，用它的 agent（第一条命中的规则不生效时不领这张）；一条都没命中的卡片，设了兜底时用兜底的 agent，没设时不领。候选卡片之间的先后仍按 §8 规则 1（含优先标签），不因为走的是兜底就排到后面。没有匹配的卡片（也没设兜底）时这一轮结束，即使白板上还有别的可领取卡片。

**执行**（机器在线、没有暂停、有空位时，按派发创建的先后开始；会话里排着的派发不在这里开始，见「会话接着做」）：

1. 生成 agent 名字（§3.2），check 这个名字，再以它领取卡片。领取失败（卡片已被领走、已不在可领取状态）时这次派发结束，结果「没领到」，不启动 agent。
2. 领到后，`board host` 以这个名字发心跳（每 10 秒），直到派发结束。
3. 在这块白板对应的目录里、按这个 agent 的启动环境启动 agent（用的启动环境写进派发记录，卡片动态里写明，例如「派发开始：mbp 上的 Claude Code（Git Bash）以 claude-mbp/opus-5.5 领取（手动）」）：提示词是 `/board-skills 开始执行 <项目>项目之中的<白板>白板中的#<ID>任务`，后面再带一句 board host 身份提示（`BOARD_AS=<名字>`、`BOARD_HOST=<机器名>`，卡片已由它领取，不要 check、claim、心跳，不要创建 goal；交审或交给人之后执行 `board next --json`，领到卡片就接着做，返回 `SESSION_DONE` 就结束）；环境变量带上 `BOARD_URL`、`BOARD_TOKEN`、`BOARD_AS=<名字>`、`BOARD_HOST=<机器名>`、`BOARD=<项目>/<白板>`，以及 `BOARD_CONFIG`：这次派发自己的配置文件（地址和令牌，0600，派发结束时删除），给不把名字像密钥的环境变量传给命令的 agent 用；`BOARD_EXE`：`board` 自己的路径，`board-skills` 的 `scripts/board` 优先用它，版本和 `board host` 一致。`board-skills` 看到 `BOARD_HOST` 且卡片已由 `BOARD_AS` 持有时，不再 check、不再领取、不启动也不停止心跳，其余步骤不变。
4. agent 的标准输出和标准错误写到 `~/.board/host/logs/<派发 ID>.log`。内置模板都用 agent 的结构化输出（事件流，JSONL）启动：Claude Code `--output-format stream-json --verbose`、Codex `exec --json`、pi `--mode json`、dsh `--json`（dsh 从 0.2.2 起才有这个参数，本机版本更旧时不加）；配置文件覆盖了命令的 agent 用配置文件写的命令，不加参数。本机日志文件里存原样的输出，`board host` 拿它做两件事：
   - 原始输出：每 5 秒上传新增的行（一次最多最后 500 行），服务端每个派发保留最后 500 行。是转写后的一行一行（agent 说的话、`▸ 工具 参数`、`↳ 结果第一行（共 N 行）`、`✗ 出错`、`■ 结束 · 用时 · 轮数 · 费用`；流式片段、状态变化不显示；不是 JSON 的行原样保留；每行最长 400 个字符）。没有事件流的 agent 原样上传。登录 shell 自己打的启动、退出提示（作业控制提示、`logout`、发行版 bashrc 的 sudo 提示）不是 agent 的输出，不上传（#232）。
   - 结构化事件：逐行解析成统一的事件——`message`（agent 说的话，Markdown）、`tool`（工具名、参数摘要、结果摘要、退出码或是否出错）、`error`（出错信息）、`result`（结束时的结果文字、用时、输入 / 输出 tokens、费用，agent 输出里有才记）；解析不了的行记成 `text`，原样保留。每 2 秒上传一次新增的事件（`POST /api/dispatches/<ID>/events`，带上这个 agent 的输出格式；没有事件流的 agent 只报格式为空）。工具调用和它的结果分两次上传时服务端合成一条。服务端按派发保存：每个派发最多 2000 条（多出来的删最早的，记下删了几条），单条超过 4 KB 截断并标明；派发结束 30 天后只留 `result` 和最后 50 条。有新事件时实时推送带上这些派发，会话页打开着就增量取、马上追加。

   会话里换到下一张后，进程的原始输出和事件都记到当时正在做的那张卡的派发上。上传到服务端、写进异常退出评论之前脱敏：当前令牌、这次派发注入的 `BOARD_TOKEN` 等密钥值，以及常见格式的密钥（`sk-…`、`ghp_…`、`github_pat_…`、`xox…-`、`AKIA…`、`-----BEGIN … PRIVATE KEY-----` 整段、`Authorization: Bearer …`）都换成 `<已隐藏>`；本机日志保留原文，文件权限 0600。单个本机日志超过 50 MB 时只留开头 1 MB 和最后 10 MB（中间一行省略说明）；结束超过 30 天的本机日志在 `board host` 启动时和之后每天删一次，天数用 `[host] log_days` 改。

**会话接着做**（`board next`）：同一个 agent 进程做的几张卡算一个会话，每张卡各有一条派发记录。agent 交审或交给人之后执行 `board next`，服务端在一个写事务里：结算上一张的派发 → 按排好的顺序取这个会话排着的下一张 → 以同一个名字领取 → 这条派发开始（同一台机器、同一个 agent、同一个启动环境，来源定时；卡片动态写「派发开始：…以 <名字> 接着做（定时，这个会话的第 N 张）」）。领取失败（卡片已被领走、已不在可领取状态）时这条派发结束，结果「没领到」，接着取再下一张。会话占一个空位直到进程退出，取下一张不看「同时跑几个」。开会话时排好之后不再往里加卡：之后新建的、新打上优先标签的卡片由别的空位或下一轮领。

- 返回 `SESSION_DONE`：这个会话排着的卡片都开始过或取消了；会话是手动派发启动的；有人停止了这个会话；机器暂停接单或已被移除；机器已经没有领取规则。
- 上一张还由这个名字持有时拒绝（`ALREADY_HOLDING`）。
- 取下一张时结算上一张：卡片在交审状态记「已交审」，在其他状态记「做不下去」。进程退出时只结算它最后一张，规则同下面的结束表；人停止会话里正在跑的派发时，结束整个进程，当前这张按「已停止」处理。
- 会话不再接着做时（`board next` 返回 `SESSION_DONE`、进程退出、被人停止、机器掉线、机器被移除），这个会话还排着的派发都取消，结果「已取消」，卡片回到原来的可领取状态最上面（仍按排好的先后）；这一轮还没结束、有空位时，由新开的会话按「定时领取」的规则重新排。
- 人可以单独取消会话里排着的一张（卡片详情、机器详情里的「取消派发」，或 `board dispatch <ID> --cancel`），也可以把它拖出它排队的锁定状态（派发自动取消）：这个会话跳过它，接着做排在后面的；人取消的那张这一轮里不再排进别的会话。

**结束**（「交审状态」「需要人处理的状态」按 `board-skills` 认角色的规则识别：规则、连线、状态名称里的关键词；「错误节点」看状态的「错误节点」开关，§7）：

| 情况 | 卡片 | 派发结果 |
|---|---|---|
| agent 退出，卡片已不被这个名字持有，在交审状态 | 不动 | 已交审 |
| agent 退出，卡片已不被这个名字持有，在其他状态 | 不动 | 做不下去 |
| agent 退出（任何退出码），卡片仍由这个名字持有 | 发 final，沿连线移到错误节点（打开了「错误节点」开关的状态，§7；默认工作流没有，按需自己建）。没有错误节点时去需要人处理的状态（默认工作流是「需人工校验」）。评论「agent 异常退出（退出码 N）」，接着是最后 10 个事件的文字（工具名加结果摘要、agent 最后说的话），原始输出的最后 20 行附在后面、默认折叠；没有结构化事件的 agent（和旧版 `board host`）照旧写日志最后 20 行 | 异常退出 |
| 人停止（界面上点「停止」或 `board dispatch <ID> --cancel`）：结束包括启动环境外壳在内的整个进程树（先 SIGTERM，10 秒后 SIGKILL；Windows 结束进程树；WSL 里在 WSL 中结束 agent 的进程组） | 同上一行，评论写「<人> 停止了这次派发」 | 已停止 |
| 到了机器的兜底设置（单次最长运行、没输出多久算卡住）：`board host` 按上一行的流程结束整个进程树，上报 `how: timeout` 和原因 | 同「卡片仍由这个名字持有」一行，评论写明原因（「运行超过 3 小时，board host 停止了它」或「20 分钟没有任何输出，board host 停止了它」），后面和上面一样写最后 10 个事件和折叠的原始输出（没有事件时写日志最后 20 行）。这一次领取记「超时」，大盘「按 agent」里算进异常退出（§10.13） | 超时 |
| agent 退出、人停止或到了兜底设置，但工作流从当前锁定状态连出去的状态里既没有错误节点也没有需要人处理的状态 | 不动，评论写明没有能接住异常退出的状态、卡片 50 秒后会回到「<可领取状态>」最上面（有错误节点 / 需要人处理的状态、只是连不出去时同样写明）；这一轮定时领取不会再领它 | 异常退出 / 已停止 / 超时 |
| 人取消排队中的派发 | 回到原来的可领取状态最上面（上面「占用」） | 已取消 |
| 机器掉线超过 50 秒 | 按心跳超时规则释放（§8 规则 7）；那台机器上的 agent 推集成分支前用 `board hold` 确认领取，失效了就改推 `wip/<白板>/<ID>` 分支，不推集成分支 | 机器掉线 |
| `board host` 在 50 秒内重启，派发还在跑、本机没有对应进程 | 同「卡片仍由这个名字持有」 | 异常退出 |

- agent 的主进程退出后，同一进程组里剩下的进程（agent 起的子进程）一起结束（Windows 除外）。
- `board host` 没走完退出流程（被 `kill -9`、崩溃）时，它启动的 agent 还在跑：每个 agent 的进程号和启动时间记在 `~/.board/host/run/<机器名>/<派发 ID>.proc`，同名重启、第一次上报成功后，先结束这些还对得上的 agent 进程组（WSL 里在 WSL 中结束），再清理上一次的派发配置文件；这些派发按上一行记「异常退出」。同名的 `board host` 正在线时，第二个只报 `HOST_NAME_TAKEN`，不动前一个的文件。
- `board host` 的标准输出写不进去（管道读端已关、终端已关）时照常运行；退出时照样先结束 agent 再离线。

**移除机器**：取消它所有排队中的派发，停止正在跑的派发，删除机器设置；派发记录保留，界面上显示为「已移除的机器」。之后这台机器的 `board host` 再连上来，按新机器建立设置。

## 10. 界面

### 10.1 整体布局

- **顶栏**：品牌、项目 / 白板切换器、搜索（命令面板入口）、在线的 agent 头像组。
  - 命令面板（`⌘ K` / `Ctrl K`、`/`）：输入内容后列出当前白板的卡片（按标题、描述、`#ID` 搜），命令和跳转项按关键字过滤；同时在所有白板（含「未整理」）里按标题、描述、评论搜一遍，当前白板以外的结果单独一组「其他白板」，每条写出白板路径、状态和标签。选中其他白板的卡片后切到那块白板、打开这张卡片。识别 `#ID`、`项目/白板#ID`、`label:<标签>` 三种写法，搜 `#12` 时列出所有白板里编号是 12 的卡片。搜索请求由服务端完成（`GET /api/search`），输入停下约 0.2 秒后发一次。
  - 头像组显示所有在线 agent（§3.2），不分白板：check 之后头像出现，离线后消失。
  - 持卡的 agent 头像外圈是心跳波纹，悬停时展开，显示这一次的耗时；提示文字是「<名字> 正在做 <项目>/<白板>#<ID>」，做过不止一次时加上累计耗时。没持卡时不跳波纹，悬停展开和提示文字只写「在线」（「<名字> 在线」）。
  - 侧栏「正在工作」和卡片上的持有者只显示持卡的 agent。
- **左侧操作台**：活动栏 + 侧栏。活动栏从上到下六个 Tab：白板、未整理、大盘、项目、机器、设置（设置固定在底部）。再次点击当前 Tab 收起或展开侧栏，每个 Tab 分别记住展开或收起；侧栏宽度可以拖动调整。
- **主内容区**：在右侧，显示当前白板、项目画布或设置页。
- 活动栏图标上不显示数量徽标。
- **网址**：白板、卡片、各个 Tab 都有自己的地址，刷新、收藏、发给别人都能回到同一个画面。
  - `/<项目>/<白板>` 打开这块白板；`/<项目>/<白板>/<ID>` 打开这块白板并弹出这张卡片的详情（「未整理」里的条目也一样）。
  - 打开卡片、关闭卡片、切换白板时地址栏跟着变：打开和关闭详情用 push（浏览器后退能关掉、再打开），在详情里切上一张 / 下一张用 replace（不一张张回放），切换白板用 push（后退回到原来那块）。
  - 浏览器后退、前进能关闭或重新打开详情，也能回到上一块白板；刷新后保持原样。地址里的白板不在了（被删掉）时换成上次打开的白板。
  - 其他 Tab（未整理、大盘、项目、机器、设置）的地址是 `?tab=<标识>`，带着当前白板；刷新后回到同一个 Tab、同一块白板。
  - 卡片详情顶部的「复制链接」复制这张卡片的完整网址（服务端地址 + 路径）。
  - 描述和评论里的卡片编号是链接：`#123` 指向本白板的卡片，`<项目>/<白板>#123` 指向那块白板的卡片；悬停显示标题和状态。卡片不存在时不变成链接，代码块里的不处理。点击在当前窗口打开，不开新标签。
  - CLI 的 `board show`、`board new` 输出这张卡片的网址（`--json` 里是 `url` 字段）。
  - 服务端把所有不认识的路径都返回界面（单页应用），所以网址直接打开、刷新都行。
  - 桌面端：页面里的卡片链接在桌面端窗口里打开，不交给系统浏览器。
- 手机上，活动栏变为底部 Tab 栏；白板各状态左右滑动切换，顶部有状态切换条，工作流图默认收起成一行入口（「工作流 · N 个状态」），点开再看；白板页头有「筛选」按钮，打开底部抽屉：筛选框、标签（点击筛选）、正在工作、最近动态（和桌面侧栏的白板部分一样，点卡片编号打开详情），可下拉、点遮罩或 `esc` 关闭；筛选生效时页头单独一行写「筛选「…」「<标签>」· N 张」，可一键清除；「项目」Tab 占满内容区，显示项目树；「未整理」Tab 显示「未整理」页（§10.5），筛选框和「记一条」放在页头下面。
- 桌面端：窗口打开 Board 服务端的页面，与网页端同源。点「用 GitHub 登录」在系统默认浏览器里登录，登录完成后桌面端自动进入白板。顶栏同时是窗口标题栏，可以拖动窗口；Windows 上没有系统标题栏和菜单栏，最小化、最大化、关闭按钮在顶栏右侧。
  - 连哪个服务端依次取：环境变量 `BOARD_URL` → 配置文件 `~/.board/config.toml` 的 `url`（和 `board` 命令行同一项）→ 构建时注入的默认地址（`BOARD_DEFAULT_URL`）。代码里不写死地址，不注入默认地址的发布版第一次打开是「连接服务端」页。
  - 「连接服务端」页（和启动页同一套样式，首次打开、还没连过服务端时出现）：填地址（`localhost:7420` 这类没写协议的按 `http://` 补全），先请求 `<地址>/api/health`，返回 `{"ok":true}` 才认作 Board 服务端——不是 Board 的地址（反向代理、别的网站、连不上）当场报错，什么都不写。通过后把地址写进 `~/.board/config.toml` 的 `url`，关掉这个窗口、按这个地址打开它的登录页或白板。
  - 配置文件里已经有 `url` 时直接打开它，不再问。
  - 本机命令（登录、一键写入配置、接任务、更新等）只对当前这个地址的页面开放：`capabilities/default.json` 只放行启动页，启动和换地址时按当前地址另外放行同一份权限（注入的默认地址也一样），换了地址旧地址的页面就调不到本机命令。
  - 桌面端窗口不跟随环境变量变化：改配置文件里的地址后，重新打开桌面端生效。
- 主题：跟随系统 / 浅色 / 深色。
- 可读性（浅色、深色主题都满足）：要读的文字对比度 ≥ 4.5:1（≥ 18.66px 或 ≥ 14px 粗体的 ≥ 3:1），分隔符、图标、禁用态除外；agent、状态、项目、品牌色写成文字时，浅色主题下加深；品牌色按钮上的文字取白字和深色字里对比度高的那个；有信息的文字不小于 11px；可点的元素至少 24×24px，触屏上按钮和分段切换至少 36px 高；只有图标的按钮和开关都有名字（`aria-label`），开关带开 / 关状态。

### 10.2 项目 / 白板切换器（顶栏）

- 显示「项目名 / 白板名」。点击后列出所有白板，按项目分组，每块白板显示正在工作的 agent 数和可领取状态里的卡片数；可以搜索，回车切换。

- 底部有「新建白板」「项目总览」入口。

### 10.3 白板 Tab

- 侧栏：
  - 筛选框：按标题、描述、`#ID`、agent 名字、标签名筛选，不匹配的卡片淡出；输入 `label:<标签>` 只按标签筛选。
  - 「标签」：项目的全部标签块状排列，每个标签显示它在当前白板上的卡片数。点击标签即按该标签筛选，再点一次取消；按住标签拖到白板上的卡片上松手，即给这张卡片加上这个标签（卡片已有时只提示；触屏上长按后拖动；Esc 取消）；整块区域就是输入框：点空白处出现光标，输入名称后回车即新建标签。改名、改色、删除标签在命令面板和项目菜单的「管理标签」里。
  - 「正在工作」：当前白板上持有卡片的 agent、卡片和这一次的耗时。
  - 「最近动态」：当前白板最近的记录。
  - 底部「回收站 · N」：这块白板删掉的卡片数，不随上面的列表滚动。点开是回收站弹窗（下面「回收站」）。
- 回收站（居中弹窗，和卡片详情一样）：列出这块白板删掉的卡片，一行一张：编号、标题、描述的第一行、原来在哪个状态（带状态色的圆点）、谁删的、删除的时间（相对时间）。右边是还剩几天（不超过 7 天时用警告色）。
  - 每张可以「恢复」或「永久删除」（永久删除要二次确认，写明动态、评论、附件一起删掉）；勾选框可以多选，顶栏的勾选框全选，选中的可以一起恢复、一起永久删除。
  - 恢复后卡片回到原来的位置，提示「已恢复 #N」，并定位到它。删除后的提示里也有「撤销」，效果和恢复一样。
  - 回收站是空的时写明「删除的卡片会先放在这里，30 天内可以恢复」。
- 主内容区：页头显示白板名（项目只在顶栏出现一次）和「新建卡片」按钮。下面依次是工作流条和状态块。
- 工作流条：把工作流画成有向图，大约两行半高。
  - 第一行是主线：从首个可领取状态出发，沿连线走到终点状态的那条路；其余状态排在第二行，居中对齐到连向它的主线状态下面。
  - 连线是直角折线，箭头表示方向；两行之间的横线自动错开、不重叠。主线末尾是「+ 添加状态」，用虚线连接，输入名称后回车即新增（加在最后，还没有连线）。
  - 每个状态显示卡片数，以及可领取、锁定、终点、错误节点的标记；可领取状态没有连到锁定状态时显示提示。
  - 鼠标放到状态上时，与它相连的连线高亮，状态右边缘出现一个圆点。
  - 连线：按住圆点拖到另一个状态上松手，即连一条线；已经连过的状态显示为已连接，松手不会重复连。
  - 改连：按住一条连线的箭头，拖到另一个状态上松手，这条连线改为指向那里；拖到空白处松手，即删除这条连线。点击连线选中后，按 `Delete` 或点 × 也能删除。
  - 拖动状态调整顺序。
  - 点击状态打开设置：名称、颜色、卡片形态、四个规则开关（可领取、锁定、终点、错误节点）、删除（要二次确认，并写明卡片会移到哪里）。
- 状态块：每个状态是一个块，块的高度随卡片数量变化，标题旁显示顺序号、卡片数和规则说明；白板设置开着「保留顺序」时还显示这块的排序依据和方向，点击打开白板设置并定位到这个状态。
  - 交审状态（锁定状态连出去、等人审核的状态，规则同 board-skills「认出角色」）的块标题上有「复盘」，需要人处理的状态（错误节点，和名字里带「人工」这类关键词的状态）上有「处理」，块里有卡片时才显示，点开复盘台（§10.14）。
  - 拖动块的标题摆放位置：块吸附到 12 栏网格上，并向上贴紧上方的块，块之间不留空隙；拖动块的右边缘调整宽度（按网格吸附）。块变宽后，块里的卡片排成多列。
  - 默认布局：每块占 3 栏，一行 4 块。前 4 个状态并排在最上面，第 5 个起按工作流顺序依次放到第 1、2、3、4 栏下面（第 i 个状态放第 i mod 4 栏）；位置只由顺序决定，不随卡片数变化。保存过布局的白板新增状态时同样按顺序放栏。
  - 布局按白板保存在数据库里，并同步到所有窗口。
- 白板设置：工作流条末尾的「白板设置」，每块白板自己的设置，保存在数据库里，同步到所有窗口和机器。打开后是居中弹窗，和卡片详情一样：左边是设置，右边是预览；手机上是底部 sheet，预览在上面。每一项改动立即生效，保存状态显示在那一项旁边，不禁用别的设置。
  - 卡片顺序：
    - 保留顺序（开关，新白板默认关）：开着时每个状态块按自己的排序依据排列，界面上拖动改不了顺序。拖到别的状态时，卡片放到那一块优先级的最后；在同一块里拖动不改顺序。松手后卡片先落在松手的位置，再补间到按排序依据该在的位置。关着时拖到哪就在哪，顺序按拖动的结果保存。只管界面上的显示和拖动：CLI、`board claim` 的领取顺序和「下一张」都按优先级，不受影响。
    - 每个状态的排序依据：移入时间（默认，新移入的在最后）、编号、最近更新、标签（按项目里的标签顺序，没有标签的排最后，不分方向）、累计耗时，各自可以切换方向；相同的按优先级排。移入时间是卡片移入现在这个状态的时间：新建、移动、领取、释放都算，同一状态里调整顺序不算。保留顺序关着时这些依据保留，但不生效。
    - 预览：鼠标放到一个状态上，预览用示例卡片演示拖动的结果，「拖到别的状态」「同一状态里拖动」两种轮流放，可以重放；锁定状态不演示（卡片只能由 agent 领取进入）。
  - 状态块布局：现在的布局、保存的布局、默认布局三张缩略图，按块的位置、宽度和卡片形态画，按钮在各自的图下面。「保存为白板布局」把现在状态块的位置和宽度存成这块白板的布局（不改现在的布局）；「应用」把现在的布局换成存下的；「复原」回到默认布局，存下的布局保留，可以再应用。和现在一样的那张标出「和现在一样」，按钮不可点。鼠标放到保存的或默认的布局上，预览里状态块在「现在」和「换过去以后」之间来回移动，虚线框是现在的位置。保存之后删掉的状态应用时跳过，新增的状态按默认布局的规则补位。
  - 升级前关着「保存顺序」（同一块里不能拖动排序）的白板打开保留顺序，其余白板关着；升级前的状态都按移入时间。
  - 代码仓库（§4）：仓库地址、集成分支两个输入框，失焦或回车时保存，留空表示没设。仓库地址没设、又有机器上报过这块白板目录的 `origin` 时，输入框里把它作为建议，旁边一个「用机器的 origin」按钮；设了之后下面写推出的仓库网页地址。集成分支旁边写明留空时按仓库的 AGENTS.md / CLAUDE.md。
  - 环境检查（§9.1）：「所有系统」「Windows」两个输入框，失焦或回车时保存，留空表示不检查；下面列出「能接这块白板的机器」：每台有这块白板目录的机器一行，写在线还是离线、系统、环境检查结果（通过 / 没通过 / 还没检查 / 不检查）、上次检查时间、目录，没通过时写输出的最后一行，点一行打开机器详情。一台都没有时写「还没有机器能接这块白板的卡」，并给出去机器「白板与目录」的入口；大盘这块白板的总览里也显示同样的提醒（§10.13）。机器详情「白板与目录」每一行下面也写这块白板的环境检查结果。
  - 终点状态的卡片只增不减：打开白板时每个终点状态只带最近移入的 50 张（按移入的时间，不看排在哪里），仍按块里的顺序显示，块的标题和工作流条上仍显示总数；块里最后一格是「更早的 M 张」，和这一块的卡片形态（卡片、单行、磁贴）一样大，磁贴里写成「+M」，点击后取回全部卡片并展开，这个窗口里不再收起。没取回全部时拖进这个状态，卡片落在看到的位置（挨着看到的前后两张）。筛选框有内容、选了标签、命令面板里搜索卡片、开着保留顺序且这个状态不按移入时间排时自动取回全部，更早的卡片也能找到。从动态、搜索打开更早的卡片照常显示详情。`board ls`、`board show` 和各状态的卡片数不受影响。
- 状态块里的卡片按所在状态的卡片形态显示：
  - 卡片：显示 ID、标题、评论数、标签；被持有的卡片还显示持有者和这一次的耗时（做过多次时下方显示累计耗时和第几次）；做过的卡片不在进行中时显示累计耗时、次数和「完成于 X 前」（相对时间：刚刚 / N 分钟前 / N 小时前 / N 天前，随时间刷新；悬停显示具体日期时间；没有完成时间时不显示）。
  - 单行：ID 和标题占一行；被持有的卡片右边显示持有者和心跳。终点状态里的单行前面打勾，标题划掉。
  - 磁贴：只显示 ID，横向排列，排满自动换行。同一块里的磁贴一样宽，宽度按这一块里最长的 ID 定；高 24px，手机上 36px。被持有的磁贴右上角是持有者颜色的心跳点，心跳晚了加警告色外框。鼠标放上去显示 ID、标题、标签，被持有的还显示持有者和这一次的耗时；手机上点开看详情。
  - 不带 ID 执行 `board claim` 时会被领走的那张卡片标为「下一张」（磁贴、单行用外框标出）；筛选时三种形态都是不匹配的淡出。
- 拖拽卡片可以换状态，白板设置关着「保留顺序」时还可以调整状态内顺序；拖动时显示插入位置，松手后卡片落到插入位置（开着保留顺序时再补间到按排序依据的位置，见白板设置）。拖到卡片形态、宽度不同的状态时，卡片一路变成目标状态的尺寸和形态落位。拖到不允许的状态时，该块显示禁止原因；松手后卡片回到原位，并提示原因。
- 通过 CLI 或其他窗口做的修改，已打开的界面在 2 秒内显示出来，不需要刷新页面，被改动的卡片会短暂高亮并标出是谁做的。

### 10.4 项目 Tab

- 侧栏：项目 → 白板的树。每个项目显示白板数和正在工作的 agent 数；每块白板显示正在工作的 agent 数和可领取状态里的卡片数。点击白板即打开它（切到白板 Tab）。
  - 项目行的菜单：新建白板、编辑项目、管理标签、改颜色、删除项目。
  - 白板行的菜单：打开、编辑白板、复制为提示词、复制 `BOARD=<路径>`、删除白板。
  - 画布上的节点有同样的菜单。
- 主内容区：无限画布。
  - 每个项目是一个节点，用连线连到它的各块白板节点。
  - 白板节点显示名称、路径、各状态卡片数、正在工作的 agent，以及「打开」按钮。有 agent 在工作的白板，连线显示为流动状态。
  - 拖动空白处平移；`⌘` / `Ctrl` + 滚轮或双指捏合缩放；有放大、缩小、100%、适应画布、定位到当前白板按钮。默认视图和「适应画布」的缩放不低于 75%，放不下时从左上角开始，拖动查看其余部分。
  - 拖动节点调整位置，位置会保存并在所有窗口同步。
  - 双击白板节点打开该白板；双击空白处新建项目；点项目节点右侧的「+」在该项目下新建白板。
- 新建项目：填名称、标识（根据名称自动生成，可修改）、描述、颜色、第一块白板的名称和标识。
- 新建白板：选所属项目，填名称、标识（自动生成，可修改）、描述。

### 10.5 未整理 Tab

agent 和人随时把想法、需求记进「未整理」，人在这里修改、合并、清理老条目，整理好再放进工作流。

- 主内容区是「未整理」页：当前白板「未整理」里的全部条目，一行一条，最新的在前。
  - 页头：标题、条目数，分组方式「按时间 / 按来源 / 按标签」（记住上次的选择）。按时间分为今天、这一周、更早、放了两周以上；按来源是记下它的 agent 或人；按标签按项目里标签的顺序，一条放在它的第一个标签下，没有标签的放在最后。
  - 每行显示勾选框、编号、来源头像、标题、描述的第一行文字（跳过小标题）、标签（最多两个）、记下多久了；放了两周以上的写成「N 天」并用警告色。悬停时有「整理到<首个可领取状态>」和「删除」。
  - 点一行在原地展开编辑（同时只展开一行，再点或按 `esc` 收起）：来源和时间、标题、标签、描述（和卡片详情同一套编辑器，可以粘贴截图），下面是「删除」「打开详情」「并到…」「移动到」「整理到<首个可领取状态>」。「打开详情」打开卡片详情看动态、评论和附件；「并到…」列出别的条目（标题相近的排在前面并标「相似」），选一条后打开合并预览，保留选中的那条。
  - 勾选：点勾选框，按住 `Shift` 连着勾，分组标题上的勾选框勾选整组，`⌘ A` / `Ctrl A` 全选，`esc` 取消。勾选后底部浮出操作条：已选几条、合并成一条（至少两条）、标签（勾选的条目一起加或去）、删除、整理到<首个可领取状态>、取消选择。
  - 合并预览（居中弹窗）：左边是合并后的标题和描述，可以先改；右边选保留哪一条的编号，默认是最早记下的那条。确认后按 §8 规则 11 合并。
  - 整理、删除、合并当帧生效：行在原位播离场，其余的行滑到新位置；被拒绝时回到原处并提示。整理后提示「已整理到…」，可以撤销（放回「未整理」最下面）。删除前要二次确认；删掉的条目进回收站（规则 10），删除后的提示里可以「撤销」（= 恢复，放回「未整理」原来的位置）。合并时被并掉的那几条不进回收站。
  - 别的窗口或 agent 新记下的条目出现时淡入；被别人改过的行闪一下。
- 侧栏：顶部是「记一条未整理」入口，标题旁显示条目数，有新的再跟上「· N 新」；下面是筛选框（标题、描述、`#编号`、`label:标签`）、来源（每个 agent 或人一行，带条数，点一下只看它，再点取消）、放了多久（各时间段的条数，点一下按时间分组并跳到那一组）。
- 新的条目：agent 新记下、人还没看过的条目算「新」，人自己记的不算。
  - 新条目在编号前面有一个点，标题加粗；点一行展开、在卡片详情里打开、编辑、整理进工作流、合并，都算看过，点随之消失。合并时，并进来的条目里有一条看过，留下的这条也算看过。
  - 页头标题下面写「N 条新的」，旁边是「全部标为已读」，点了「未整理」里所有的点一起消失，之后接着记下的条目照常算新。
  - 按时间分组时，新条目照常按时间排序，不单独排在一起。
  - 活动栏图标上不显示徽标（§10.1）。
  - 「看过」记在服务端（每一条记下人看过的时间），所有窗口、所有设备同步：一个窗口里看过，别的窗口收到推送后 2 秒内点也消失。
- 卡片详情的「移动到」里有「未整理」：人可以把卡片放回「未整理」最下面（被持有时不能）。

### 10.6 设置 Tab

- 侧栏：设置目录，点击跳到对应部分；「账号」排在第一。
- 主内容区：
  - 账号：当前登录的 GitHub 账号（头像、名字、账号名）与「退出登录」；本机模式下显示不需要登录。桌面端在这一节多一行「服务端」：当前连的地址、服务端版本、地址来自哪里（`BOARD_URL` / 配置文件 / 画面上选的），以及「切换服务端」
    - 「切换服务端」：填新地址，先按「连接服务端」页同样的方式校验 `/api/health`，通过后用应用内的确认框写明从哪个地址换到哪个、地址会写进 `~/.board/config.toml` 的 `url`、之后本机命令只对新地址开放；本机在跑 `board host` 时还要写明它会按新地址重启、正在跑的 agent 会结束（`board host` 只管这台机器上的接任务，不看新服务端上有没有这台机器）。取消则什么都不改。
    - 确认后写配置文件、关掉这个窗口、按新地址重新打开（没登录就显示它的登录页），`board host` 先停掉、重新打开后按新地址再启动。
    - 地址来自 `BOARD_URL` 时环境变量改不了：只写配置文件，写明重新打开桌面端后才生效。
    - 网页端、旧版桌面端（外壳没有这个命令）不显示这一行。
  - 外观：主题、卡片密度（舒适 / 紧凑）、动效（完整 / 减弱）
  - 白板规则：当前白板的工作流有向图（和白板页的工作流条同一张图：状态、连线、卡片数、可领取/锁定/终点/错误节点标记都一样；只读，不能连线、拖动、打开状态设置，窄屏时在框里横向滚动），四个规则开关的说明，以及 §8 的规则摘要
  - Agent 接入：`board-skills` 的用法（§10.9）与安装（可复制入口 SKILL.md；整个 skill 要解压 board-skills.zip 或链接目录）、`board` 命令行的安装（按系统给出说明：Windows 随桌面端装好、macOS 给一条把 `board` 目录写进 shell PATH 的命令、其他情况从源码装）、连接服务端（`board login`，§9）、错误码；快捷提示词里「做某状态里带某标签的任务」每个可领取状态一行，在行里选标签（当前项目的标签）后复制
  - 访问令牌：单独一节，在侧栏目录里；新建、列表、吊销（§3.1）
  - 新建令牌后只给一条命令：`board login --url <当前服务端地址> --token <令牌>`，不分 shell。桌面端另有「一键写入」：把服务端地址和令牌写进 `~/.board/config.toml`（效果同 `board login`），不改 shell 配置文件和系统环境变量
  - 本机（只在桌面端）：开关「让这台电脑接任务」，打开后桌面端在后台用自带的 `board` 运行 `board host`，关掉窗口也继续运行（macOS 点 Dock 图标、其他系统点托盘图标重新打开窗口），退出桌面端时结束；下次打开桌面端自动运行。下面一个开关「开机时自动启动」：登录系统时在后台启动桌面端（带 `--autostart`），「让这台电脑接任务」开着时不弹窗口，只显示托盘 / Dock 图标，照常运行 `board host`；没开接任务时照常打开窗口。打开「让这台电脑接任务」时一起打开，可以单独关掉（关掉接任务时不动它）。macOS 写 launchd 用户代理 `~/Library/LaunchAgents/dev.board.desktop.plist`（登录时执行一次 `open -g -a <Board.app> --args --autostart`，已经开着时不会多开），Windows 写注册表 `HKCU\Software\Microsoft\Windows\CurrentVersion\Run` 的「Board」一项；开关当帧切换，失败时拨回去并提示原因；旧版桌面端不显示这个开关。同一处可以编辑机器名和白板与目录（写进 `~/.board/config.toml` 的 `[host]`），显示 `board host` 在不在跑和最近的输出。打开「让这台电脑接任务」、修改白板目录时，先用 Board 应用内的确认提示框列出机器名和每个白板的目录与免审批运行的风险，确认后才生效，取消则配置不变（关掉接任务不用确认）；保存设置不重启 `board host`：写完配置后通知它（标准输入一行 `reload`），它重新读配置文件的 `[host]`，换上新的机器名、白板与目录，正在跑的 agent 不受影响。别的设备改了这台机器的目录时不要求本机确认：桌面端显示最新的目录，并写「<时间> 由 <账号> 在别的设备上修改」。改机器名时先让服务端把机器记录原地改名（设置和历史派发记录保留），新名字被别的机器占用时保存失败并提示原因，配置不变。桌面端只给当前这个服务端地址（`BOARD_URL`、配置文件的 `url` 或「连接服务端」页里填的地址）的页面开放本机命令，换地址后旧地址的页面调不到；同一台电脑上只运行一个桌面端，再次打开只把已有窗口带到前面
  - 快捷键
- 窄屏（手机）下标签与控件上下堆叠：分段控件完整可见，代码块、错误码、令牌列表、白板与目录行可换行或横向滚动，页面没有横向滚动；触屏设备上输入框字号不小于 16px，避免 iOS Safari 聚焦输入框时自动放大页面。桌面端宽屏外观不变。

### 10.7 新建（居中弹窗）

- 白板 Tab 的「新建卡片」入口和未整理 Tab 的「记一条未整理」入口都打开同一个居中弹窗。弹窗大小与卡片详情相同。
- 左侧：标题（必填）、描述（Markdown，可以切换编辑 / 预览，可以插入验收标准模板）。
- 右侧：「放到」首个可领取状态或未整理（从未整理入口打开时默认未整理）、标签、等价的 CLI 命令（选未整理时带 `--inbox`）、「连续新建」开关。
- 标题里按 `↵` 创建；`⌘ ↵` / `Ctrl ↵` 在任何位置创建；`⇧ ↵` 跳到描述。标题为空时不能创建，并提示原因。
- 「连续新建」打开时，创建后清空标题和描述、保留标签，继续录入下一条，并列出本次已创建的卡片。
- 关闭弹窗时，未提交的内容保留为草稿，下次打开自动恢复，并可以一键清空。

### 10.8 卡片详情（居中弹窗）

- 点击卡片打开详情。弹窗居中，固定宽 920px、高 640px，窗口不够大时按窗口缩小；手机上从底部弹出，可以下拉关闭。
- 顶部：卡片 ID、所在状态、同状态内「上一张 / 下一张」及位置、「返回 / 前进」、「复制链接」、「复制为提示词」、关闭。
  - 「返回」「前进」是在打开过的卡片之间走（和浏览器的后退、前进不是一回事）：打开另一张卡片时（上一张 / 下一张、描述和评论里的卡片编号、命令面板和搜索里打开的卡片、切换到别的白板上的卡片）换掉当前这条地址，原来那张记进「返回」，于是能一层层退回；「前进」回到刚才返回之前看的那张。跳到另一块白板上的卡片时，「返回」先切回原来那块白板。没有可返回 / 前进的时按钮置灰；关掉详情后清空。快捷键 `⌘[` / `⌘]`（macOS）、`Alt+←` / `Alt+→`（Windows、Linux）；手机上两个按钮都留着（同状态内上一张 / 下一张在手机上不显示）。
- 左栏：
  - 标题、创建者和时间、标签（可以加或去）；
  - 被持有的卡片显示持有者、这一次的耗时、累计耗时、领取次数、心跳次数（各次领取收到的心跳之和，含 final）和异常退出次数，并有「强制释放」按钮，标题和描述只读；累计耗时、领取次数、心跳次数、异常退出写成一行；做过的卡片不在进行中时只显示这一行，并加上「完成于 X 前」（悬停显示具体日期时间），没做过的不显示；
  - 「未整理」的条目有「整理到<首个可领取状态>」按钮；
  - 「移动到」列出工作流里的其他状态和「未整理」；
  - 描述（编辑 / 预览），编辑时可以粘贴截图、拖入文件或点「附件」上传；预览里任务列表（`- [ ]`）的勾选框可以直接点，翻转描述里那一项并保存（乐观更新；卡片被持有、正在保存时不能点）；
  - 附件列表：图片缩略图（点击放大）、文件名、大小、上传者，点击文件名下载；
  - 有排队或正在跑的派发时显示派发状态：排队写「排队 → <机器> · <agent>」和原因（等空位 / 等机器上线 / 暂停接单；会话里排着的写「会话第 N/M 张」，下面一行写会话的名字和它正在做的卡片，例如「claude-mbp/opus-5.5 正在做 #12」），对应「取消派发」；在跑写机器、agent 名字和已跑时间，「会话」打开这次派发所在的会话（定位到这张卡），对应「停止」；
  - 派发记录：这张卡结束过的每一次派发，新的在前，每次一行：结束时间、机器 · agent、结果、用时，属于多张卡的会话时写「会话第 N/M 张」；点一行打开那个会话并定位到这张卡（§10.12「会话」）。没有结束过的派发时不显示这一节；
  - 底部操作栏：左边「删除」（删除前要二次确认，写明卡片会移进回收站、30 天内可以恢复；删除后卡片当帧从白板上消失，提示里可以「撤销」），右边「派发」和「移动到」。「派发」只对可领取状态里、没有派发的卡片可用，打开对话框选机器和 agent（§10.12）。
- 右栏：动态（默认显示到最新一条）和评论框；评论框里可以粘贴截图或点回形针按钮上传附件。评论发出后输入框立即清空，动态底部先显示「发送中」，服务端确认后转成正式评论，失败时原文回到输入框。人发的评论悬停时有「编辑」「删除」按钮：点编辑原地修改（⌘/Ctrl+Enter 保存、Esc 取消，空内容不能保存）；点删除要二次确认，删除后无法恢复。

### 10.9 复制为提示词

- agent 通过 skill 接入：`board-skills` 写明身份与白板的设置方法、处理卡片的步骤（先领取 → 按描述和验收标准干活、用评论记进度 → 交审；做不下去时评论原因，沿连线移到错误节点（没有时移到需要人处理的状态，例如「需人工校验」））、整理「未整理」条目的方法、§8 的规则和 §12 的错误码。skill 要求 agent 拿到卡片后第一条和这张卡片有关的命令就是 `board claim <ID>`：领取成功之前不读卡片、不看代码、不调研、不发这张卡片的进展，免得调研期间卡片被别人领走，也让耗时（从领取后的第一次心跳算起）包含全部实际工作。skill 还要求：卡片描述自包含（agent 可能在别的电脑上，不能只写本机文件路径，要把相关的需求原文写进描述）；需求里的截图、文件建卡时用 `board new --image / --file` 随卡上传；交审、做不下去时有截图、日志等证据就用 `board attach … --comment-file` 和评论放在同一条里上传，没有证据时说明原因。skill 随项目提供（`.agents/skills/board-skills/`，各家 agent 能自动识别；Claude Code 通过 `.claude/skills/board-skills` 链接识别）：入口 `SKILL.md` 只放用途、参数和快捷提示词、规则摘要、错误码总则和「按场景读哪个文件」的索引（不超过 150 行），其余按场景放在同目录的 `work.md`（会话开始和结束、处理卡片和白板、代码）、`plan.md`（卡片颗粒度、拆解和新建、整理未整理）、`host.md`（由 board host 启动的会话）、`reference.md`（工作流和认角色、常用命令、错误码），agent 做到那一步时再读。桌面端一键安装、发版的 `board-skills.zip` 都带上这几个文件。
- 复制为提示词只复制一行 skill 调用，卡片的标题、描述、动态由 agent 用 CLI 自己读取：
  - 卡片：`/board-skills 开始执行 <项目>项目之中的<白板>白板中的#<ID>任务`（例如 `/board-skills 开始执行 mini项目之中的main白板中的#2任务`），一句完整的话就说清项目、白板、卡片编号。卡片详情的「复制为提示词」按钮和 `C` 键复制这一行。
  - 白板：`/board-skills <项目>/<白板>`，agent 循环执行不带 ID 的领取，直到 `EMPTY_TODO`。项目树和画布上白板的菜单里有这一项。
- skill 的参数也可以是一句话需求：agent 先用 `board new` 记到首个可领取状态，再按卡片处理。
- 复制后提示已复制的内容。

### 10.12 机器 Tab

- 主区（机位总览）：标题「机器」、一句说明、「总览 / 对比 / 共用配置」切换（选过的记在本机；侧栏最上面一行「共用配置」也切到它，见下面「共用配置」）、「全部暂停 / 全部恢复」「全部停止」「添加机器」按钮（没有机器时不显示汇总条，侧栏的「＋」、切换和这些按钮也不显示，只留空状态里一个「添加机器」）；汇总条：在线台数 `x/总数`、在用的并发位 `x/总位数`（不算暂停和离线的机器）、排队张数（会话里排着的不算）、占用比例条；每台机器一张卡片，两列排：

  - 「全部停止」：二次确认（写明会结束几个正在跑的 agent 进程、卡片按异常退出处理、所有机器同时暂停接单），确认后停止所有正在跑的派发（和单台「停止」一样结束进程树，卡片按异常退出处理，评论写明是谁停的），同时全部机器暂停接单。同样要等服务端返回。

  - 有排队时列出排队的卡片（会话里排着的不在这里列）；
  - 底部：不放 agent 胶囊（设置里会用到的 agent 在机器详情里看）；定时领取的摘要（和机器详情里的胶囊一样，例如「每天 23:00、工作日 09:00」；没开或没设表达式时不显示）；有 agent 在用的启动环境里看不到 `board-skills` 时，一行警告色「N 个 agent 看不到 board-skills」，点击打开机器详情，鼠标放上去写明看哪里；没有这种 agent、也没有要写的摘要时，这一块不占位置。

- 会话（同一个 agent 进程用 `board next` 接着做的几张卡，§9.1「会话接着做」）：和卡片详情同一种居中弹窗，叠在卡片详情、机器详情上面，`esc` 先关它；手机上从底部弹出，按住顶部下拉关闭。头部：机器（点一下打开机器详情）、agent 图标和名称、agent 名字、启动环境、模型和强度（设置过时）、来源（手动 / 定时）、开始时间、用时、状态（在跑 / 已结束和最后一张的结果），在跑时「停止」（和机器详情里的「停止」一样）。左栏：这个会话的卡片，按先后每张一行（序号、`#ID`、标题、这一张的结果或「在跑」「排着」、用时），点一行滚到这张卡那段输出，点 `#ID` 打开卡片详情。头部还显示整个会话累计的输入 / 输出 tokens 和费用（各张卡结束事件里的加起来；agent 输出里有才显示）。主区按卡片分段，每段标题是 `#ID 标题` 和结果，默认显示「过程」（§9.1「执行」的结构化事件）：agent 说的话按 Markdown 渲染；每个工具调用占一行（图标、工具名、参数摘要、成功 / 失败 / 在跑），有结果时点开看结果摘要、退出码；连续的读文件、搜索类调用折叠成一行（例如「读了 3 个文件、搜索 2 次」），点开列出每一次；出错一行用警告色；解析不了的几行合成一段等宽文字；子 agent 里的事件缩进；`result` 画在这张卡那一段的末尾（成功或出错、用时、轮数、tokens、费用，结果文字和最后一句话不同时才写）；删过事件时段首写删了几条。没有事件时写明为什么：这个 agent 没有结构化输出（只能看原始输出）、旧版 `board host` 没记录过程、还没有事件、排着，带「看原始输出」。右上角可以切到「原始输出」：每个派发最后 500 行转写后的输出，和以前的日志一样。事件第一次全取，之后带 `since` 只取新增、改过的：推送里有这个会话的派发时马上取，在跑时另外每 5 秒取一次；滚在底部时跟着新内容，往上翻时位置不动。从卡片打开时定位到那张卡的一段。接口：`GET /api/sessions/<任一次派发的 ID>[?since=<runs>]`（会话的全部派发、各自的输出和事件，`runs` 是事件的版本）、`GET /api/dispatches?board=<白板>&card=<ID>`（一张卡的全部派发，新的在前），只能在登录后的界面上用。
- 共用配置：所有机器共用的配置，第一节是 skills 共用库，第二节是 MCP 服务器，第三节是 agent 模板。
  - 库在服务端：每个 skill 是一个目录（`SKILL.md` 加上它带的文件，合计最大 5 MB），版本号是内容的哈希（按路径排序后对路径、可执行位、内容做 SHA-256 取前 12 位），记录更新时间、来源（哪台机器，或「界面」）、谁上传的。`board-skills` 是固定的第一项：内容随服务端版本（编译服务端时打包进去，不含 `bin/`），不能删、不能改；`bin/<平台>/board` 由各台 `board host` 用自己的 `board` 填上（WSL 里不放，那里用 PATH 里的 Linux 版）。

  - 同步：`board host` 启动时、库变了时、重新检查或桌面端重新读配置后、没变化时每 10 分钟，在后台把库里的 skill 写进本机每个找到的 agent 读用户级 skill 的目录（内置模板的第一个：`~/.agents/skills`、`~/.claude/skills`、`$CODEX_HOME/skills`；几个 agent 共用一个目录时写一次；WSL 里的 agent 写到 WSL 用户目录下，经 `\\wsl.localhost\<发行版>\…`）。先写进同一目录下的临时目录，写完整体换上；目录里放标记文件 `.board-sync`（名称、版本）。只动带标记的：本机已有同名、没有标记的目录（包括开发用的链接）不覆盖，状态写「本机有同名，没有覆盖」；`board-skills` 例外——不是链接的旧拷贝（以前桌面端一键安装、解压 `board-skills.zip` 装的）换成同步装的。库里删掉的、带标记的删掉。同步结果按 agent、skill 逐项随上报带给服务端（已同步、版本落后、本机有同名没覆盖、失败及原因），旧版 `board host` 不带。装上、换掉了东西后重新检查各 agent 看不看得到 `board-skills`。

  - MCP 的同步：`board host` 和 skills 一样的时机，在后台按每个 agent 自己的方式写进它的用户级配置：Claude Code 在它的启动环境里执行 `claude mcp add-json --scope user <名称> <JSON>`（改的时候先 `claude mcp remove --scope user <名称>`；`~/.claude.json` 它自己经常改写，只读它判断已有哪些）；Codex 改 `$CODEX_HOME/config.toml`（默认 `~/.codex`）的 `[mcp_servers.<名称>]`（`command`、`args`、`env` 或 `url`、`http_headers`），保留文件里别的配置和注释；pi 改 `~/.pi/agent/mcp.json` 的 `mcpServers`（`command`、`args`、`env` 或 `url`、`headers`）；dsh 和配置文件里的 agent 写「不支持」。WSL 里的 agent：文件经 `\\wsl.localhost\…` 改，Claude Code 的命令在 WSL 里执行。只增删改同步加进去的条目：加过哪些记在本机 `~/.board/host/mcp-sync.json`（agent → 名称 → 版本），不改条目名称、不往 agent 配置里加标记；配置里已有同名、不是同步加的，不覆盖，状态写「有同名，没有覆盖」；共用列表里删掉的（或不再同步给这个 agent 的），同步加的那条删掉，用户自己加的不动。结果按 agent、服务器逐项随上报带给服务端（已同步、有同名没覆盖、不支持、失败及原因），旧版 `board host` 不带。
  - MCP 的界面：标题「MCP 服务器」、一句说明，右边「添加」和桌面端才有的「从本机导入」。列表每行：展开箭头、名称、类型、命令和参数（或地址）、同步给哪些 agent（或「所有支持的 agent」）、更新时间、汇总「N/M 台已同步 · K 台有问题 · J 台不同步」、修改、删除（二次确认：写明各台机器上同步加的那项会被删掉，agent 里用户自己加的不受影响）。展开：环境变量 / 请求头（密钥写 `••••<末尾 4 位>（密钥）`），每台机器一行、每个 agent 一格：已同步 / 有同名，没有覆盖（写明哪个文件里有）/ 不支持 / 失败及原因 / 正在同步；旧版 board host 写「board 版本太旧，不同步」。添加、修改是同一张表单：名称（修改时不能改）、类型、命令、参数（一行一个）或地址、环境变量或请求头（名字、值、「密钥」勾选框；密钥的值框是密码框，修改时显示 `••••<末尾 4 位>（不改就留空）`）、同步给（三个勾选框）、取消 / 保存；保存前在界面上校验（和服务端一致），不对时提示原因、表单留着；保存时按钮转圈、禁用直到返回。「从本机导入」：读出这台电脑上 Claude Code（`~/.claude.json` 顶层）、Codex、pi 已经配好的 MCP 服务器（同步加的不列；名字像密钥的环境变量、请求头——带 TOKEN、KEY、SECRET、PASSWORD、AUTH 等，和 `Authorization`——标成密钥，值一起带上），列成勾选清单（共用列表里没有的默认勾上，有同名的写「会换成这个」），「导入所选」一项项加进共用列表。
  - agent 模板：在界面上接入新的 agent，或者改内置 agent 的命令，不用一台台改配置文件。每个模板：标识（同 agent 标识的规则）、名称、命令模板（第一个是命令，正好一个 `{prompt}`）、默认模型（派发名字的第二段）、传模型的参数（要有 `{model}`）、传思考强度的参数（要有 `{effort}`）和能选的档位、Windows 上支持的启动环境（`pwsh`、`powershell`、`git-bash`、`wsl:*`、`cmd`、`direct` 里按顺序选）。和内置 agent 同标识的覆盖它，没写的项沿用内置的。存在服务端，版本号是内容的哈希；改了、删了算机器有变化，任务里带全部模板，在线的 `board host` 马上取到、合进本机 agent、重新检查后上报（§9.1「本机 agent」），不用重启。某台机器的配置文件里有同标识的 `[agents.*]` 时以本机为准，那台机器上这个 agent 标「本机配置覆盖」。接口：`GET /api/agent-templates`、`POST /api/agent-templates`（新增或修改）、`DELETE /api/agent-templates/{标识}`，只能在登录后的界面上用。
  - agent 模板的界面：标题「agent 模板」、一句说明，右边「添加」。列表每行：展开箭头、图标、名称、标识（覆盖内置的写「覆盖内置」）、命令模板、更新时间、汇总「N/M 台找到了 · K 台本机配置覆盖」、修改、删除（二次确认：覆盖内置的写明各台机器换回内置命令；新加的写明各台机器不再有它，用它的领取规则标成不生效）。展开：默认模型、传参写法、Windows 启动环境，每台机器一行：找到了（版本）/ 没找到命令 / 本机配置覆盖 / 还没上报 / 离线。表单：标识（修改时不能改）、名称、命令模板（一行一个参数）、默认模型、传模型、传强度、能选的强度（空格隔开）、Windows 启动环境（勾选），先在界面上校验（和服务端一样），保存时按钮转圈、禁用直到返回，失败时表单留着。
  - 机器详情「本机 agent」上方的提醒：新版 `board host` 按共用配置同步 board-skills，提醒里写同步的情况（没同步成的目录和原因）；桌面端原来的「一键安装」改成「立即同步」：本机 `board host` 在跑时通知它马上同步一次（标准输入一行 `reload`），没在跑时才由桌面端直接写。
- 自检：在界面上确认一台机器真的能干活，不用拿真实的卡片去试错。机器详情「自检」一节一个「自检」按钮（整台机器），「本机 agent」每一行（找得到命令的）各一个小「自检」按钮（只查这一个）。board host 收到请求后在后台做，不占并发位、不影响正在跑的派发；会消耗 agent 的额度，只在人点按钮时做、不定时做；同一台机器同时只做一次（做的时候按钮禁用，写「正在自检……，最长 3 分钟 · 谁 多久前请求」；机器离线时写「等机器上线后自检」；超过 15 分钟没做完的算作废，可以重新自检）。检查三类：
  - agent：在它设置的启动环境里、进一个临时目录，带上设置好的模型和思考强度，用 docs/agents.md「本机验证」那句不改任何文件的提示词跑一次（最长 3 分钟）。回答里有 `board-skills` 算通过；没登录（输出里有 `Not logged in`、`Please run /login`、`Invalid API key` 这类）、超时、回答里没有 `board-skills`（不认识 skill）、退出码非 0 分别写明。整台机器自检时只查找得到命令的 agent。
  - git：每块白板的目录依次检查是不是 git 仓库、有没有 origin，再 `git fetch origin`、`git push --dry-run origin HEAD:refs/heads/board-selftest`（只检查权限，不会真的推上去）；失败时写明是没有推送权限、没有 origin、远端仓库不存在、网络不通，附 git 输出的最后几行。只查一个 agent 时不查 git。
  - 版本：服务端收到结果时比较这台机器的 board 版本和服务端版本，落后时这一项没通过，写「board <版本> 落后于服务端 <版本>」。
  结果逐项列出：通过打勾、没通过警告色写原因（agent 回答的前几行、git 输出放在下面的小框里），每项写检查时间；标题旁写「N 项都通过」或「N 项没通过」和检查时间。结果一直保留到下一次自检：整台机器自检换掉全部结果，只查一个 agent 时只换它那一项。agent 那一行的小按钮按上次结果着色（通过绿勾、没通过警告色），悬停写上次的结论。请求和结果都记进操作记录（「请求自检」「自检通过（N 项）」「自检：<哪几项> 没通过」）。旧版 board host 不会自检（上报里没有这一项）：按钮置灰，写「这台机器的 board（<版本>）还不会自检：先升级到 <服务端版本>」，「本机 agent」里不显示小按钮。
- 添加机器：同样的居中弹窗，写两种方法：装了桌面端的电脑在「设置 → 本机」打开「让这台电脑接任务」；只有命令行的机器用一条命令接好——选系统（macOS / Linux、Windows，默认按当前浏览器），填机器名（规则同 `board host --name`）、选要接的白板并填路径（可以加多行），点「生成命令」：界面以机器名新建一个访问令牌（按钮转圈、禁用直到返回），给出一行可复制的命令 `curl -fsSL <服务端>/install.sh | sh -s -- --token <令牌> --name <机器名> --dir <白板>=<路径> --service`（Windows 是一行 PowerShell：`& ([scriptblock]::Create((irm '<服务端>/install.ps1'))) -Token … -Name … -Dir … -Service`），值里有空格、引号时加引号。在新机器上执行这一行就依次完成：安装 `board` → `board login` → `board host --install`（§9「安装与升级」、§9.1「让机器重启后自动接任务」）；命令下面写明装成了哪种服务、异常退出 10 秒后自动重启、日志在 `~/.board/host/host.log`、怎么卸载，Linux 另写要在没人登录时运行需执行一次 `loginctl enable-linger`。令牌原文只在弹窗里显示这一次；生成后再改机器名、目录，命令跟着变、令牌不变。机器名不对、没有填目录、同一块白板写了两次时不能生成，旁边写原因。
- 派发对话框（卡片详情的「派发」）：列出所有机器，每台显示在线 / 离线、`在跑/上限`、是否暂停接单；离线、已满、暂停的机器可以选，写明「会排队」；没有这块白板目录的机器不能选，写明「没有这块白板的目录」。选机器后列出它的本机 agent（胶囊带上启动环境，例如「pi · Git Bash」），没找到的不能选，默认选中这台机器的默认 agent。选中看不到 `board-skills` 的 agent 时，胶囊带警告标记，下面显示和机器详情里一样的提醒，仍然可以派发。点「派发」后关闭对话框，卡片上出现派发状态。
- 白板上的卡片：有排队中的派发时卡片在领取时会进的锁定状态里（§9.1「占用」），画成虚线框（agent 的颜色）、没有持有者，写「排队 → <机器> · <agent>（原因）」，会话里排着的原因写「会话第 N/M 张」；在跑时显示持有者和耗时（与领取相同）。拖出那一块等于取消派发，卡片当帧落到放下的位置；取消派发时卡片当帧回到原来的可领取状态最上面。

### 10.13 大盘 Tab

在界面上看一块白板、一个项目或全部项目：这是什么、现在卡在哪、这段时间干得快不快、对不对、人是不是瓶颈、agent 靠不靠谱。数据全部由服务端统计，一次请求拿到一个范围的全部数据（`GET /api/stats`，见下文「数据」）。

**位置**：活动栏「大盘」Tab，在「未整理」后面，图标是三根柱子。

**侧栏：范围导航**

- 标题「大盘」，右边写当前时间范围（「最近 7 天」或「自定义范围」）。
- 最上面一行图例说明右边的两个数；下面第一行「全部项目」；每个项目一行（项目头像 + 名称），项目下面缩进列出它的白板。白板前面有一个点，有 agent 正在干活时是绿色。
- 每行右边两个数：黄色圆角数字是现在待复盘的张数（为 0 时不显示），右边是这段时间完成的张数。
- 点一行，大盘切到这个范围；点项目或白板时，顶栏的当前项目 / 白板跟着切换。打开大盘时默认是顶栏当前的白板。

**页头**

- 小字「大盘」，标题是范围名（白板名、项目名或「全部项目」），下面写白板标识或「N 块白板」「N 个项目 · N 块白板」，以及时区（浏览器的 IANA 时区，传给接口）。
- 右边：时间范围分段控件「24 小时 / 3 天 / 7 天 / 自定义」，默认 7 天；预设范围的结束时间是现在所在的整点（向上取整）；选自定义出现起止两个日期框（整天，含结束那天）。下面写当前区间和对比的上一周期区间；整天的区间只写日期。
- 切换范围和时间时保留旧数据直到新数据回来，不闪成空白，页头写「正在更新」。

**区块**（从上到下）

1. 总览（随范围变）
   - 白板：头部是项目头像、项目名 · 项目描述、白板名、白板描述（没有时写「这块白板还没有一句话描述」）；右边白板标识、「创建于 YYYY 年 M 月 D 日 · 已经 N 天」。一台机器都没有这块白板的目录时，头部下面写「还没有机器能接这块白板的卡」和去机器「白板与目录」的入口（§10.3 白板设置「环境检查」）。下面是上下布局：先「日历热力图」（原来「白板说明」的位置，见区块 8），再「创建以来的六个数」；「现在卡片在哪」：按状态颜色分段的横条，下面按工作流顺序列出每个状态和张数（含「未整理」）；标签（项目共用，按使用次数排，最多 8 个，带次数）；同项目的其他白板（名字、描述、卡片数，点一下切过去）。白板说明不在总览里显示（数据还在，编辑入口在白板右键菜单「编辑白板」和设置里）。
   - 项目：头部是项目头像、名称、描述、标识、创建日期、白板数、标签数；下面是「各白板」对比表，点一行切到那块白板。
   - 全部项目：「项目对比」表，点一行切到那个项目。
   - 对比表的列：名称（带描述）、待办、待复盘（大于 0 时黄色加粗）、这段时间完成（数字 + 按桶的小柱图）、交付周期中位、一次通过率、返工。
2. 现在：标题旁写「不随时间范围变 · 有推送就刷新」。左边三块：待复盘（张数、最久等了多久、「已经进了集成分支，还没人复盘」；看一块白板、有待复盘的卡时可以点，打开复盘台 §10.14）；进行中（个数、持有者，没有时写「没有 agent 在跑」）；待办（张数、最久等了多久）。待复盘最久的等了 8 小时以上时，这一块黄色底并带 ⚠。右边「正在卡着的卡」：每行状态胶囊、（项目和全部范围下）白板标识、`#ID` 标题、附注、停了多久。
3. 这段时间 · 总量：六块，每块数值下面写与上一周期的比较：完成（张数，比百分比）、交付周期 · 中位（时长，下面一行写 P85；比百分比，越短越好）、一次通过率（比差几个百分点）、返工（次数，比百分比，越少越好）、领取（次数，比百分比）、空转（时长，比百分比，越短越好）。比较写 ▲ / ▼ 加幅度，后面灰字「上一周期 X」；变好的箭头绿色、变差的红色；上一周期为 0 时只写差值，不写百分比；上一周期没有数据（比例为空）时写「上一周期没有数据」；相等时写「与上一周期持平」。六块下面一行小字：新建（上一周期）、累计耗时、评论、心跳。鼠标停在块上显示该指标的口径。
4. 积压净流量：一句话「新建 N · 完成 N · 积压减少 / 增加 N 张」（减少绿色、增加红色）；每个桶两根柱子（新建、完成），带图例；悬停显示该桶的新建、完成和净变化。
5. 交付周期：中位、P85 两个数；「中位拆开看」一条两段的横条和文字「排队等人领 X · 领取到完成 Y」；7 档直方图，柱顶写张数，中位和 P85 所在的档上方标出。
6. 趋势：一张柱状图，右上角切换指标（完成、新建、领取、返工、评论、心跳、累计耗时），写明按小时还是按天；悬停显示时段和数值。
7. agent 时间轴：横轴是当前时间区间，标出整点 / 日期刻度，当前时刻一条竖线。第一条泳道「空转」：空转时段画成斜纹块，左边写总时长。每个 agent 一条泳道（按领取次数从多到少），左边写名字、领取次数、忙了多久；每次领取画成一段，同一个 agent 同时跑的叠成多行。颜色表示结果：交审、被打回、异常退出（段尾加 ×）、做不下去、领取被释放、进行中；图例只列出现的结果。悬停显示卡片、标题、领取用的名字、开始时间、时长、结果。
8. 日历热力图 / 时段热力图（不并排）。日历在白板总览里（上面那块，见区块 1），时段热力图单独一张卡片、占满一行。日历：一列一周、周一在最上面，最近 26 周（宽度不够时从最早的一周开始少显示）；格子跟着卡片宽度放大（14–20px），当前时间区间不加框；还没到的日子只画空框；悬停显示日期和动态条数。时段：7 行（周一到周日）× 24 列，列头每 3 小时标一次；悬停显示「周三 02:00–03:00 · N 条动态」。都用同一色相由浅到深 6 档（0 单独一档），右下角图例「少 … 多」；深色主题按深色底重新取阶。
9. 卡片时间线：这段时间完成的卡片，默认最近完成的 10 张，「显示全部」最多 40 张。每行：（项目和全部范围下）白板标识、`#ID` 标题；中间是从新建到完成的分段条，每段用状态颜色，完成处一个对勾圆点；右边「从新建到完成」时长，有返工时写「打回 N 次」。横轴从这些卡片最早的新建时间到最晚的完成时间。悬停一段显示「#ID 在『状态』」、起止时间、时长。
10. 按 agent（表格）：agent（颜色方块 + 名字）、领取（带横条）、累计耗时、一次通过率、异常退出率、放弃率。一次通过率低于 75%、异常退出率或放弃率达到 8% 时红色。表下写明这三个阈值。
11. 状态停留：每个状态一行：状态色块和名称、横条（中位数为实心、平均数为竖线）、右边中位数（加粗）和「平均 X · N 次」。

区间内没有任何动态时，「现在」和总览照常显示，「这段时间」以下换成占位：「这段时间没有动态」「换一个时间范围看看，或者回到最近 7 天」和「看最近 7 天」按钮。页面上任何地方不出现 `NaN`、`0/0`、`Infinity`。

**数据**

```
GET /api/stats?scope=board|project|all&path=<项目/白板 或 项目>&from=<ms>&to=<ms>&tz=<IANA 时区>
```

- 区间左闭右开 `[from, to)`，最长 400 天；区间不超过 3 天按小时分桶，否则按天分桶，都按 `tz` 换算。`scope=project` 时 `path` 是项目标识，`all` 时不带 `path`。`scope` 不对、缺 `path`、`to ≤ from`、区间太长、时区不认识时报 `USAGE`；白板或项目不存在报 `BOARD_NOT_FOUND`。
- 项目和全部项目的数据是范围内各白板的合计；比例和分位数用合并后的样本重新算，不是各白板取平均。
- 返回里还带上每块白板、每个项目和全部项目的几个数（现在待办、待复盘、有没有 agent 在干活；这段时间完成、按桶的完成数、交付周期中位、一次通过率、返工），侧栏和对比表用。
- 卡片每换一次状态，服务端在写动态的同一个事务里记一条流转记录：移动（含整理、删除状态时卡片被移走）、领取、人强制释放、心跳中断或超时后回到可领取状态。记下状态的标识和当时的名称、操作人、时间；随卡片一起删除。升级前的数据从动态的文字里回填一次：名称按这块白板现有状态找标识，找不到（改过名、删掉了）的标识为空、名称保留；释放、超时的原来状态从这张卡片的上一条记录推出。

状态的角色（与 board-skills 认状态的规则一致）：可领取、终点、锁定看规则；需要人处理 = 锁定状态连出去、名称里带「人工」之类关键词的状态，以及错误节点；交审 = 锁定状态连出去、不是可领取 / 锁定 / 终点 / 错误节点、也不是需要人处理的状态。

| 指标 | 口径 |
|---|---|
| 新建 | 新建时间落在区间内的卡片数 |
| 领取 | 开始时间落在区间内的领取次数 |
| 完成 | 区间内移入终点状态的去重卡片数 |
| 返工 | 区间内由人或 agent 移入可领取状态（释放、心跳中断不算）、且这张卡在此之前已有领取记录的次数 |
| 评论 | 区间内的评论条数 |
| 心跳 | 开始时间在区间内的领取收到的心跳次数之和 |
| 累计耗时 | 开始时间在区间内、已结束的领取的耗时之和 |
| 交付周期 | 区间内完成的卡片，从新建到（区间内最后一次）移入终点状态的时长。中位数和 P85：升序排序后取第 ⌊q·n⌋ 个，不插值 |
| 排队 / 处理 | 交付周期拆成两段：新建 → 第一次领取、第一次领取 → 完成，各给中位数；完成前没有领取过的卡片不计 |
| 交付周期分布 | 区间内完成的卡片按交付周期分 7 档：1 小时内、1–2 小时、2–4 小时、4–8 小时、8–24 小时、1–3 天、3 天以上 |
| 一次通过率 | 区间内完成的卡片里，从新建到完成之间没有返工的比例；没有完成的卡片时为空 |
| 空转 | `[from, min(to, 现在))` 内，一块白板的可领取状态里至少有一张卡、而这块白板上没有任何进行中的领取（卡片在锁定状态或领取还没结束）的时段，单段满 15 分钟才计入；给出总时长和每一段的起止。项目和全部项目是各白板相加 |
| 积压净流量 | 每个桶的新建数和完成数 |
| 上一周期 | 以上各项在 `[from - (to - from), from)` 上的值 |
| 时间序列 | 按桶的新建、领取、完成、返工、评论、心跳、累计耗时 |
| 按 agent | 每个 agent：领取次数、累计耗时、一次通过率（它最后一次领取后完成的卡片）、异常退出次数（含超时）、做不下去的次数（界面算成异常退出率、放弃率）。由派发启动的领取按「agent 标识/机器名」合并成一行（例如 `claude/mbp`），其他按名字 |
| 状态停留 | 每个状态（终点除外，含「未整理」）：离开时间落在区间内的停留时长的中位数、平均数、样本数 |
| 热力（时段） | 7 × 24：按 `tz` 换算的星期几（周一在前）× 小时，值为区间内的动态条数 |
| 热力（日历） | 最近 26 周（从 26 周前的周一开始），按 `tz` 每天的动态条数，不受 `from` / `to` 限制 |
| 领取明细 | 区间内有交集的每次领取：合并后的名字、领取用的名字、白板、卡片、标题、开始、结束、结果。结果：还没结束为进行中；心跳中断、到了机器的兜底设置被 board host 停止（超时）为异常退出；人强制释放为领取被释放；之后第一次离开锁定状态是由它移到需要人处理的状态为做不下去，回到可领取状态为领取被释放，进了交审状态、在下一次领取之前又被移回可领取状态为被打回；其他为交审 |
| 卡片流转明细 | 区间内完成的卡片，按完成时间倒序最多 40 张：白板、卡片、标题、新建时间、完成时间、返工次数，以及从新建到完成的每一段（状态、开始、结束） |

现在（不受时间范围影响）：各状态现在的卡片数（含「未整理」）；待复盘（现在在交审状态的张数、其中进入这个状态最早的一张等了多久）；待办（可领取状态的张数、等得最久的一张等了多久）；进行中（被持有的张数和持有者名字）；正在卡着的卡（不在终点状态、也不在「未整理」的卡片，按进入当前状态的时间从早到晚前 6 张：白板、卡片、标题、状态、停了多久、附注——有持有者写持有者名字，没有时写最近一条评论的第一个非空行，最多 40 字）。

创建以来（白板和项目范围）：卡片总数、现在在终点状态的张数、返工总次数、参与过的 agent 数（按上面的合并规则）、agent 工时（全部已结束领取的耗时之和）、平均每天完成（终点状态张数 ÷ 创建以来的天数，保留一位小数）。

白板说明里贴的图片不属于任何卡片，被说明引用着就一直保留，不按「24 小时没有卡片」清理。

### 10.14 复盘台

agent 交审以后，人逐张复盘：看交审评论、对照验收标准，通过或打回一步完成。「需要人处理」的卡（错误节点、需人工校验）也在这里逐张回复后放回。

- 入口：白板上交审状态块标题的「复盘」、需要人处理的状态块标题的「处理」（§10.3）；大盘「现在」里的待复盘（看一块白板时，点开是这块白板的全部交审状态）。
- 居中大弹窗（叠在白板、大盘上面），手机上全屏。头部：「复盘台」或「处理」、状态名、「还剩 N 张」、上一张 / 下一张和「第 i / N」、关闭。卡片按进入当前状态的时间从早到晚排，一次显示一张；处理完一张（卡片离开这几个状态）自动显示同一个位置上的下一张；都处理完时写「都复盘完了」。
- 一张卡：`#ID`（点开卡片详情）和标题、标签；agent 最近一次评论放在最上面（复盘时是交审评论，处理时是它留下的问题），`提交：`、`集成分支：`、`检查：` 几行拆出来高亮（白板设了仓库地址时提交号链到提交页面），其余照 Markdown 显示，截图直接显示；描述，标题旁写「验收标准 已勾/总数」，任务列表可以直接勾选（和卡片详情一样）；派发记录（有的话，每条打开会话）。
- 底部：意见框和按钮。
  - 复盘：「通过」移到这个状态连向的终点状态；「打回」必须写意见（没写时意见框标红、提示「打回要写意见」，不发请求），意见作为评论发出，同时把卡片移到这个状态连向的可领取状态（默认工作流里是「返工」）；「跳过」看下一张。连向的终点状态或可领取状态不止一个时，按钮旁边选去哪个（没有连线时：通过去全部终点状态里选，打回去首个可领取状态）。通过时意见框里写了内容，也作为评论一起发出。
  - 处理：只有「回复并放回「<首个可领取状态>」」：回复必须写，作为评论发出，再把卡片移到首个可领取状态。
  - 评论和移动由服务端一个命令完成（`{"op": "reply", "id", "text", "column"}`），在同一个写事务里：移动被拒绝时评论也不留下。
- 乐观更新（AGENTS.md「界面写操作」）：操作当帧把卡片移走、显示下一张；请求失败时提示原因，回到那一张，写好的意见还在。
- 快捷键见 §10.10；在意见框里按 `Esc` 先离开意见框，再按一次关闭。

## 11. 实时同步

- 多个窗口、CLI 读写的是同一份数据。任一处的修改，其他已打开的界面在 2 秒内显示出来。
- 实时推送只发给已登录的界面和带令牌的 `board host`（§3.1、§9.1）。
- agent 上线（check）、下线（`board beat --final` 或心跳中断）和卡片状态变化时推送；只更新心跳时间的 `board beat` 不推送。
- 机器上线、离线、设置变化，以及派发的排队、开始、停止请求、结束时推送；推送里带上机器和派发的版本，`board host` 看到它变了就重新取自己的任务。只更新心跳时间的机器心跳不推送，机器页、机器详情打开时立即刷新一次最近心跳，之后每 10 秒一次。
- 项目画布上节点位置、工作流和状态块布局的修改也同步到所有窗口。
- 大盘打开时，收到推送后 1.2 秒内重新取一次 `GET /api/stats`（连着的几次推送合成一次）。
- 跨白板搜索（`GET /api/search`）在读取的同一个快照里完成，不需要推送：命令面板每次输入后自己再请求一次。

## 12. 错误码

| 错误码 | 出现时机 |
|---|---|
| `NO_IDENTITY` | CLI 没有提供 agent 名字。提示：先 `board check --as <名字>`，之后每条命令都带 `--as <名字>` |
| `NO_BOARD` | CLI 没有指定白板 |
| `BOARD_NOT_FOUND` | 指定的项目或白板不存在；或项目下有多块白板却只写了项目标识 |
| `NOT_FOUND` | 卡片不存在 |
| `EMPTY_TITLE` | 新建或编辑时标题为空 |
| `EMPTY_TODO` | 不带 ID 领取时，连到锁定状态的可领取状态里都没有卡片 |
| `NOT_IN_TODO` | 带 ID 领取的卡片不在可领取状态，且不是自己持有的卡片 |
| `ALREADY_HOLDING` | 该 agent 在这块白板上已经持有另一张卡片 |
| `NOT_HOLDER` | 编辑或移动被持有卡片的不是持有者 |
| `FORBIDDEN_COLUMN` | 把卡片直接移进锁定状态；agent 把卡片移入、移出终点状态或「未整理」；agent 不沿连线移动卡片；从没有连到锁定状态的可领取状态领取 |
| `USAGE` | 命令格式或参数不正确：未知的命令、未知的状态、项目里不存在的标签、agent 加或去「仅人可打」的标签、缺少必需的参数、评论内容为空 |
| `NOT_LOGGED_IN` | 没有登录：界面没有登录会话；CLI 的环境变量和配置文件里都没有服务端地址或令牌（提示运行 `board login`）；用访问令牌调用只能在界面上做的管理接口（项目、白板、工作流、标签、机器） |
| `INVALID_TOKEN` | 访问令牌不存在或已吊销 |
| `UNREACHABLE` | CLI 连不上服务端 |
| `NAME_TAKEN` | `board check` 的名字正被在线 agent 使用；agent 级心跳、`board beat --final` 带的会话标识和名字记录的对不上（名字属于另一个会话或 `board host`）；本机 `board heartbeat start / stop`、不带 ID 的 `board beat` 用的名字是另一个还在运行的 agent 进程 check 的（HTTP 409，§3.2） |
| `NAME_OFFLINE` | 名字没有 check，或心跳中断超过 50 秒：带令牌的卡片命令、上传附件、agent 级心跳被拒绝（HTTP 409）。原因：「名字不在线：没有 check，或心跳中断超过 50 秒，先 board check --as <名字>」 |
| `NOT_AUTHOR` | 修改或删除不是自己发的评论：agent 修改、删除任何评论，或人修改、删除 agent 的评论（HTTP 403） |
| `HOST_NAME_TAKEN` | `board host` 的机器名正被另一个在线的 `board host` 使用（HTTP 409） |
| `ALREADY_DISPATCHED` | 派发的卡片已经有排队或正在跑的派发（HTTP 409） |
| `NO_SUCH_HOST` | 派发、修改、移除的机器不存在，含已移除的机器（HTTP 404） |
| `AGENT_NOT_ON_HOST` | 派发的 agent 不在这台机器上，或标为没找到（HTTP 409） |
| `BOARD_NOT_ON_HOST` | 派发的卡片所在白板在这台机器上没有目录（HTTP 409） |
| `BOARD_NOT_READY` | 派发的卡片所在白板在这台机器上的环境检查没通过，或还没检查（HTTP 409）。原因里写明输出的最后一行 |
| `DISPATCHED` | 卡片有排队中的派发，别的 agent 带 ID 领取或移动它（HTTP 409） |
| `SESSION_DONE` | `board next`：这个会话不再接着做（排着的卡片做完了、手动派发、有人停止、暂停接单或已移除、没有领取规则）（HTTP 409） |
| `IN_TRASH` | 卡片在回收站里：带 id 的卡片命令（编辑、移动、加标签、评论、领取……）要动它时（`board show`、读接口仍返回 `NOT_FOUND`）。原因里写明「#N 在回收站里：先恢复，才能编辑、移动或评论」（HTTP 410） |
| `INTERNAL` | 服务端内部错误（HTTP 500），例如数据库或文件读写失败 |

## 13. 验收标准

1–11 在同一块白板上执行，CLI 已登录（`board login`），名字已 check 并在发心跳，命令带上名字和白板（`--as`、`--board`，或 `BOARD_AS`、`BOARD`）；服务端和本机两种连接方式（§9）结果相同。

1. 「待办」从上到下是 #1、#2。α 执行 `board claim`，得到 #1；#1 进入「进行中」，持有者是 α。
2. 「待办」里只有 #1。α 和 β 同时执行 `board claim 1`：一个成功，另一个得到 `NOT_IN_TODO`。
3. α 持有 #1，再执行 `board claim`，得到 `ALREADY_HOLDING`。
4. α 持有 #1。β 执行 `board edit 1 --title x`，得到 `NOT_HOLDER`；β 执行 `board comment 1 "…"`，成功。
5. α 在 10:00 领取 #1，10:00:02 开始心跳并每 10 秒一次，10:20:05 发 final：动态里记「第 1 次耗时 20 分 3 秒」，卡片累计耗时 20 分 3 秒。
6. α 在 10:00 领取 #1，心跳到 10:10 后中断。10:10:50 时 #1 回到「待办」最上面，持有者为空，动态里记「心跳中断」「判定异常退出，第 1 次耗时约 10 分」。β 随后领取 #1；α 再执行 `board move 1 review`，得到 `NOT_HOLDER`。
7. α 持有 #1，执行 `board move 1 done`，得到 `FORBIDDEN_COLUMN`；执行 `board move 1 review` 成功，持有者清空。人把 #1 拖到「已完成」，成功。
8. 人把「待办」里的卡片拖进「进行中」：卡片回到原位，并显示原因。agent 执行 `board move 2 doing`，得到 `FORBIDDEN_COLUMN`。
9. 人对 α 持有的 #1 点「强制释放」：#1 回到「待办」最上面，持有者为空；α 之后执行 `board claim`，不会得到 `ALREADY_HOLDING`。
10. 执行 `board new "x"` 后，已打开的界面在 2 秒内出现卡片 x，不需要刷新。
11. 任一命令加 `--json`，都输出合法 JSON；被拒绝时退出码为 1，JSON 里带错误码。

项目与白板：

12. 没有 `--board` 也没有 `BOARD` 时执行 `board ls`，得到 `NO_BOARD`。
13. 项目 `oss` 下有白板 `main` 和 `release`：`--board oss` 得到 `BOARD_NOT_FOUND`，原因里列出 `main`、`release`；`--board oss/nope` 得到 `BOARD_NOT_FOUND`。项目 `site` 下只有白板 `launch`：`--board site` 等同于 `--board site/launch`。
14. 在新建的白板上执行 `board new "x"`，得到 #1。
15. α 在 `oss/main` 持有一张卡片，在 `oss/release` 执行 `board claim`，成功。
16. 在 `oss/main` 执行 `board new "x"`，正在看 `oss/release` 的界面不出现卡片 x。
17. 人在界面上删除白板 `oss/release` 后，agent 以 `BOARD=oss/release` 执行任一命令，得到 `BOARD_NOT_FOUND`。
18. `board boards` 列出所有白板的路径。

未整理：

19. agent 执行 `board new "想法" --inbox --json` 成功，返回 `column=inbox`、`holder=null`，条目位于「未整理」最下面；`board ls --column inbox` 能看到它。人在界面上也能新建放进「未整理」的条目 #5。「待办」为空时 agent 执行 `board claim`，得到 `EMPTY_TODO`；执行 `board claim 5`，得到 `NOT_IN_TODO`。
20. 人对 #5 点「整理到待办」，#5 出现在「待办」最下面。
21. 人在「未整理」页对条目选「移动到 → 进行中」：被拒绝并显示原因，条目还在「未整理」。

标签：

22. α 持有 #1。β 执行 `board label 1 +bug`，成功，#1 的动态里有一条加标签的记录，持有者仍是 α。
23. 执行 `board label 1 +不存在的标签`，得到 `USAGE`。
24. `board ls --label bug` 只列出带 bug 标签的卡片。
25. 人在界面上删除标签 bug 后，项目内所有卡片上都没有 bug 标签。

工作流（默认工作流，§7）：

## 14. 使用场景（不属于产品功能）

我们用 Board 自动维护开源项目时，会在 Board 之外运行下面这些程序。它们都只通过 CLI 访问白板，用 `board login` 写的配置连接服务端，开始时 `board check` 名字并启动心跳，每条命令带上名字和要操作的白板。

| 程序 | 怎么用 Board |
|---|---|
| issue 监听 | 发现新 issue 后，先用 `board ls --search gh#140` 查有没有卡片；没有就执行 `board new "<标题>" --body "gh#140 …"` |
| 社区监听 | 同上，用帖子链接查重 |
| 定期清理 | 发现需要清理的代码，执行 `board new` |
| 需求拆解 | 把需求拆成卡片，只 `board new`，不修改已有的卡片。一张卡 = 一次复盘 = 集成分支上的一个提交：同类别的小改动（界面、文案、图片）合成一张卡，描述里每项改动一个小节、带自己的验收标准；模块重构，改数据表、服务端接口、CLI 命令、skill 规则，以及其他改动各一张卡。不按前端、后端拆，不按步骤拆，有先后依赖的部分放在同一张卡里 |
| 执行 agent | 会话开始：`board check` 名字，启动后台心跳。循环执行：`board claim` 领卡片 → 在本会话的 worktree 里按描述干活，期间用 `board comment` 记进度 → 改代码的卡片：`board flow --json` 认集成分支（白板设置 → 仓库的 AGENTS.md / CLAUDE.md → 远端默认分支），rebase 到它，在 rebase 之后的代码上跑仓库规定的全部检查，压成一个最后一行是 `卡片：<项目>/<白板>#<ID>` 的提交，推之前用 `board hold <ID>` 确认领取仍有效（卡片已经不归自己时不推集成分支，改推 `wip/<白板>/<ID>` 分支、评论说明后结束这张卡，不 final、不移动；连不上服务端时每 30 秒重试、最多等 5 分钟，还连不上同样改推 wip 分支，能连上后补评论），再直接推到集成分支，推送被拒就重新 rebase、重新检查再推 → 评论改了什么、`提交：<sha>`、`集成分支：<分支>`、`检查：<结果>`，对这张卡片发 final，沿连线移到交审状态（默认工作流里是「待审核」）；做不下去就不推集成分支，把未完成的改动推到 `wip/<白板>/<ID>` 分支，用 `board comment` 写明原因和分支名，发 final，再沿连线把卡片移到错误节点（没有错误节点时移到需要人处理的状态，默认工作流里是「需人工校验」）。会话结束：停掉心跳，名字离线，删掉自己的 worktree |

集成分支按「白板设置的集成分支 → 仓库的 AGENTS.md / CLAUDE.md → 远端的默认分支」的顺序认；仓库的 AGENTS.md / CLAUDE.md 还写明推送前要跑的检查（白板换集成分支时只改白板设置，不用改仓库文件）。不建卡片分支，不设专门的合并节点；每个会话在本机一个 worktree 里一张接一张地做卡片。agent 只按工作流的规则、连线和状态名称里的关键词认出首个可领取状态、交审状态和需要人处理的状态，不依赖具体的状态名。

人在界面上调整「待办」的顺序来决定先做什么。「待审核」里的卡片代码已经在集成分支上，人看卡片动态里的提交号、检查记录和提交本身复盘：没问题拖到「已完成」；有问题拖到「返工」并评论哪几项不对，领到它的 agent 在集成分支上再提交一次修复，不改写已经推上去的提交。「需人工校验」里是 agent 做不下去、等人处理的卡片。发版由人决定。没想清楚的事先记在「未整理」，整理好再放进「待办」。
