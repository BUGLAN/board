# Board 产品需求文档

| 项 | 内容 |
|---|---|
| 版本 | v0.9 |
| 日期 | 2026-11-09 |

## 1. 产品定义

Board 是看板式白板。人在界面上操作，agent 通过命令行（CLI）操作，两边读写的是同一块白板。

服务端部署在线上（`https://board.buglan.com`）。人用 GitHub 账号登录，agent 用访问令牌连接。

白板按项目组织：一个项目下有多块白板。

Board 只管两件事：卡片在哪个状态、谁在做。agent 怎么干活不归 Board 管。每台干活的机器上可以常驻一个 `board host`：人把卡片派给某台机器，或者机器到了设定的时间自己领卡，`board host` 在本机启动已经装好的 agent（§9.1）。

## 2. 范围

**包含**

- 项目与白板的新建、编辑、删除
- 卡片的新建、编辑、移动、排序、评论、删除
- 卡片附件：图片和常见文件
- 「未整理」条目：放在工作流之前、还没整理成卡片的内容
- 每块白板的工作流（状态和连线）可以自定义
- 标签
- agent 名字的查重与在线状态；agent 领取卡片、发心跳，以及心跳中断后自动释放
- 复制为提示词，以及给 agent 用的 skill（`board-skills`）
- 界面：网页端与桌面端使用同一套界面；手机浏览器可用
- CLI
- 登录：网页端和桌面端用 GitHub 账号登录，只允许一个指定的账号
- agent 访问令牌：在界面上新建、吊销
- 任务下发（§9.1）：机器（`board host`）、手动派发、定时领取

**不包含**

- agent 本身。任何能执行命令行的 agent 都可以接入；`board host` 只启动本机已经装好的 agent。
- 界面里的命令行终端。agent 在自己的环境里运行 CLI。
- 对 GitHub issue、社区的监听
- 与 GitHub 等外部系统的同步（GitHub 只用于登录）
- 多个账号、团队、成员角色，以及注册

## 3. 身份与白板定位

| 操作方式 | 身份 | 操作哪块白板 |
|---|---|---|
| 界面 | 人：登录的 GitHub 账号（§3.1） | 界面上当前打开的白板。每个窗口可以打开不同的白板 |
| CLI | agent。名字由 `--as <名字>` 或环境变量 `BOARD_AS` 给出，两者都没有时命令被拒绝（`NO_IDENTITY`）；会话开始时先 `board check` 占用名字（§3.2）。连接服务端时用访问令牌认证（§3.1、§9） | 由 `--board <项目>/<白板>` 或环境变量 `BOARD` 给出，两者都没有时命令被拒绝（`NO_BOARD`） |

- 白板路径写成「项目标识/白板标识」，例如 `oss/release`。
- 项目下只有一块白板时，可以只写项目标识，例如 `site`。项目下有多块白板时只写项目标识，返回 `BOARD_NOT_FOUND`，原因里列出该项目的白板标识。

### 3.1 登录与访问令牌

**登录**

- 服务端只允许一个指定的 GitHub 账号登录（部署时配置）。所有项目和白板都属于这个账号。
- 没有登录时，网页端和桌面端显示登录页，页面上只有「用 GitHub 登录」。用其他 GitHub 账号登录时被拒绝，登录页提示该账号没有权限。
- 登录后 30 天内有效，使用期间自动续期。在「设置 → 账号」里可以退出登录。
- 所有 API，包括实时推送，都需要登录或访问令牌，否则被拒绝（`NOT_LOGGED_IN`）。
- 服务端以本机模式运行时，只接受本机访问，不需要登录。

**访问令牌**

- agent 连接服务端时用访问令牌认证。令牌属于登录的账号。
- 在「设置 → Agent 接入」新建令牌，填写用途（例如 `macbook`）。令牌原文只在新建时显示一次。
- 令牌列表显示用途、令牌开头几位、创建时间、最近使用时间。令牌可以吊销，吊销后使用它的命令被拒绝（`INVALID_TOKEN`）。
- `--as` / `BOARD_AS` 是 agent 的名字，与令牌无关：同一个令牌可以用不同的名字运行多个 agent。§8 的持有者仍按 agent 名字判断。
- 令牌只能用于 CLI 的命令（§9）和 agent 接口：check、心跳、在线列表（§3.2）；`board host` 的上报、开始与结束派发、上传日志、订阅实时推送，以及创建、取消派发（§9.1）。项目、白板、工作流、标签的管理，机器的设置与移除，以及删除卡片、强制释放，只能在登录后的界面上做。

### 3.2 agent 名字

**格式**：`<运行环境>/<模型>`，需要时加 `-<后缀>`。

- 两段都只能用小写字母、数字、`.`、`-`，并以字母或数字开头；只有一个 `/`，总长不超过 48 个字符。
- 例子：`claude/opus-5.5`、`dsh/deepseek-v4.1-flash`、`claude/opus-5.5-login`。
- 格式不对时 `board check` 报 `USAGE`，原因里给出格式说明。

**名字由 agent 自己生成**：运行环境用 claude、codex 这类名称；模型名转成小写，空格换成 `-`；本机已有同名会话时，加一个和本会话相关的后缀，例如任务名或分支名。

**board host 生成的名字**：`<agent 标识>/<机器名>-<序号>`，例如 `claude/mbp-3`，序号在这台机器上递增。`board host` 以这个名字 check、领取卡片、发心跳，再启动 agent（§9.1）。

**check**：`board check --as <名字>`。

- 名字正被在线 agent 使用时报 `NAME_TAKEN`，`detail` 里带上名字。
- 否则把名字标为在线，心跳时间记为当前时间，然后返回。
- 查重和占用是一个原子操作：同时 check 同一个名字，只有一个成功。

**在线**：名字最近一次心跳在 50 秒以内（每 10 秒一次，连续 5 次没收到算离线）。`board beat --final`（不带 ID）让名字立刻离线。离线后，同一个名字可以被任何会话重新 check，原会话也可以。

**名字表**：服务端记录名字、首次 check 时间、最近心跳时间、令牌 ID。表只增不删。

**严格模式**：带令牌的卡片命令（`POST /api/cmd`）和上传附件（`POST /api/files`）里的名字必须在线，否则报 `NAME_OFFLINE`。读接口不检查名字。

## 4. 项目与白板

**项目**

| 字段 | 说明 |
|---|---|
| 名称 | 必填 |
| 标识 | 必填。小写字母、数字和 `-`，以字母或数字开头，最长 32 个字符；全局唯一；创建后不能修改 |
| 描述 | 选填 |
| 颜色 | 从固定色板里选一种 |
| 标签 | 见 §6 |

**白板**

| 字段 | 说明 |
|---|---|
| 名称 | 必填 |
| 标识 | 必填。格式同项目标识；在所属项目内唯一；创建后不能修改 |
| 描述 | 选填 |

- 一块白板只属于一个项目。
- 新建项目时同时新建它的第一块白板（默认名称「主白板」，标识 `main`）。
- 每块白板相互独立：卡片 ID、工作流、领取、心跳都只在本白板内计算。
- 项目和白板只能在界面上新建、编辑、删除。删除前要二次确认；删除项目会删除它的全部白板。整个工作区至少保留一块白板。
- 白板被删除后，指向它的 CLI 命令返回 `BOARD_NOT_FOUND`。

## 5. 卡片

| 字段 | 说明 |
|---|---|
| ID | 每块白板内自增的整数，从 1 开始；界面上显示为 `#1`。「未整理」条目与卡片共用同一套 ID |
| 标题 | 必填 |
| 描述 | 选填，Markdown。验收标准、相关链接都写在这里 |
| 状态 | 「未整理」或工作流里的一个状态（§7） |
| 标签 | 0 个或多个，取自所属项目的标签 |
| 持有者 | 领取这张卡片的 agent 名字，只有锁定状态里的卡片有 |
| 耗时 | 每一次领取的耗时（第一次心跳到结束），以及累计耗时、做过几次、其中几次异常退出 |
| 动态 | 评论和系统记录，按时间排列，只能追加；人可以在界面上原地修改自己发的评论（显示「已编辑」和修改时间），agent 的评论和系统记录不能修改 |
| 附件 | 0 个或多个文件：图片（PNG、JPEG、GIF、WebP）和常见文件（PDF、TXT、Markdown、日志、JSON、CSV、ZIP），单个不超过 10 MB |

- 卡片在状态内有先后顺序，越靠前越优先。
- 附件：
  - 在描述和评论里插入：图片直接显示，点击放大；其他文件显示为下载链接。
  - 人在界面上的描述框、新建弹窗的描述框和评论框里粘贴截图、拖入文件或点「附件」按钮上传；agent 用 `board attach` 上传（§9）。
  - 读取附件需要登录或访问令牌。
  - 删除卡片时附件一起删除；备份包含附件。
- 卡片被新建、编辑、移动、调整顺序、领取、开始或结束心跳、释放，以及加或去标签时，系统自动在动态里追加一条记录，写明谁、在什么时间、做了什么。

## 6. 标签

| 字段 | 说明 |
|---|---|
| 名称 | 必填；在所属项目内唯一，不区分大小写 |
| 颜色 | 从固定色板里选一种 |

- 标签属于项目，项目下的所有白板共用。
- 人和 agent 都能给卡片加标签、去标签，任何状态的卡片都可以，包括别人持有的卡片（不受 §8 规则 5 限制）。
- 卡片上的标签显示为块状胶囊（色点 + 名称）。
- 标签的新建、改名、改色、删除在界面上做。删除标签时，它会从项目内所有卡片上移除。
- CLI 引用项目里不存在的标签时，命令被拒绝（`USAGE`），原因里列出可用的标签。

## 7. 工作流

每块白板有自己的工作流：一组有先后顺序的状态，以及状态之间的连线。连线 A → B 表示 agent 可以把卡片从 A 移到 B（§8 规则 12）；人移动卡片不受连线限制。

新建白板时默认是 6 个状态：

| 状态 | 标识 | 规则 | 连线（可以去往） |
|---|---|---|---|
| 待办 | `todo` | 可领取 | 进行中 |
| 进行中 | `doing` | 锁定 | 待审核、需人工校验 |
| 待审核 | `review` | — | 已完成、返工 |
| 已完成 | `done` | 终点 | — |
| 返工 | `rework` | 可领取 | 进行中 |
| 需人工校验 | `check` | — | 待办 |

| 字段 | 说明 |
|---|---|
| 名称 | 必填；在白板内唯一，不区分大小写；最长 12 个字 |
| 标识 | 系统生成，不能修改。默认的 6 个状态见上表，新增的状态依次是 `s1`、`s2`… |
| 颜色 | 从固定色板里选一种 |
| 规则 | 三个开关，见下表 |
| 卡片形态 | 状态块里的卡片怎么显示：卡片、单行、磁贴三选一（§10.3），只影响界面显示。没有设置过时，终点状态用磁贴，其他状态用卡片 |
| 连线 | 从这个状态出发、可以去往的状态，0 个或多个 |

| 规则 | 含义 | 数量 |
|---|---|---|
| 可领取 | `board claim` 从这里领取，领取后卡片沿连线进入锁定状态（§8 规则 1） | 1 个或多个 |
| 锁定 | 只能由 agent 领取进入；卡片被持有期间，只有持有者能编辑和移动 | 0 个或多个 |
| 终点 | 进到这里算完成；只有人能把卡片移入或移出 | 0 个或多个 |

- 状态的顺序决定：工作流条上的排列；不带 ID 领取时先领哪个可领取状态；新建卡片放在哪里。
- **首个可领取状态**：按顺序排在最前面的可领取状态。新建卡片、「整理到…」都放进这里。
- 工作流只能在界面上修改：新增、改名、改色、选卡片形态、调整顺序、切换规则、连线、删除。
- 至少要有一个可领取状态：最后一个可领取状态不能关闭「可领取」，也不能删除。
- 可领取状态没有连到任何锁定状态时，不能从这里领取；工作流条上这个状态显示提示。
- 删除状态时，里面的卡片移到首个可领取状态最下面，被持有的卡片同时释放；与它相关的连线一起删除。
- 关闭某个状态的「锁定」时，其中被持有的卡片释放。
- 「未整理」（标识 `inbox`）不属于工作流，没有连线：每块白板固定都有，不显示在白板的主内容区，agent 不能领取，也不能把卡片移入或移出。
- CLI 里用标识或名称指定状态，名称不区分大小写。
- 升级前已有的白板：原来的领取起点变为可领取，按原来的顺序给相邻的状态依次连线（第 1 个 → 第 2 个 → …），其余在界面上调整。

## 8. 规则

以下规则都在同一块白板内生效。

1. **领取**：只有可领取状态里的卡片能被领取。领取后卡片沿连线进入锁定状态：这个可领取状态连向的锁定状态里，按顺序排在最前面的一个；没有连到锁定状态时不能从这里领取。不带 ID 领取时，按工作流顺序，领第一个有卡片、并且连到锁定状态的可领取状态最上面的卡片。持有者是领取它的 agent。
2. **互斥**：多个 agent 同时领取同一张卡片，只有一个成功。
3. **一个 agent 在一块白板上同时只持有一张卡片。**
4. **进入锁定状态只能靠领取**：人和 agent 都不能把卡片直接移进锁定状态。例外：持有者可以沿连线把自己持有的卡片从一个锁定状态移到另一个锁定状态，领取保持不变。
5. **持有者独占**：被持有的卡片只有持有者能编辑和移动，其他人和 agent 只能评论、加或去标签。人可以在界面上「强制释放」。
6. **心跳与耗时**：一个 agent 会话只有一路后台心跳。check 之后，`board heartbeat start` 启动的后台循环每 10 秒发一次 `board beat`（不带 ID）：更新名字的心跳时间（名字已离线时被拒绝，`NAME_OFFLINE`），并对这个名字持有、这一次还没 final 的每张卡片记一次心跳，效果等同于 `board beat <ID>`：更新卡片的心跳时间，计入心跳次数。领取后的第一次心跳是这一次的开始，动态里记「开始第 n 次」；final（`board beat <ID> --final`）是结束，两者之差是这一次的耗时，记在动态里；卡片显示累计耗时。final 之后这张卡片不再被后台心跳刷新，再发 `board beat <ID>` 被拒绝。同一张卡片被多次领取时，每一次分别计时、分别记录。评论、编辑不代替心跳。
7. **心跳中断释放**：从领取或最近一次心跳算起，连续 5 次（50 秒）没收到心跳，卡片回到领取它时所在的可领取状态最上面（那个状态已删除或不再可领取时，回到首个可领取状态最上面），持有者清空，动态里记「心跳中断」。进行中的这一次以最后一次心跳为结束，记为异常退出；还没开始心跳、或发了 final 后 50 秒内没有沿连线移走的，动态里写明原因。名字离线后，它持有的卡片收不到心跳，按这条规则在 50 秒内释放。本次耗时有四种结束方式：final 正常结束、持有者移出锁定状态、人强制释放、心跳中断。
8. **离开锁定状态即释放**：持有者把卡片移到不锁定的状态时，持有者清空，进行中的这一次在此时结束。人强制释放后，卡片回到的位置同规则 7，进行中的这一次在此时结束。
9. **终点只归人管**：只有人能把卡片移入或移出终点状态。
10. **删除只能在界面上做。**
11. **「未整理」只归人管**：「未整理」只在界面上新建；只有人能把卡片移入或移出「未整理」，同样受规则 4、5 约束。
12. **agent 只能沿连线移动**：agent 把卡片从 A 移到 B 时，工作流里必须有连线 A → B，否则被拒绝，原因里列出 A 能去的状态。人移动卡片不受连线限制。在同一个状态内调整顺序不受影响。

**卡片在状态里的位置**

- 新建：首个可领取状态最下面；CLI 带 `--top` 时放在最上面。界面上新建时可以选择放进「未整理」，放在「未整理」最下面。
- 移动：目标状态最下面；CLI 带 `--top` 时放在最上面。界面上拖拽时放在松手的位置。
- 「整理到<首个可领取状态>」：首个可领取状态最下面。
- 心跳中断释放、强制释放：领取它时所在的可领取状态最上面（规则 7）。

## 9. CLI

所有命令都支持 `--json`，输出 JSON。成功时退出码为 0；被拒绝时退出码为 1，并给出错误码（见 §12）和原因。

**安装**：桌面端安装包自带 `board` 命令行。Windows 安装器把它写进用户 PATH，装完重开终端就能用；macOS 的安装包不带安装脚本，在「设置 → Agent 接入」里执行一条 `ln -sf` 命令把 `Board.app` 里自带的 `board` 链接到 `/usr/local/bin`。不装桌面端时从源码安装：`cargo install --path crates/board-cli`（需要 Rust）。agent 用 skill 自带的 `board`：发版附件 `board-skills.zip` 的 `bin/` 里有各平台的二进制，skill 里的 `scripts/board`（Windows：`scripts\board.cmd`）按平台选用，没有时用 PATH 里的 `board`。

**连接**

CLI 只通过服务端读写白板，规则在服务端执行。服务端地址和访问令牌写在配置文件 `~/.board/config.toml`（Windows 上是 `%USERPROFILE%\.board\config.toml`）里：

| 配置项 | 内容 |
|---|---|
| `url` | 服务端地址，例如 `https://board.buglan.com`；本机模式的服务端填它的本机地址，例如 `http://127.0.0.1:7420` |
| `token` | 访问令牌，在界面「设置 → Agent 接入」新建 |
| `[host]` | `board host` 的机器名 `name` 和白板与目录 `dirs`（§9.1） |
| `[agents.<标识>]` | `board host` 的 agent 命令模板 `cmd`（§9.1） |

- 配置文件所在目录权限 0700，文件权限 0600。以后固定的配置也写在这个文件里；agent 名字（`BOARD_AS`）和白板（`BOARD`）不写进这个文件。
- 读取顺序：环境变量 `BOARD_URL` / `BOARD_TOKEN` 优先，配置文件其次。两处都没有时报 `NOT_LOGGED_IN`，提示运行 `board login`。
- 令牌无效或已吊销时被拒绝（`INVALID_TOKEN`）；连不上服务端时被拒绝（`UNREACHABLE`）。

**`board login [--url <地址>] [--token <令牌>]`**

- 不带 `--url` 时沿用文件里已有的 `url`，文件里也没有就报 `USAGE`。不带 `--token` 时从标准输入读一行。
- 写入前用 `GET /api/workspace` 校验令牌。校验失败时不写文件，按服务端返回的错误码报错（`INVALID_TOKEN`、`UNREACHABLE` 等）。
- 改写文件时保留其他配置项。
- 写入成功后，如果当前环境里设置了 `BOARD_URL` 或 `BOARD_TOKEN`，输出一行提醒：环境变量会覆盖配置文件，需要从 shell 配置文件里删掉对应的 `export`。
- 输出里不打印令牌原文。

**`board logout`**：从配置文件删掉 `token`，保留 `url`。

**`board doctor [--as <名字>] [--board <白板>]`**：环境自检，没通过的项给出原因和下一步，有失败项时退出码为 1。

- 服务端地址和令牌两项写明值来自哪里：环境变量还是 `~/.board/config.toml`。两处都有时状态为 warn，说明环境变量覆盖了文件；两处都没有时，下一步提示 `board login --url <服务端地址>`。
- 名字（`--as` 或 `BOARD_AS`）和白板（`--board` 或 `BOARD`）没提供时跳过，不判失败；提供了名字时，检查格式和是否在线。

除 `board help`、`board login`、`board logout`、`board doctor` 外，所有命令都需要连接服务端；除这几个和 `board host`、`board dispatch` 外，都需要身份（§3）；此外除 `board boards`、`board check`、不带 ID 的 `board beat`、`board host` 外，都需要白板（§3）。

| 命令 | 作用 |
|---|---|
| `board check --as <名字>` | 占用名字（§3.2）。会话开始时执行一次 |
| `board heartbeat start` | 启动后台心跳（§8 规则 6）：先同步发一次 `board beat`，失败直接报错；成功后后台每 10 秒发一次，立即返回。后台心跳跟随 agent 进程（从 board 往上找第一个不是 shell 的祖先进程），agent 进程不在了就停下，不发 final；心跳被拒绝时停下，连不上服务端时继续重试 |
| `board heartbeat stop` | 先停掉后台心跳、等它退出，再发 `board beat --final`，名字立刻离线；重复执行不报错 |
| `board heartbeat final <ID>` | 等同 `board beat <ID> --final`：结束这张卡片这一次的计时 |
| `board beat [--final]` | agent 级心跳（§8 规则 6），一般由 `board heartbeat` 的后台循环发送；`--final` 让名字立刻离线 |
| `board beat <ID> [--final]` | 一张卡片的心跳；`--final` 结束这一次计时（§8 规则 6） |
| `board boards` | 列出所有白板：路径、项目名、白板名、各状态卡片数 |
| `board flow` | 列出当前白板的工作流：顺序、标识、名称、规则、卡片数，以及每个状态可以去往的状态 |
| `board ls [--column <状态>] [--search <文字>] [--label <标签>]` | 列出卡片：ID、状态、标题、标签、持有者，按工作流顺序和状态内顺序排列。`--search` 在标题和描述里查找；`--label` 只列出带该标签的卡片 |
| `board show <ID>` | 显示卡片的全部字段和动态 |
| `board new "<标题>" [--body "<描述>"] [--top]` | 在首个可领取状态新建卡片 |
| `board edit <ID> [--title "<标题>"] [--body "<描述>"]` | 修改标题或描述 |
| `board move <ID> <状态> [--top]` | 把卡片移到指定状态（标识或名称）；只能沿连线移动（§8 规则 12） |
| `board claim [<ID>]` | 领取。不带 ID 时按 §8 规则 1 选卡片。返回卡片的全部字段和动态 |
| `board comment <ID> "<内容>"` | 追加评论 |
| `board label <ID> +<标签> -<标签> …` | 加标签（`+` 或不带前缀）、去标签（`-`），可以一次写多个 |
| `board labels` | 列出白板所属项目的标签，以及每个标签被多少张卡片使用 |
| `board attach <ID> <文件>… [--comment "<说明>"]` | 上传附件，连同说明作为一条评论追加到卡片 |
| `board files <ID> [--out <目录>]` | 把卡片的附件下载到本地（默认系统临时目录），列出文件路径 |
| `board host [--name <机器名>] [--dir <项目>/<白板>=<路径>]…` | 在这台机器上常驻接任务（§9.1），前台运行，`Ctrl+C` 退出 |
| `board dispatch <ID> --host <机器名> [--agent <标识>]` | 把卡片派给一台机器上的 agent；不带 `--agent` 用这台机器的默认 agent（§9.1） |
| `board dispatch <ID> --cancel` | 取消还在排队的派发，或停止正在跑的派发（§9.1） |

### 9.1 任务下发（board host）

**机器**：运行 `board host` 的进程代表一台机器。有名字、在线状态、并发上限、本机 agent、白板与目录。

- 机器名：小写字母、数字、`.`、`-`，以字母或数字开头，最长 24 个字符；不填时取本机主机名转成小写、非法字符换成 `-`。同名机器正在线时启动失败（`HOST_NAME_TAKEN`）。同一台机器上 `board host` 异常退出后重启，接回原来的名字。
- 白板与目录：`--dir` 把一块白板对应到本机的一个仓库目录，agent 在这个目录里启动。没有对应目录的白板，这台机器不接它的卡片。目录不存在时启动失败（`USAGE`，写明是哪个目录）。
- 本机 agent：启动时按配置文件里的 `[agents.*]` 加上内置模板，逐个检查命令在不在 `PATH` 里、取版本号（`<命令> --version` 的第一行）；找不到的也上报，标为「没找到」。内置模板只有 `claude`（Claude Code）：`claude -p {prompt} --dangerously-skip-permissions`。配置文件里同标识的模板覆盖内置模板。`{prompt}` 换成提示词，作为一个参数传入，不经过 shell。
- 参数也可以写在 `~/.board/config.toml` 的 `[host]`（`name`、`dirs = { "<项目>/<白板>" = "<路径>" }`）和 `[agents.<标识>]`（`cmd = [...]`）里，命令行参数优先。
- 启动后上报机器名、操作系统、board 版本、本机 agent、白板与目录，每 10 秒一次机器心跳，连续 5 次没收到算离线。`board host` 用令牌订阅实时推送，收到派发、设置变化、停止请求后立即处理。
- `Ctrl+C` 退出：先按「人停止」结束本机由它启动的全部 agent，再让机器离线。

**机器设置**（存在服务端，在界面上修改，`board host` 实时拿到，不需要重启；机器第一次连上时按默认值建立）：

| 设置 | 默认值 | 说明 |
|---|---|---|
| 同时跑几个 | 1 | 1–8。正在跑的派发达到上限后，新的派发在服务端排队 |
| 暂停接单 | 关 | 打开后不启动新的派发（手动派发照样排队），已经在跑的不受影响 |
| 默认 agent | 本机 agent 里第一个找到的 | 定时领取用它；手动派发时预先选中它 |
| 定时领取 | 关，没有时间点 | 每天的若干个时间点（`HH:MM`，机器本地时区），开关 |

**派发**：一次「在某台机器上用某种 agent 做某张卡」，来源是手动或定时。状态：排队 → 在跑 → 结束；结束的结果是已交审、做不下去、异常退出、已停止、已取消、机器掉线、没领到之一。派发、取消、开始、结束都在卡片动态里追加一条，写明机器、agent、来源和结果。派发记录一直保留。

**手动派发**：卡片详情的「派发」或 `board dispatch`。不满足下列条件时拒绝，不产生派发：

| 条件 | 错误码 |
|---|---|
| 卡片不在可领取状态 | `NOT_IN_TODO` |
| 卡片已经有排队或正在跑的派发 | `ALREADY_DISPATCHED` |
| 机器不存在（含已移除） | `NO_SUCH_HOST` |
| 机器上没有这种 agent，或标为没找到 | `AGENT_NOT_ON_HOST` |
| 机器没有这块白板的目录 | `BOARD_NOT_ON_HOST` |

派给离线、已满、暂停接单的机器时排队。卡片有排队中的派发时，别的 agent `board claim <ID>` 报 `DISPATCHED`，不带 ID 的 `board claim` 跳过它；人可以照常拖动它，拖出可领取状态时这次派发自动取消。

**定时领取**：到了设置的时间点，机器在线、没有暂停接单时开始一轮：在这台机器有目录的白板上，按 §8 规则 1 领下一张可领取的卡片（跳过有排队派发的），用默认 agent 开始；有空位就继续领，每有一个派发结束再领一张；所有白板都没有可领取的卡片时这一轮结束。多块白板时按 `--dir` 的顺序轮流，一块白板领一张再换下一块。一轮还没结束时到了下一个时间点，不重复开始；到点时机器离线或暂停接单，这个时间点跳过，上线后不补。机器详情里的「现在领一轮」效果与到点相同。

**执行**（机器在线、没有暂停、有空位时，按派发创建的先后开始）：

1. 生成 agent 名字（§3.2），check 这个名字，再以它领取卡片。领取失败（卡片已被领走、已不在可领取状态）时这次派发结束，结果「没领到」，不启动 agent。
2. 领到后，`board host` 以这个名字发心跳（每 10 秒），直到派发结束。
3. 在这块白板对应的目录里启动 agent：提示词是 `/board-skills 开始执行 <项目>项目之中的<白板>白板中的#<ID>任务`；环境变量带上 `BOARD_URL`、`BOARD_TOKEN`、`BOARD_AS=<名字>`、`BOARD_HOST=<机器名>`。`board-skills` 看到 `BOARD_HOST` 且卡片已由 `BOARD_AS` 持有时，不再 check、不再领取、不启动也不停止心跳，其余步骤不变。
4. agent 的标准输出和标准错误写到 `~/.board/host/logs/<派发 ID>.log`，每 5 秒上传新增的行；服务端每个派发保留最后 500 行。

**结束**（「交审状态」「需要人处理的状态」按 `board-skills` 认角色的规则识别：规则、连线、状态名称里的关键词）：

| 情况 | 卡片 | 派发结果 |
|---|---|---|
| agent 退出，卡片已不被这个名字持有，在交审状态 | 不动 | 已交审 |
| agent 退出，卡片已不被这个名字持有，在其他状态 | 不动 | 做不下去 |
| agent 退出（任何退出码），卡片仍由这个名字持有 | 发 final，沿连线移到需要人处理的状态（默认工作流是「需人工校验」），评论「agent 异常退出（退出码 N）」和日志最后 20 行 | 异常退出 |
| 人停止（界面上点「停止」或 `board dispatch <ID> --cancel`）：结束 agent 进程树（先 SIGTERM，10 秒后 SIGKILL；Windows 结束进程树） | 同上一行，评论写「<人> 停止了这次派发」 | 已停止 |
| 人取消排队中的派发 | 不动 | 已取消 |
| 机器掉线超过 50 秒 | 按心跳超时规则释放（§8 规则 7） | 机器掉线 |
| `board host` 在 50 秒内重启，派发还在跑、本机没有对应进程 | 同「卡片仍由这个名字持有」 | 异常退出 |

**移除机器**：取消它所有排队中的派发，停止正在跑的派发，删除机器设置；派发记录保留，界面上显示为「已移除的机器」。之后这台机器的 `board host` 再连上来，按新机器建立设置。

## 10. 界面

### 10.1 整体布局

- **顶栏**：品牌、项目 / 白板切换器、搜索（命令面板入口）、在线的 agent 头像组。
  - 头像组显示所有在线 agent（§3.2），不分白板：check 之后头像出现，离线后消失。
  - 持卡的 agent 头像外圈是心跳波纹，悬停时展开，显示这一次的耗时；提示文字是「<名字> 正在做 <项目>/<白板>#<ID>」，做过不止一次时加上累计耗时。没持卡时提示文字是「<名字> 空闲」。
  - 侧栏「正在工作」和卡片上的持有者只显示持卡的 agent。
- **左侧操作台**：活动栏 + 侧栏。活动栏从上到下五个 Tab：白板、项目、未整理、机器、设置。再次点击当前 Tab 收起或展开侧栏，每个 Tab 分别记住展开或收起；侧栏宽度可以拖动调整。
- **主内容区**：在右侧，显示当前白板、项目画布或设置页。
- 活动栏图标上不显示数量徽标。
- 手机上，活动栏变为底部 Tab 栏；白板各状态左右滑动切换，顶部有状态切换条；「项目」「未整理」Tab 占满内容区，显示对应的列表。
- 桌面端：打开线上的 Board（`https://board.buglan.com`）。点「用 GitHub 登录」在系统默认浏览器里登录，登录完成后桌面端自动进入白板。顶栏同时是窗口标题栏，可以拖动窗口；Windows 上没有系统标题栏和菜单栏，最小化、最大化、关闭按钮在顶栏右侧。
- 主题：跟随系统 / 浅色 / 深色。

### 10.2 项目 / 白板切换器（顶栏）

- 显示「项目名 / 白板名」。点击后列出所有白板，按项目分组，每块白板显示正在工作的 agent 数和可领取状态里的卡片数；可以搜索，回车切换。
- 其他白板上有 agent 正在工作时，切换器上有提示点。
- 底部有「新建白板」「项目总览」入口。

### 10.3 白板 Tab

- 侧栏：
  - 筛选框：按标题、描述、`#ID`、agent 名字、标签名筛选，不匹配的卡片淡出；输入 `label:<标签>` 只按标签筛选。
  - 「标签」：项目的全部标签块状排列，每个标签显示它在当前白板上的卡片数。点击标签即按该标签筛选，再点一次取消；按住标签拖到白板上的卡片上松手，即给这张卡片加上这个标签（卡片已有时只提示；触屏上长按后拖动；Esc 取消）；整块区域就是输入框：点空白处出现光标，输入名称后回车即新建标签。改名、改色、删除标签在命令面板和项目菜单的「管理标签」里。
  - 「正在工作」：当前白板上持有卡片的 agent、卡片和这一次的耗时。
  - 「最近动态」：当前白板最近的记录。
- 主内容区：页头显示「项目名 › 白板名」和「新建卡片」按钮。下面依次是工作流条和状态块。
- 工作流条：把工作流画成有向图，大约两行半高。
  - 第一行是主线：从首个可领取状态出发，沿连线走到终点状态的那条路；其余状态排在第二行，居中对齐到连向它的主线状态下面。
  - 连线是直角折线，箭头表示方向；两行之间的横线自动错开、不重叠。主线末尾是「+ 添加状态」，用虚线连接，输入名称后回车即新增（加在最后，还没有连线）。
  - 每个状态显示卡片数，以及可领取、锁定、终点的标记；可领取状态没有连到锁定状态时显示提示。
  - 鼠标放到状态上时，与它相连的连线高亮，状态右边缘出现一个圆点。
  - 连线：按住圆点拖到另一个状态上松手，即连一条线；已经连过的状态显示为已连接，松手不会重复连。
  - 改连：按住一条连线的箭头，拖到另一个状态上松手，这条连线改为指向那里；拖到空白处松手，即删除这条连线。点击连线选中后，按 `Delete` 或点 × 也能删除。
  - 拖动状态调整顺序。
  - 点击状态打开设置：名称、颜色、卡片形态、三个规则开关、删除（要二次确认，并写明卡片会移到哪里）。
- 状态块：每个状态是一个块，块的高度随卡片数量变化，标题旁显示顺序号、卡片数和规则说明。
  - 拖动块的标题摆放位置：块吸附到 12 栏网格上，并向上贴紧上方的块，块之间不留空隙；拖动块的右边缘调整宽度（按网格吸附）。块变宽后，块里的卡片排成多列。
  - 默认布局：各状态并排，每块占 3 栏。新增的状态放在当前最矮的那一栏下面。
  - 布局按白板保存在数据库里，并同步到所有窗口；工作流条末尾有「复原布局」，回到默认布局。
- 状态块里的卡片按所在状态的卡片形态显示：
  - 卡片：显示 ID、标题、评论数、标签；被持有的卡片还显示持有者和这一次的耗时（做过多次时下方显示累计耗时和第几次）；做过的卡片不在进行中时显示累计耗时和次数。
  - 单行：ID 和标题占一行；被持有的卡片右边显示持有者和心跳。终点状态里的单行前面打勾，标题划掉。
  - 磁贴：只显示 ID，横向排列，排满自动换行。同一块里的磁贴一样宽，宽度按这一块里最长的 ID 定；高 24px，手机上 36px。被持有的磁贴右上角是持有者颜色的心跳点，心跳晚了加警告色外框。鼠标放上去显示 ID、标题、标签，被持有的还显示持有者和这一次的耗时；手机上点开看详情。
  - 不带 ID 执行 `board claim` 时会被领走的那张卡片标为「下一张」（磁贴、单行用外框标出）；筛选时三种形态都是不匹配的淡出。
- 拖拽卡片可以调整状态内顺序或换状态，拖动时显示插入位置。拖到不允许的状态时，该块显示禁止原因；松手后卡片回到原位，并提示原因。
- 通过 CLI 或其他窗口做的修改，已打开的界面在 2 秒内显示出来，不需要刷新页面，被改动的卡片会短暂高亮并标出是谁做的。

- 主内容区：无限画布。
  - 每个项目是一个节点，用连线连到它的各块白板节点。
  - 白板节点显示名称、路径、各状态卡片数、正在工作的 agent，以及「打开」按钮。有 agent 在工作的白板，连线显示为流动状态。

  - 双击白板节点打开该白板；双击空白处新建项目；点项目节点右侧的「+」在该项目下新建白板。

### 10.5 未整理 Tab

- 侧栏：顶部是「记一条未整理」入口，下面是当前白板的未整理条目，侧栏标题旁显示条目数。条目显示 ID、标题、描述的第一行、标签、创建时间。

### 10.6 设置 Tab

- 侧栏：设置目录，点击跳到对应部分。

  - 外观：主题、卡片密度（舒适 / 紧凑）、动效（完整 / 减弱）
  - 白板规则：工作流与三个规则开关的说明，以及 §8 的规则摘要
  - Agent 接入：`board-skills` 的用法（§10.9）与安装（可复制 SKILL.md）、`board` 命令行的安装（按系统给出说明：Windows 随桌面端装好、macOS 给链接命令、其他情况从源码装）、连接服务端（`board login`，§9）、访问令牌（新建、列表、吊销，§3.1）、错误码

  - 账号：当前登录的 GitHub 账号（头像、名字、账号名）与「退出登录」；本机模式下显示不需要登录
  - 快捷键

### 10.7 新建（居中弹窗）

- 白板 Tab 的「新建卡片」入口和未整理 Tab 的「记一条未整理」入口都打开同一个居中弹窗。弹窗大小与卡片详情相同。

### 10.8 卡片详情（居中弹窗）

- 顶部：卡片 ID、所在状态、同状态内「上一张 / 下一张」及位置、「复制为提示词」、关闭。
- 左栏：
  - 标题、创建者和时间、标签（可以加或去）；
  - 被持有的卡片显示持有者、这一次的耗时、累计耗时、领取次数、心跳次数（各次领取收到的心跳之和，含 final）和异常退出次数，并有「强制释放」按钮，标题和描述只读；做过的卡片不在进行中时显示累计耗时；
  - 「未整理」的条目有「整理到<首个可领取状态>」按钮；

  - 底部操作栏：左边「删除」（删除前要二次确认），右边「派发」和「移动到」。「派发」只对可领取状态里、没有派发的卡片可用，打开对话框选机器和 agent（§10.12）。
- 右栏：动态（默认显示到最新一条）和评论框；评论框里可以粘贴截图或点回形针按钮上传附件。评论发出后输入框立即清空，动态底部先显示「发送中」，服务端确认后转成正式评论，失败时原文回到输入框。人发的评论悬停时有「编辑」按钮，点开后原地修改（⌘/Ctrl+Enter 保存、Esc 取消，空内容不能保存）。

### 10.9 复制为提示词

- agent 通过 skill 接入：`board-skills` 写明身份与白板的设置方法、处理卡片的步骤（先领取 → 按描述和验收标准干活、用评论记进度 → 交审；做不下去时评论原因，沿连线移到需要人处理的状态，例如「需人工校验」）、整理「未整理」条目的方法、§8 的规则和 §12 的错误码。skill 要求 agent 拿到卡片后第一条和这张卡片有关的命令就是 `board claim <ID>`：领取成功之前不读卡片、不看代码、不调研、不发这张卡片的进展，免得调研期间卡片被别人领走，也让耗时（从领取后的第一次心跳算起）包含全部实际工作。skill 随项目提供（`.agents/skills/board-skills/SKILL.md`，各家 agent 能自动识别；Claude Code 通过 `.claude/skills/board-skills` 链接识别）。
- 复制为提示词只复制一行 skill 调用，卡片的标题、描述、动态由 agent 用 CLI 自己读取：
  - 卡片：`/board-skills 开始执行 <项目>项目之中的<白板>白板中的#<ID>任务`（例如 `/board-skills 开始执行 mini项目之中的main白板中的#2任务`），一句完整的话就说清项目、白板、卡片编号。卡片详情的「复制为提示词」按钮和 `C` 键复制这一行。
  - 白板：`/board-skills <项目>/<白板>`，agent 循环执行不带 ID 的领取，直到 `EMPTY_TODO`。项目树和画布上白板的菜单里有这一项。
- skill 的参数也可以是一句话需求：agent 先用 `board new` 记到首个可领取状态，再按卡片处理。
- 复制后提示已复制的内容。

### 10.12 机器 Tab

- 活动栏图标：两层服务器。
- 侧栏：标题「机器」，右边 `在线数/总数`、「＋」（添加机器）；每台机器一行：状态点、名字、`在跑/上限`（暂停时写「暂停」，离线时写多久前在线），下面列出正在跑的卡片（agent 标记 + `#ID`）。点一行打开这台机器的详情。
- 主区（机位总览）：标题「机器」、一句说明、「添加机器」按钮；汇总条：在线台数 `x/总数`、在用的并发位 `x/总位数`（不算暂停和离线的机器）、排队张数、占用比例条；每台机器一张卡片，两列排：
  - 头部：系统图标、名字、系统和最近心跳（离线时写多久前在线）、状态胶囊（满载 / 在跑 / 空闲 / 暂停接单 / 离线）；
  - 并发位：上限是几就画几格。占用的格子显示 agent 标记、`#ID`、标题、已用分钟、最近心跳、来源（手动 / 定时）；空格子写「空位」，暂停时写「暂停」，离线时画斜纹写「离线」；
  - 有排队时列出排队的卡片；
  - 底部：本机 agent（默认的标「默认」）、定时领取的摘要（例如「每天 23:00、03:00」或「只接手动」）。
- 机器详情：与卡片详情同一种居中弹窗。顶栏：系统图标、状态胶囊、上一台 / 下一台（`↑↓` / `K J`）、关闭（`esc`）。左栏从上到下：名字和系统、board 版本、最近心跳；正在跑 `x/上限`（每个派发一行：agent 标记、`#ID`、标题、agent 名字、已用时间、最近心跳、来源，「日志」展开最后 500 行，「停止」）；排队（「等空位」或「等机器上线」、来源、排了多久，「取消派发」）；派发规则（同时跑几个 − / ＋、定时领取的开关和时间点列表、「现在领一轮」）；本机 agent（每种一个胶囊，带版本号，默认的标「默认」，点一下设为默认，没找到的置灰）；白板与目录；底部操作栏左边「移除机器」、右边「暂停接单 / 恢复接单」。右栏「最近」：这台机器最近 50 个结束的派发（agent、`#ID`、标题、结果、用时、结束时间），顶部写今天交审几个、异常退出几个。
- 添加机器：同样的居中弹窗，写两种方法：装了桌面端的电脑在「设置 → 本机」打开「让这台电脑接任务」；只有命令行的机器先 `board login`，再 `board host --name … --dir …`。
- 派发对话框（卡片详情的「派发」）：列出所有机器，每台显示在线 / 离线、`在跑/上限`、是否暂停接单；离线、已满、暂停的机器可以选，写明「会排队」；没有这块白板目录的机器不能选，写明「没有这块白板的目录」。选机器后列出它的本机 agent，没找到的不能选，默认选中这台机器的默认 agent。点「派发」后关闭对话框，卡片上出现派发状态。
- 白板上的卡片：有排队中的派发时写「排队 → <机器> · <agent>（原因）」；在跑时显示持有者和耗时（与领取相同）。

## 11. 实时同步

- 多个窗口、CLI 读写的是同一份数据。任一处的修改，其他已打开的界面在 2 秒内显示出来。
- 实时推送只发给已登录的界面和带令牌的 `board host`（§3.1、§9.1）。
- agent 上线（check）、下线（`board beat --final` 或心跳中断）和卡片状态变化时推送；只更新心跳时间的 `board beat` 不推送。
- 机器上线、离线、设置变化，以及派发的排队、开始、停止请求、结束时推送；推送里带上机器和派发的版本，`board host` 看到它变了就重新取自己的任务。只更新心跳时间的机器心跳不推送，机器页打开时每 10 秒刷新一次最近心跳。
- 项目画布上节点位置、工作流和状态块布局的修改也同步到所有窗口。

## 12. 错误码

| 错误码 | 出现时机 |
|---|---|
| `NO_IDENTITY` | CLI 没有提供 agent 名字。提示：先 `board check --as <名字>`，之后每条命令都带 `--as <名字>` |
| `NO_BOARD` | CLI 没有指定白板 |
| `BOARD_NOT_FOUND` | 指定的项目或白板不存在；或项目下有多块白板却只写了项目标识 |
| `NOT_FOUND` | 卡片不存在 |
| `EMPTY_TITLE` | 新建或编辑时标题为空 |
| `EMPTY_TODO` | 不带 ID 领取时，连到锁定状态的可领取状态里都没有卡片 |
| `NOT_IN_TODO` | 带 ID 领取的卡片不在可领取状态，且不是自己持有的卡片 |
| `ALREADY_HOLDING` | 该 agent 在这块白板上已经持有另一张卡片 |
| `NOT_HOLDER` | 编辑或移动被持有卡片的不是持有者 |
| `FORBIDDEN_COLUMN` | 把卡片直接移进锁定状态；agent 把卡片移入、移出终点状态或「未整理」；agent 不沿连线移动卡片；从没有连到锁定状态的可领取状态领取 |
| `USAGE` | 命令格式或参数不正确：未知的命令、未知的状态、项目里不存在的标签、缺少必需的参数、评论内容为空 |
| `NOT_LOGGED_IN` | 没有登录：界面没有登录会话；CLI 的环境变量和配置文件里都没有服务端地址或令牌（提示运行 `board login`）；用访问令牌做只能在界面上做的操作 |
| `INVALID_TOKEN` | 访问令牌不存在或已吊销 |
| `UNREACHABLE` | CLI 连不上服务端 |
| `NAME_TAKEN` | `board check` 的名字正被在线 agent 使用（HTTP 409） |
| `NAME_OFFLINE` | 名字没有 check，或心跳中断超过 50 秒：带令牌的卡片命令、上传附件、agent 级心跳被拒绝（HTTP 409）。原因：「名字不在线：没有 check，或心跳中断超过 50 秒，先 board check --as <名字>」 |
| `NOT_AUTHOR` | 修改不是自己发的评论：agent 修改任何评论，或人修改 agent 的评论（HTTP 403） |
| `HOST_NAME_TAKEN` | `board host` 的机器名正被另一个在线的 `board host` 使用（HTTP 409） |
| `ALREADY_DISPATCHED` | 派发的卡片已经有排队或正在跑的派发（HTTP 409） |
| `NO_SUCH_HOST` | 派发、修改、移除的机器不存在，含已移除的机器（HTTP 404） |
| `AGENT_NOT_ON_HOST` | 派发的 agent 不在这台机器上，或标为没找到（HTTP 409） |
| `BOARD_NOT_ON_HOST` | 派发的卡片所在白板在这台机器上没有目录（HTTP 409） |
| `DISPATCHED` | 卡片有排队中的派发，别的 agent 带 ID 领取它（HTTP 409） |

## 13. 验收标准

1–11 在同一块白板上执行，CLI 已登录（`board login`），名字已 check 并在发心跳，命令带上名字和白板（`--as`、`--board`，或 `BOARD_AS`、`BOARD`）；服务端和本机两种连接方式（§9）结果相同。

1. 「待办」从上到下是 #1、#2。α 执行 `board claim`，得到 #1；#1 进入「进行中」，持有者是 α。
2. 「待办」里只有 #1。α 和 β 同时执行 `board claim 1`：一个成功，另一个得到 `NOT_IN_TODO`。
3. α 持有 #1，再执行 `board claim`，得到 `ALREADY_HOLDING`。
4. α 持有 #1。β 执行 `board edit 1 --title x`，得到 `NOT_HOLDER`；β 执行 `board comment 1 "…"`，成功。
5. α 在 10:00 领取 #1，10:00:02 开始心跳并每 10 秒一次，10:20:05 发 final：动态里记「第 1 次耗时 20 分 3 秒」，卡片累计耗时 20 分 3 秒。
6. α 在 10:00 领取 #1，心跳到 10:10 后中断。10:10:50 时 #1 回到「待办」最上面，持有者为空，动态里记「心跳中断」「判定异常退出，第 1 次耗时约 10 分」。β 随后领取 #1；α 再执行 `board move 1 review`，得到 `NOT_HOLDER`。
7. α 持有 #1，执行 `board move 1 done`，得到 `FORBIDDEN_COLUMN`；执行 `board move 1 review` 成功，持有者清空。人把 #1 拖到「已完成」，成功。
8. 人把「待办」里的卡片拖进「进行中」：卡片回到原位，并显示原因。agent 执行 `board move 2 doing`，得到 `FORBIDDEN_COLUMN`。

## 14. 使用场景（不属于产品功能）

我们用 Board 自动维护开源项目时，会在 Board 之外运行下面这些程序。它们都只通过 CLI 访问白板，用 `board login` 写的配置连接服务端，开始时 `board check` 名字并启动心跳，每条命令带上名字和要操作的白板。

| 程序 | 怎么用 Board |
|---|---|
| issue 监听 | 发现新 issue 后，先用 `board ls --search gh#140` 查有没有卡片；没有就执行 `board new "<标题>" --body "gh#140 …"` |
| 社区监听 | 同上，用帖子链接查重 |
| 定期清理 | 发现需要清理的代码，执行 `board new` |
| 需求拆解 | 把需求拆成卡片，只 `board new`，不修改已有的卡片。一张卡 = 一次复盘 = 集成分支上的一个提交：同类别的小改动（界面、文案、图片）合成一张卡，描述里每项改动一个小节、带自己的验收标准；模块重构，改数据表、服务端接口、CLI 命令、skill 规则，以及其他改动各一张卡。不按前端、后端拆，不按步骤拆，有先后依赖的部分放在同一张卡里 |
| 执行 agent | 会话开始：`board check` 名字，启动后台心跳。循环执行：`board claim` 领卡片 → 在本会话的 worktree 里按描述干活，期间用 `board comment` 记进度 → 改代码的卡片：rebase 到集成分支，在 rebase 之后的代码上跑仓库规定的全部检查，压成一个最后一行是 `卡片：<项目>/<白板>#<ID>` 的提交，直接推到集成分支，推送被拒就重新 rebase、重新检查再推 → 评论改了什么、`提交：<sha>`、`检查：<结果>`，对这张卡片发 final，沿连线移到交审状态（默认工作流里是「待审核」）；做不下去就不推集成分支，把未完成的改动推到 `wip/<白板>/<ID>` 分支，用 `board comment` 写明原因和分支名，发 final，再沿连线把卡片移到需要人处理的状态（默认工作流里是「需人工校验」）。会话结束：停掉心跳，名字离线，删掉自己的 worktree |

代码仓库的 AGENTS.md / CLAUDE.md 写明集成分支（没写就用远端的默认分支）和推送前要跑的检查。不建卡片分支，不设专门的合并节点；每个会话在本机一个 worktree 里一张接一张地做卡片。agent 只按工作流的规则、连线和状态名称里的关键词认出首个可领取状态、交审状态和需要人处理的状态，不依赖具体的状态名。

人在界面上调整「待办」的顺序来决定先做什么。「待审核」里的卡片代码已经在集成分支上，人看卡片动态里的提交号、检查记录和提交本身复盘：没问题拖到「已完成」；有问题拖到「返工」并评论哪几项不对，领到它的 agent 在集成分支上再提交一次修复，不改写已经推上去的提交。「需人工校验」里是 agent 做不下去、等人处理的卡片。发版由人决定。没想清楚的事先记在「未整理」，整理好再放进「待办」。
