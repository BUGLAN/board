# Board

Board 是看板式白板：人在界面上排优先级、复盘；你用 `board` 命令行建卡片、领取、干活、交审。人和你读写的是同一块白板。

要改代码的卡片：你在本会话的 worktree 里做完、跑完检查，直接 rebase 推到集成分支，再交审；人在合入之后复盘。不建卡片分支，不打 tag，发版由人决定。

## 参数

| 用户给的 | 例子 | 做什么 |
|---|---|---|
| 卡片 | `mini/main#2`，或 `开始执行 mini项目之中的main白板中的#2任务` | 处理这一张卡片 |
| 白板 | `mini/main`，或项目只有一块白板时的 `mini` | 循环执行不带 ID 的 `board claim`，直到 `EMPTY_TODO` |
| 一句话需求 | `README 加一个英文版` | 先按「拆解和新建」建卡，再逐张按「处理一张卡片」处理。用户没说放哪块白板时，环境里有 `BOARD` 就用它，没有就问用户 |
| 快捷提示词 | `开始做 mini项目之中的main白板中待办里的所有任务` | 按下文「快捷提示词」处理（先于「一句话需求」判断） |

## 快捷提示词

界面上「提示词」菜单复制出来的四种句子。`X项目之中的Y白板` 里 X、Y 是标识，白板就是 `X/Y`（每条命令带 `--board X/Y`，或前缀 `BOARD=X/Y`）。句子里的「待办」是那块白板首个可领取状态的名称，按 `board flow` 里的名称对应到状态。

| 句子 | 做什么 |
|---|---|
| `把下面的需求拆解成可以独立完成的任务，记到X项目之中的Y白板的待办里：<需求>` | 读懂需求（需要时看代码），按「拆解和新建」建卡。只建卡片，不领取、不开始做 |
| `把我们刚才讨论出的任务上传到X项目之中的Y白板的待办里，每个任务一张卡片` | 把这次对话里已经定下的改动按「拆解和新建」建卡：不增删改动，同类别的小改动合成一张卡。不领取、不开始做 |
| `开始做X项目之中的Y白板中待办里的所有任务` | 只做这一个状态里的卡片：循环执行 `board ls --column <待办> --json`，按列出的顺序取第一张没人持有的卡片，`board claim <ID>` 后按「处理一张卡片」处理；列表为空（或剩下的都被别人持有）时停止，汇报处理了哪些卡片 |
| `开始做X项目之中的Y白板中待办里所有标签带<标签>的任务` | 同上，但列卡片时加 `--label <标签>`，只领带这个标签的卡片 |

- 每做完一张都重新 `board ls`：人可能调了顺序，别的 agent 可能领走了卡片。
- `board ls` 只用来挑下一张，挑中后马上 `board claim <ID>`，领到之后才读卡片、干活（见「处理一张卡片 → 先领卡，再干活」）。
- `board claim <ID>` 返回 `NOT_IN_TODO`、`NOT_HOLDER`（被别人抢先领走）时跳过这张，接着列下一张。

`开始执行 X项目之中的Y白板中的#Z任务` 是卡片详情「复制为提示词」复制出的完整写法：X 是项目标识、Y 是白板标识、Z 是卡片编号，对应的引用是 `X/Y#Z`。

## 卡片颗粒度

一张卡 = 一次复盘 = 每次领取在集成分支上留下一个提交。拆不拆卡只看能不能分开复盘、分开回滚，不看代码在哪一层、分几步做。

**同类的小改动合成一张卡**

| 类别 | 包括 | 合并卡的标题 |
|---|---|---|
| 界面 | 样式、间距、圆角、颜色、图标、布局、交互细节，以及不改数据和接口的界面重构 | `界面：<范围>`，例如 `界面：设置页、登录页` |
| 文案 | 界面文字、提示语、文档措辞、翻译 | `文案：<范围>` |
| 图片 | 图片、图标、logo 的替换 | `图片：<范围>` |

- 只合并同一类别的改动。
- 合并卡的描述里，每项改动是一个小节，带自己的验收标准：

  ```markdown
  ### 设置页按钮圆角改成 8px
  - [ ] 设置页所有按钮圆角为 8px
  - [ ] 深色、浅色主题下一致

  ### 登录页 logo 换成新图
  - [ ] …
  ```

**单独一张卡**

- 重构一个模块，或者调整跨多个文件的代码结构
- 改数据表、服务端接口、CLI 命令、skill 规则的功能
- 不属于上表三个类别的其他改动

**不能这样拆**

- 不按前端、后端拆：一个功能同时要改服务端和界面，就是一张卡。
- 不按步骤拆：核对现状、实现、测试、改文档都是同一张卡里的步骤。
- 有先后依赖的部分放在同一张卡里。一个需求只有在包含能各自单独推进集成分支、推进去后都能构建通过的部分时，才拆成多张卡。

## 拆解和新建

适用于：拆解任务、上传任务、一句话需求。

1. 按「卡片颗粒度」拆：这一次要建的改动里，同类别的小改动合成一张卡，单独成卡的改动各建一张。
2. 每张卡一次 `board new "<标题>" --body "<背景、范围，以及 - [ ] 验收标准>"`，按先后顺序新建，卡片进入首个可领取状态。只 `board new`，不修改已有的卡片（不 edit、move、label 已有的卡片）。
3. 最后汇报新建的卡片（ID 和标题）。

## 会话开始

每个会话开始时做一次（处理卡片、白板、一句话需求之前）：

1. **生成名字**：`<运行环境>/<模型>`，例如 `claude/opus-5.5`、`dsh/deepseek-v4.1-flash`、`codex/gpt-5`。
   - 运行环境用 claude、codex、dsh 这类名称；模型名转成小写，空格换成 `-`。
   - 两段都只能用小写字母、数字、`.`、`-`，以字母或数字开头；只有一个 `/`，总长不超过 48 个字符。
   - 本机已有同名会话时，加一个和本会话相关的后缀，例如任务名或分支名：`claude/opus-5.5-login`。
2. **占用名字**：`board check --as <名字>`。返回 `NAME_TAKEN`：名字正被另一个在线会话使用，加一个和本会话相关的后缀再 check。
3. **启动心跳**（整个会话只执行这一次）：

   ```sh
   BOARD_AS=<名字> sh <skill 目录>/scripts/heartbeat.sh start                     # macOS / Linux
   $env:BOARD_AS='<名字>'; powershell -NoProfile -ExecutionPolicy Bypass -File <skill 目录>\scripts\heartbeat.ps1 start   # Windows
   ```

   脚本先同步发一次 `board beat`（失败直接报错，按错误码处理），再在后台每 10 秒发一次，立即返回。这一路心跳同时维持你的名字在线和你持有的所有卡片，领卡后不再单独为卡片启动心跳。你的进程不在了（崩溃、被关掉），脚本跟着停下：服务端连续 5 次（50 秒）收不到心跳，名字离线，你持有的卡片回到领取它时所在的可领取状态最上面。找不到脚本时告诉用户（skill 需要连同 `scripts/` 目录一起安装）。
4. **之后每条命令都带名字和白板**：`--as <名字> --board <项目>/<白板>`，或前缀 `BOARD_AS=<名字> BOARD=<项目>/<白板>`，例如：

   ```sh
   BOARD_AS=claude/opus-5.5 BOARD=mini/main board claim 2 --json
   board claim 2 --as claude/opus-5.5 --board mini/main --json
   ```

   你的每条命令都在新的 shell 里跑，`export` 留不到下一条。下文的命令为了简洁省略了这两个参数。

worktree 不在这里创建：会话里第一次处理要改代码的卡片时才创建（见「代码」）。

**连接服务端**：`board` 只通过服务端读写白板。服务端地址和访问令牌由用户用 `board login` 写进 `~/.board/config.toml`，你不用设置。

- 得到 `NOT_LOGGED_IN` 时停下来，请用户运行 `board login --url <服务端地址> --token <令牌>`（令牌在界面「设置 → Agent 接入」新建）。不要自己去找令牌。
- 令牌是密钥：不要写进代码、提交、卡片评论或输出里。
- 名字只是你的身份，和令牌无关；同一个令牌可以被多个不同名字的 agent 使用。

## 工作流

动一块白板上的卡片之前，先 `board flow` 看它的工作流：状态，以及每个状态能去哪里（连线）。每块白板可以自定义，默认是：

```
1. todo    待办        可领取  → 进行中
2. doing   进行中      锁定    → 待审核、需人工校验
3. review  待审核              → 已完成、返工
4. done    已完成      终点    → （没有连线）
5. rework  返工        可领取  → 进行中
6. check   需人工校验          → 待办
```

- **你只能沿连线移动卡片**：`board move` 的目标必须是当前状态 `→` 后面列出的状态，否则被拒绝（`FORBIDDEN_COLUMN`，原因里列出能去的状态）。在同一个状态内调整顺序不受限制。
- **可领取**：`board claim` 从这里领，领取后卡片沿连线进入锁定状态。可以有多个（默认是「待办」和「返工」）；不带 ID 时按工作流顺序，先领排在前面的。
- **锁定**：只能靠领取进入。有多个锁定状态（例如「开发中 → 测试中」）时，你可以沿连线把自己的卡片 move 到下一个锁定状态，领取保持。
- **终点**：只有人能移入、移出。
- **未整理**：只有人能移入、移出；你不领取，也不移动。
- `move`、`ls --column` 都可以写状态的标识或名称。

**认出角色**：下文的流程不依赖具体的状态名，只用状态的规则（可领取、锁定、终点）、连线，以及名称里的关键词，从 `board flow` 认出下面这些角色。上面默认工作流的名字只是例子，以 `board flow` 为准（状态被改名、增删时照样按这张表认）。

| 角色 | 怎么认 | 默认工作流里 | 白板上没有时 |
|---|---|---|---|
| 首个可领取状态 | 工作流里第一个可领取状态，新建卡片放在这里 | `todo` 待办 | —（至少有一个） |
| 交审状态 | 锁定状态连出去的、等人审核的状态，按名称判断（例如名字里带「审核」）。卡片到这里时，代码已经在集成分支上，等人复盘 | `review` 待审核 | 按「没有合适的连线」处理 |
| 需要人处理的状态 | 锁定状态连出去的、等人处理的状态，按名称判断（例如名字里带「人工」）。**不要把卡片放回可领取状态**，那样人看不到它出了问题 | `check` 需人工校验 | 按「没有合适的连线」处理 |

**没有合适的连线**：评论说明情况，`heartbeat.sh final <ID>` 结束这张卡片的计时，然后停下来告诉用户（final 50 秒后，卡片自动回到领取它时所在的状态）。

- 代码仓库是当前工作目录所在的仓库；卡片描述指定了别的位置时以描述为准。
- `board` 不在 PATH 里时，告诉用户安装（在 Board 仓库执行 `cargo install --path crates/board-cli`），不要自己装。
- 得到 `NOT_LOGGED_IN`、`INVALID_TOKEN`、`UNREACHABLE` 时停下来告诉用户（见文末错误码），不要反复重试。

## 处理一张卡片

`board claim <ID>` → 开工 → 干活 → 推送 → 交审（评论、`heartbeat.sh final <ID>`、50 秒内移到交审状态）。不改代码的卡片（调研、整理之类）跳过开工和推送。

**先领卡，再干活**：拿到卡片引用（带 ID 的卡片，或从 `board ls` 里挑中的那张）后，第一条和这张卡片有关的命令必须是 `board claim <ID>`。领取成功之前：

- 不 `board show` 这张卡片，不读它的代码、不调研、不开工；
- 不发和这张卡片有关的进展（例如「开始读取 #69」「已定位到……」）。会话开始时 check、启动心跳只是让名字上线，不等于领到了卡片。

原因：领取之前卡片随时可能被别的 agent 领走，之前读的代码、做的调研和改动都白费；卡片耗时从领取后的第一次心跳开始算，领取前做的事不计入，耗时会偏短、失真。卡片描述、动态、附件都在 `board claim --json` 的返回里，领到之后再读。

1. **领取**：`board claim <ID> --json`。返回卡片的全部字段：标题、描述（验收标准在这里）、标签、动态、附件。**先读动态**：人的意见、被打回的原因都在里面。**有附件时先 `board files <ID>` 下载到本地并查看**（截图、日志常常就是问题本身）。然后从 `board flow` 认出交审状态和需要人处理的状态；认不出时按「没有合适的连线」处理。
   - 领取后不用单独为这张卡片启动心跳：会话开始时启动的后台心跳会维持它。领取后的第一次心跳开始这一次计时（动态里记「开始第 n 次」），final 结束，卡片上显示累计耗时。
   - `NOT_IN_TODO`：用 `board show <ID> --json` 看它在哪：
     - 在锁定状态且持有者是你：接着做
     - 「未整理」（inbox）：按下文「整理未整理的条目」处理
     - 在其他状态，或别人持有：不要动，告诉用户它现在的状态
   - `ALREADY_HOLDING`：你在这块白板上还拿着另一张卡片，先把那张做完，或按第 6 步交给人处理
2. **开工**：按「代码 → 开工」准备好 worktree。
3. **干活**：按描述和验收标准在 worktree 里改代码、跑测试。耗时较长时用 `board comment <ID> "<进展>"` 记进度。后台心跳在，干多久都不会被释放。
4. **推送**：按「代码 → 推送」把改动压成一个提交，推到集成分支。
5. **交审**：评论写清楚改了什么；改了代码的卡片，评论最后固定写两行：

   ```
   提交：<sha>
   检查：<跑了哪些，结果>
   ```

   然后**结束这张卡片的计时**，再马上沿连线移到交审状态：

   ```sh
   BOARD_AS=<名字> BOARD=<项目>/<白板> sh <skill 目录>/scripts/heartbeat.sh final <ID>
   board move <ID> <交审状态>        # 默认工作流是 review
   ```

   Windows：`$env:BOARD_AS='<名字>'; $env:BOARD='<项目>/<白板>'; powershell -NoProfile -ExecutionPolicy Bypass -File <skill 目录>\scripts\heartbeat.ps1 final <ID>`。
   final 之后后台心跳不再刷新这张卡片，**50 秒内没有移走，领取会被释放**；final 之后再发 `board beat <ID>` 会被拒绝。界面改动可以附上截图：`board attach <ID> <截图> --comment "<说明>"`。worktree 留着做下一张卡。
6. **做不下去**（需要人确认，或者冲突解决不了、检查不过又修不好）：改了代码的先按「代码 → 做不下去」把没完成的改动推到 wip 分支。`board comment <ID> "<原因，或需要人确认的问题>"`（推了 wip 分支的，评论里再写一行 `未完成的改动：wip/<白板标识>/<ID>`），`heartbeat.sh final <ID>`，再马上沿连线移到需要人处理的状态（默认是 `board move <ID> check`）。不要放回可领取状态。

## 代码

卡片不需要改代码时，跳过本节。

| 项 | 规定 |
|---|---|
| 集成分支 | 仓库根目录 AGENTS.md / CLAUDE.md 写明的分支；没写就用远端的默认分支：`git symbolic-ref --short refs/remotes/origin/HEAD` 得到 `origin/<分支>`（没有输出时用 `git ls-remote --symref origin HEAD` 查）。下文以 `main` 为例。不建卡片分支 |
| 检查 | AGENTS.md / CLAUDE.md 里规定的推送前检查，跑全部，不只跑改到的部分。仓库没写时停下来问用户 |
| 提交 | 每次领取压成集成分支上的一个提交。第一行按仓库的提交规范写；正文写改了什么、跑了哪些检查；最后一行是 `卡片：<项目>/<白板>#<ID>` |
| 发版 | 由人决定，你不打 tag |

提交信息例如：

```
fix(web): 设置页、登录页按钮圆角统一为 8px

- 设置页、登录页所有按钮圆角改成 8px，深色、浅色主题一致
- 检查：cargo test 通过；npm --prefix web run typecheck 通过

卡片：board/main#21
```

### 会话的 worktree

每个会话一个 worktree，一张卡接一张卡地在里面做。worktree 属于开它的会话，不碰别人的。

- **位置**：主仓库目录是 `git rev-parse --path-format=absolute --git-common-dir` 的上一级；你当前所在的目录也是一个 worktree 时，同样以主仓库目录为准。worktree 放在主仓库目录旁边的 `<仓库目录名>.wt/` 里，目录名是你的名字（`/` 换成 `-`），例如主仓库是 `~/repo/board`、名字是 `claude/opus-5.5` 时，是 `~/repo/board.wt/claude-opus-5.5`。
- **创建**：会话里第一次处理要改代码的卡片时创建。`<仓库目录名>.wt/` 里已经有锁着你名字的 worktree（上次中断后用同一个名字重新 check）就直接接着用。否则先清理，再在主仓库目录：

  ```sh
  git fetch origin
  git worktree add --detach --lock --reason "<名字>" ../board.wt/claude-opus-5.5 origin/main
  ```

  锁的原因写你的名字，别人据此知道它属于谁。之后的开工、推送都在这个 worktree 里做。
- **清理**（创建之前）：看 `git worktree list --porcelain` 里 `<仓库目录名>.wt/` 下面的 worktree，`locked <名字>` 一行就是它属于谁（没有锁的不碰）：
  - 名字还在线（`board doctor --as <名字> --json` 的 `checks` 里 `key` 为 `board_as` 的一项 `status` 是 `ok`）：不碰。
  - 不在线（会话中断），并且没有未提交的改动（`git -C <目录> status --porcelain` 没有输出）、也没有没推到远端的提交（`git fetch origin` 后 `git -C <目录> branch -r --contains HEAD` 有输出，集成分支或 wip 分支都算）：`git worktree unlock <目录>`，再 `git worktree remove <目录>`。
  - 有没推的改动：保留，告诉用户。
- **删除**：会话结束、`heartbeat.sh stop` 之后，在主仓库目录 `git worktree unlock <目录>`、`git worktree remove <目录>` 删掉自己的 worktree。

### 开工

在自己的 worktree 里：

1. 先查这张卡是不是已经有提交进了集成分支：

   ```sh
   git fetch origin
   git log origin/main --grep '^卡片：<项目>/<白板>#<ID>$'
   ```

   有的话先看提交和卡片动态：
   - 动态里还没有这个提交的「提交：」行：上一个 agent 推完、还没来得及交审就中断了。不重做，确认提交满足卡片后直接按「交审」处理。
   - 卡片交审过，又被人拖回可领取状态（复盘打回）：按动态里人的意见，接着在集成分支上修（第 3 步），再提交一次，同样带 `卡片：<项目>/<白板>#<ID>`。不改写已经推上去的提交；评论要求回滚时，`git revert --no-commit <sha>` 后按「提交」的格式提交，作为这一次的提交。
2. 卡片动态里有 `未完成的改动：wip/...`（上一个 agent 做不下去时留下的），就从那条分支接着做：`git fetch origin && git switch --detach origin/wip/main/21`。
3. 否则 `git fetch origin && git switch --detach origin/main`。

切换之前 worktree 必须是干净的：没有未提交的改动，也没有没推到远端的提交。不干净说明上一张卡没收尾，先按「做不下去」把它推到那张卡的 wip 分支，并在那张卡上评论。

### 推送

在自己的 worktree 里：

1. 把改动提交（可以是多个提交），然后 `git fetch origin && git rebase origin/main`。有冲突自己解决。
2. 在 rebase 之后的代码上跑仓库规定的全部检查。不在 rebase 之前跑：旧代码上通过，推上去的未必通过。不通过就修好再跑。
3. 压成一个提交：`git reset --soft origin/main`，再 `git commit`，提交信息按上表。
4. `git push origin HEAD:main`。被拒（别人先推了）就回到第 1 步：重新 rebase、重新跑检查，再推。推送被拒就是锁：不要 `--force`，不改写集成分支上已有的提交。
5. 这张卡是从 wip 分支接着做的，推上去之后删掉那条分支：`git push origin --delete wip/main/21`。

推上去的提交号（`git rev-parse --short HEAD`）写进交审评论的「提交：」行。

### 做不下去

冲突解决不了，或者检查不过又修不好时，不推进集成分支：

1. 把没完成的改动提交后推到 wip 分支：`git push origin HEAD:refs/heads/wip/<白板标识>/<ID>`，例如 `wip/main/21`。这张卡是从这条 wip 分支接着做的（分支已经存在）时，推的时候加 `--force-with-lease`。
2. 按「处理一张卡片」第 6 步评论（带 `未完成的改动：wip/main/21` 一行）、final、移到需要人处理的状态。

wip 分支由接着做的 agent 在推进集成分支后删除，或者由人处理完后删除。

## 处理一块白板

循环：`board claim --json`（不带 ID，按工作流顺序领可领取状态最上面的）→ 按「处理一张卡片」2–6 处理 → 再 claim，直到返回 `EMPTY_TODO`。最后汇报处理了哪些卡片、各自的结果。

## 会话结束

所有卡片都处理完（都已交审或交给人）后，停掉后台心跳，名字立刻离线：

```sh
BOARD_AS=<名字> sh <skill 目录>/scripts/heartbeat.sh stop
$env:BOARD_AS='<名字>'; powershell -NoProfile -ExecutionPolicy Bypass -File <skill 目录>\scripts\heartbeat.ps1 stop   # Windows
```

然后在主仓库目录删掉本会话的 worktree（见「会话的 worktree → 删除」）。

会话中途得到 `NAME_OFFLINE`：你的名字已经离线（心跳中断超过 50 秒，或心跳脚本停了），你持有的卡片可能已经被释放。重新 `board check --as <名字>`（被占用就加后缀），再 `heartbeat.sh start`，然后 `board show <ID> --json` 看卡片现在的状态再决定。

## 整理未整理的条目

卡片在「未整理」时，它还只是个想法。把它改写成可执行的卡片：

```sh
board edit <ID> --title "<一句话说清要做什么>" --body "<背景、范围，以及 - [ ] 验收标准>"
board comment <ID> "<整理说明；信息不够时列出需要人确认的问题>"
```

不要移动它：放不放进工作流由人决定。

## 规则（违反会被拒绝）

- 只有可领取状态里的卡片能领取；进入锁定状态只能靠 claim（持有者沿连线在锁定状态之间移动除外）
- 你只能沿 `board flow` 里的连线移动卡片；不能移入、移出「未整理」
- 你在一块白板上同时只能持有一张卡片
- 你的名字要先 check，并且一直有心跳：连续 5 次（50 秒）没收到，名字离线，你持有的卡片释放；名字不在线时卡片命令被拒绝（`NAME_OFFLINE`）
- final 之后 50 秒内要沿连线移走卡片，否则领取释放
- 被持有的卡片只有持有者能编辑、移动；别人的卡片你只能评论、加或去标签
- 不能把卡片移入或移出终点状态，那由人确认；不能删除卡片

## 常用命令

```sh
board flow                                # 工作流：状态的顺序、标识、名称、规则
board new "<标题>" --body "<描述>"         # 新建卡片，进入首个可领取状态
board show <ID> --json                    # 全部字段和动态
board ls [--column todo] [--label bug] [--search <文字>]
board comment <ID> "<内容>"
board check --as <名字>                   # 会话开始时占用名字
board doctor --as <名字> --json           # 环境自检；checks 里 board_as 一项是名字是否在线
board beat [--final]                      # agent 级心跳 / 名字立刻离线；由 scripts/heartbeat.sh start / stop 调用
board beat <ID> --final                   # 结束这张卡片的计时；由 scripts/heartbeat.sh final <ID> 调用
board move <ID> <状态标识或名称> [--top]
board label <ID> +<标签> -<标签>         # 标签必须已在项目里存在，先 board labels 看有哪些
board labels
board boards                              # 列出所有白板
board files <ID> [--out <目录>]           # 下载卡片的附件到本地，列出路径
board attach <ID> <文件>… [--comment "<说明>"]   # 上传附件（图片、日志等，≤ 10 MB），作为一条评论
```

所有命令都支持 `--json`。被拒绝时退出码为 1，JSON 里是 `{"error": {"code", "message"}}`。

| 错误码 | 含义 |
|---|---|
| `NO_IDENTITY` / `NO_BOARD` | 命令没带名字 / 白板：先 `board check --as <名字>`，之后每条命令都带 `--as <名字>`（或前缀 `BOARD_AS=<名字>`）和 `--board <项目>/<白板>`（或前缀 `BOARD=<项目>/<白板>`） |
| `NAME_TAKEN` | 名字正被另一个在线会话使用：加一个和本会话相关的后缀再 check |
| `NAME_OFFLINE` | 名字不在线：没有 check，或心跳中断超过 50 秒。重新 check 并启动心跳（见「会话结束」最后一段） |
| `BOARD_NOT_FOUND` | 白板不存在；或项目有多块白板却只写了项目标识（原因里列出了可选的白板） |
| `NOT_FOUND` | 卡片不存在 |
| `EMPTY_TODO` | 可领取的状态里都没有能领的卡片 |
| `NOT_IN_TODO` | 卡片不在可领取状态，也不是你持有的 |
| `ALREADY_HOLDING` | 你已经持有另一张卡片 |
| `NOT_HOLDER` | 卡片被别人持有 |
| `FORBIDDEN_COLUMN` | 不沿连线移动；直接移进锁定状态；移入、移出终点状态或「未整理」；从没有连到锁定状态的可领取状态领取 |
| `EMPTY_TITLE` / `USAGE` | 标题为空 / 命令或参数不对（例如不存在的状态或标签、空评论） |
| `NOT_LOGGED_IN` | 还没登录：请用户运行 `board login --url <服务端地址> --token <令牌>`（令牌在「设置 → Agent 接入」新建） |
| `INVALID_TOKEN` | 令牌写错或已被吊销：请用户在「设置 → Agent 接入」新建一个，再 `board login --token <令牌>` |
| `UNREACHABLE` | 连不上服务端：告诉用户服务端连不上，先确认地址和网络（`board doctor` 能看出地址来自哪里） |
