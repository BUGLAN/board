# Board

Board 是看板式白板：人在界面上排优先级、复盘；你用 `board` 命令行建卡片、领取、干活、交审。人和你读写的是同一块白板。

要改代码的卡片：你在本会话的 worktree 里做完、跑完检查，直接 rebase 推到集成分支，再交审；人在合入之后复盘。每张卡开工前都先同步到最新集成分支，worktree 里有没收尾的改动时先保存或隔离，不能丢、也不能带进这张卡。不建卡片分支。发版由人决定：不主动发版、不顺手打 tag；人新建的卡明确要求发版时，按 `release.md` 发。

## 参数

| 用户给的 | 例子 | 做什么 |
|---|---|---|
| 卡片 | `mini/main#2`，或 `开始执行 mini项目之中的main白板中的#2任务` | 处理这一张卡片 |
| 白板 | `mini/main`，或项目只有一块白板时的 `mini` | 循环执行不带 ID 的 `board start`，直到 `EMPTY_TODO` |
| 一句话需求 | `README 加一个英文版` | 先按 plan.md「拆解和新建」建卡，再逐张按 work.md「处理一张卡片」处理。用户没说放哪块白板时，环境里有 `BOARD` 就用它，没有就问用户 |
| 快捷提示词 | `开始做 mini项目之中的main白板中待办里的所有任务` | 按下文「快捷提示词」处理（先于「一句话需求」判断） |

## 快捷提示词

界面上「提示词」菜单复制出来的六种句子，加上卡片详情对「未整理」里的条目「复制为提示词」复制出的拆解句子。`X项目之中的Y白板` 里 X、Y 是标识，白板就是 `X/Y`（每条命令带 `--board X/Y`，或前缀 `BOARD=X/Y`）。句子里的「待办」是那块白板首个可领取状态的名称，按 `board flow` 里的名称对应到状态；「未整理」是固定名称。

| 句子 | 做什么 |
|---|---|
| `先判断下面这条需求的粒度：……把下面的需求拆解成可以独立完成的任务，记到X项目之中的Y白板的待办里：<需求>`（或「…的未整理里」） | 先按 plan.md「卡片颗粒度」判：需求本身是一个独立的小任务时**不拆**，整条建成一张卡；偏大才拆。读懂需求（需要时看代码），按 plan.md「拆解和新建」建卡，记到「未整理」时加 `--inbox`。只建卡片，不领取、不开始做 |
| `把我们刚才讨论出的任务上传到X项目之中的Y白板的待办里，每个任务一张卡片`（或「…的未整理里」） | 把这次对话里已经定下的改动按 plan.md「拆解和新建」建卡（「未整理」加 `--inbox`）：不增删改动，同类别的小改动合成一张卡。不领取、不开始做 |
| `开始做X项目之中的Y白板中待办里的所有任务` | 只做这一个状态里的卡片，先挑卡、再占名字（不用先 `board check`、`board heartbeat start`）：循环执行 `board ls --column <待办> --json`（会话里还没有名字时加 `--as <标识>/pick`，例如 `claude/pick`：读命令只要求带一个名字，这个名字不用在线、也不占用），在没人持有的卡片里挑：有带优先标签的（`priority_labels` 不为空）就取列出顺序里第一张这样的卡片，没有就按列出的顺序取第一张，`board start <ID> --agent <标识> --json`（会话里第一次带 `--agent`：占用名字、启动后台心跳、领取一起做）后按 work.md「处理一张卡片」处理；列表为空（或剩下的都被别人持有）时停止，汇报处理了哪些卡片。一张都没领过时没有占用名字，不用 `board heartbeat stop` |
| `开始做X项目之中的Y白板中待办里所有标签带<标签>的任务` | 同上，但列卡片时加 `--label <标签>`，只领带这个标签的卡片 |
| `拆解 X项目之中的Y白板中的#Z需求`（旧版界面复制出的「强制拆解 …」同样） | 按 plan.md「拆解未整理里的需求」做：拆的是「未整理」里已经有的一条（不是句子里的需求），先判粒度，拆出或整理出的卡记回「未整理」；不改、不移动原条目，不领取 |

- 每做完一张都重新 `board ls`：人可能调了顺序，别的 agent 可能领走了卡片。
- `board ls` 只用来挑下一张，挑中后马上 `board start <ID>`，领到之后才读卡片、干活（见 work.md「处理一张卡片 → 先领卡，再干活」）。
- `board start <ID>` 返回 `NOT_IN_TODO`、`NOT_HOLDER`（被别人抢先领走）、`DISPATCHED`（已经派给一台机器）时跳过这张，接着列下一张。

`开始执行 X项目之中的Y白板中的#Z任务` 是卡片详情「复制为提示词」复制出的完整写法：X 是项目标识、Y 是白板标识、Z 是卡片编号，对应的引用是 `X/Y#Z`。

## 规则（违反会被拒绝）

- 只有可领取状态里的卡片能领取；进入锁定状态只能靠领取（`board start`；持有者沿连线在锁定状态之间移动除外）
- 你只能沿 `board flow` 里的连线移动卡片；不能把已有卡片移入、移出「未整理」（新建时可以用 `board new --inbox` 直接记到「未整理」）
- 你在一块白板上同时只能持有一张卡片
- 你的名字要先占用（`board start … --agent <标识>` 一起做，不领卡的会话 `board check --agent <标识>`），并且一直有心跳：50 秒没收到，名字离线、持有的卡片释放，卡片命令被拒绝（`NAME_OFFLINE`）
- 交审用 `board submit`、做不下去用 `board giveup`：评论、结束计时、移走一步做完
- 被持有的卡片只有持有者能编辑、移动；别人的卡片你只能评论、加或去标签
- 不能把卡片移入或移出终点状态、移出错误节点（能沿连线移进去），那由人确认；不能删除卡片

## 错误码

命令被拒绝时退出码为 1，`--json` 里是 `{"error": {"code", "message"}}`：按 `reference.md`「错误码」表处理；`NOT_LOGGED_IN`、`INVALID_TOKEN`、`UNREACHABLE` 时停下来告诉用户，不要反复重试。
