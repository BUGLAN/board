# Board

Board 是看板式白板：人在界面上排优先级、复盘；你用 `board` 命令行建卡片、领取、干活、交审。人和你读写的是同一块白板。

要改代码的卡片：你在本会话的 worktree 里做完、跑完检查，直接 rebase 推到集成分支，再交审；人在合入之后复盘。不建卡片分支，不打 tag，发版由人决定。

## 按场景读哪个文件

这一页是总纲：参数、快捷提示词、规则。其余内容按场景放在本 skill 目录里（和 SKILL.md 同一层），做到那一步时再读；一次要做几件事就都读。

| 要做的事 | 读 |

| 处理一张卡片、处理一块白板、快捷提示词「开始做…待办里的…任务」 | `work.md`（会话开始、处理一张卡片、代码、处理一块白板、会话结束），动卡片之前读 `reference.md`「工作流」认角色 |

## 参数

| 用户给的 | 例子 | 做什么 |
|---|---|---|
| 卡片 | `mini/main#2`，或 `开始执行 mini项目之中的main白板中的#2任务` | 处理这一张卡片 |
| 白板 | `mini/main`，或项目只有一块白板时的 `mini` | 循环执行不带 ID 的 `board claim`，直到 `EMPTY_TODO` |
| 一句话需求 | `README 加一个英文版` | 先按 plan.md「拆解和新建」建卡，再逐张按 work.md「处理一张卡片」处理。用户没说放哪块白板时，环境里有 `BOARD` 就用它，没有就问用户 |
| 快捷提示词 | `开始做 mini项目之中的main白板中待办里的所有任务` | 按下文「快捷提示词」处理（先于「一句话需求」判断） |

## 快捷提示词

界面上「提示词」菜单复制出来的六种句子，加上卡片详情对「未整理」里的条目「复制为提示词」复制出的拆解句子。`X项目之中的Y白板` 里 X、Y 是标识，白板就是 `X/Y`（每条命令带 `--board X/Y`，或前缀 `BOARD=X/Y`）。句子里的「待办」是那块白板首个可领取状态的名称，按 `board flow` 里的名称对应到状态；「未整理」是固定名称。

| 句子 | 做什么 |
|---|---|
| `把下面的需求拆解成可以独立完成的任务，记到X项目之中的Y白板的待办里：<需求>` | 读懂需求（需要时看代码），按 plan.md「拆解和新建」建卡。只建卡片，不领取、不开始做 |
| `把我们刚才讨论出的任务上传到X项目之中的Y白板的待办里，每个任务一张卡片` | 把这次对话里已经定下的改动按 plan.md「拆解和新建」建卡：不增删改动，同类别的小改动合成一张卡。不领取、不开始做 |
| `把下面的需求拆解成可以独立完成的任务，记到X项目之中的Y白板的未整理里：<需求>` | 读懂需求（需要时看代码），按 plan.md「拆解和新建」用 `board new ... --inbox` 建卡。只建卡片，不领取、不开始做 |
| `把我们刚才讨论出的任务上传到X项目之中的Y白板的未整理里，每个任务一张卡片` | 把这次对话里已经定下的改动按 plan.md「拆解和新建」用 `board new ... --inbox` 建卡：不增删改动，同类别的小改动合成一张卡。不领取、不开始做 |
| `开始做X项目之中的Y白板中待办里的所有任务` | 只做这一个状态里的卡片：循环执行 `board ls --column <待办> --json`，在没人持有的卡片里挑：有带优先标签的（`priority_labels` 不为空）就取列出顺序里第一张这样的卡片，没有就按列出的顺序取第一张，`board claim <ID>` 后按 work.md「处理一张卡片」处理；列表为空（或剩下的都被别人持有）时停止，汇报处理了哪些卡片 |
| `开始做X项目之中的Y白板中待办里所有标签带<标签>的任务` | 同上，但列卡片时加 `--label <标签>`，只领带这个标签的卡片 |
| `拆解 X项目之中的Y白板中的#Z需求` | 按 plan.md「拆解未整理里的需求」：读这条（描述、附件、评论），按 plan.md「卡片颗粒度」拆，每张 `board new --inbox --from Z`，原需求里的图片按 plan.md「拆解和新建」第 3 步挂到对应的卡；最后在原条目上评论拆成了哪几张（`#a 标题`、`#b 标题`…）。不改、不移动原条目，不领取 |

- 每做完一张都重新 `board ls`：人可能调了顺序，别的 agent 可能领走了卡片。
- `board ls` 只用来挑下一张，挑中后马上 `board claim <ID>`，领到之后才读卡片、干活（见 work.md「处理一张卡片 → 先领卡，再干活」）。
- `board claim <ID>` 返回 `NOT_IN_TODO`、`NOT_HOLDER`（被别人抢先领走）、`DISPATCHED`（已经派给一台机器）时跳过这张，接着列下一张。

`拆解 X项目之中的Y白板中的#Z需求` 和「把下面的需求拆解成……记到X项目之中的Y白板的待办里」不同：前者拆的是白板上「未整理」里已经有的一条，拆出的卡记回「未整理」；后者拆的是句子里的需求，人明确说了放进「待办」。

`开始执行 X项目之中的Y白板中的#Z任务` 是卡片详情「复制为提示词」复制出的完整写法：X 是项目标识、Y 是白板标识、Z 是卡片编号，对应的引用是 `X/Y#Z`。

## 规则（违反会被拒绝）

- 只有可领取状态里的卡片能领取；进入锁定状态只能靠 claim（持有者沿连线在锁定状态之间移动除外）
- 你只能沿 `board flow` 里的连线移动卡片；不能把已有卡片移入、移出「未整理」（新建时可以用 `board new --inbox` 直接记到「未整理」）
- 你在一块白板上同时只能持有一张卡片
- 你的名字要先 check，并且一直有心跳：连续 5 次（50 秒）没收到，名字离线，你持有的卡片释放；名字不在线时卡片命令被拒绝（`NAME_OFFLINE`）
- final 之后 50 秒内要沿连线移走卡片，否则领取释放
- 被持有的卡片只有持有者能编辑、移动；别人的卡片你只能评论、加或去标签
- 不能把卡片移入或移出终点状态，那由人确认；不能删除卡片

## 错误码

命令被拒绝时退出码为 1，`--json` 里是 `{"error": {"code", "message"}}`：按 `reference.md`「错误码」表处理；`NOT_LOGGED_IN`、`INVALID_TOKEN`、`UNREACHABLE` 时停下来告诉用户，不要反复重试。
