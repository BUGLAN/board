# board-skills：拆解建卡、整理未整理（plan.md）

`/board-skills` 的分文件：卡片颗粒度、拆解和新建、拆解未整理里的需求、整理未整理的条目。先读 SKILL.md；名字、心跳、命令参数见 work.md「会话开始」，常用命令见 reference.md。

## 卡片颗粒度

一张卡 = 一次复盘 = 每次领取在集成分支上留下一个提交。拆不拆卡只看能不能分开复盘、分开回滚，不看代码在哪一层、分几步做。

**同类的小改动合成一张卡**

| 类别 | 包括 | 合并卡的标题 |
|---|---|---|
| 界面 | 样式、间距、圆角、颜色、图标、布局、交互细节，以及不改数据和接口的界面重构 | `界面：<范围>`，例如 `界面：设置页、登录页` |
| 文案 | 界面文字、提示语、文档措辞、翻译 | `文案：<范围>` |
| 图片 | 图片、图标、logo 的替换 | `图片：<范围>` |

- 只合并同一类别的改动。
- 合并卡的描述里，每项改动是一个小节，带自己的验收标准：

  ```markdown
  ### 设置页按钮圆角改成 8px
  - [ ] 设置页所有按钮圆角为 8px
  - [ ] 深色、浅色主题下一致

  ### 登录页 logo 换成新图
  - [ ] …
  ```

**单独一张卡**

- 重构一个模块，或者调整跨多个文件的代码结构
- 改数据表、服务端接口、CLI 命令、skill 规则的功能
- 不属于上表三个类别的其他改动

**不能这样拆**

- 不按前端、后端拆：一个功能同时要改服务端和界面，就是一张卡。
- 不按步骤拆：核对现状、实现、测试、改文档都是同一张卡里的步骤。
- 有先后依赖的部分放在同一张卡里。一个需求只有在包含能各自单独推进集成分支、推进去后都能构建通过的部分时，才拆成多张卡。

## 拆解和新建

适用于：拆解任务、上传任务、一句话需求。

1. 按「卡片颗粒度」拆：这一次要建的改动里，同类别的小改动合成一张卡，单独成卡的改动各建一张。
2. **描述要自包含**：领卡的 agent 可能在另一台电脑上，看不到你这台电脑上的文件。
   - 不能只写 `来源：<本地文件路径>`（`E:\…`、`C:\Users\…`、`/Users/…`、`~/…`、会话的临时目录都算）。把需求里和这张卡相关的原文、关键内容直接写进描述（照原文引用，不改写意思），或者把整段需求作为描述的一部分；可以注明出处的文件名，但不能只靠它。
   - 只有所有人都打得开的地址（公开网页、仓库里的文件、Board 上的卡片）可以只给链接。
3. **有图必须随卡上传**：读需求时先列出里面引用的所有截图、图片和文件（日志、设计稿等），按它们说的是哪件事归到对应的卡片：建这张卡时用 `--image <图片>` / `--file <文件>`（可以写多次）一起上传，附件按顺序接在描述后面，界面上直接显示。
   - 每张图都要有归属，不漏、不乱挂；一张图说的是几张卡的事，就挂到每一张。
   - 不要建完卡再用 `board attach` 补一条只有图片的评论。
4. 建卡前先 `board labels` 看项目里有哪些标签。新建时用 `--label <标签>`（可以写多次）带上合适的：不新建标签，「仅人可打」的不带，没有合适的就不带。标签用来让定时领取的会话接着做相近的卡、决定由哪个 agent 做，建卡时就带上。
5. 目标取决于句子：说「待办」时每张卡一次 `board new "<标题>" --body-file <描述文件> [--image <图片>]… [--file <文件>]… [--label <标签>]…`（描述里写背景、范围，以及 `- [ ] 验收标准`；多行描述写进文件再传，见 work.md「会话开始」第 5 步），按先后顺序新建，卡片进入首个可领取状态；说「未整理」时同样的命令加 `--inbox`，卡片进入「未整理」最下面。只 `board new`，不修改已有的卡片（不 edit、move、label 已有的卡片）。
6. 最后汇报新建的卡片（ID、标题、标签和带上的附件）。

## 拆解未整理里的需求

适用于：`拆解 X项目之中的Y白板中的#Z需求`（卡片详情对「未整理」里的条目复制出的句子，或 board host 派来的拆解）。#Z 是「未整理」里人记下的一条原始需求，拆出的卡回到「未整理」、挂在它下面，人看过后再整理进工作流。

1. `board show Z --json` 读这一条：标题、描述、动态（人的补充、之前拆过的说明）、附件（`board files Z` 下载到本地看）；`split_into` 不为空时这条已经拆过，只补上次没拆到的部分。不要 claim：它在「未整理」里，领不了。
2. 按「卡片颗粒度」拆，描述按「拆解和新建」第 2 步写成自包含的（把原需求里和这张卡相关的原文写进去），带上合适的标签（第 4 步）。
3. 每张卡 `board new "<标题>" --inbox --from Z --body-file <描述文件> [--image <图片>]… [--file <文件>]… [--label <标签>]…`：卡片进「未整理」最下面，记下拆自 #Z。原需求里的图片、文件按「拆解和新建」第 3 步挂到对应的卡（先 `board files Z` 下载）。
4. 最后在 #Z 上评论拆成了哪几张，一行一张：`#a 标题`、`#b 标题`…；信息不够、拆不了时，评论写明缺什么，不建卡。
5. 不改、不移动 #Z（不 edit、move、label）：拆完的原条目留不留由人决定。

## 整理未整理的条目

卡片在「未整理」时，它还只是个想法。把它改写成可执行的卡片：

```sh
board edit <ID> --title "<一句话说清要做什么>" --body-file <描述文件>   # 背景、范围，以及 - [ ] 验收标准
board comment <ID> "<整理说明；信息不够时列出需要人确认的问题>"
```

描述同样要自包含（见「拆解和新建」第 2 步）。条目引用了还没传到 Board 上的图片、文件时：先 `board attach <ID> <图片>… --comment-file <整理说明文件> --json` 上传（整理说明就写在这条评论里，代替上面的 `board comment`），再按返回的 `attachments[]`（`url`、`image`）在 `board edit` 的描述里写上引用：图片 `![<文件名>](<url>)`，在描述里直接显示；其他文件 `[<文件名>](<url>)`。

不要移动它：放不放进工作流由人决定。
